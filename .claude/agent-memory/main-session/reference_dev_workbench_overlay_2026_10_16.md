The existing telemetry DLL D3D9 seam patches `Direct3DCreate9` via an import-checked IAT slot and follows COM `CreateDevice`, `Reset`, and `TestCooperativeLevel`. The bootstrap globally refuses all hooks when the supported SGW.exe code/slot fingerprint mismatches. Windows SDK `d3d9.h` assigns `IDirect3DDevice9::EndScene` slot 42, `Clear` 43, `GetViewport` 48 and `CreateStateBlock` 59; `IDirect3DStateBlock9::Apply` is slot 5. DW-16 adds a lab-bridge-only EndScene patch after bridge startup, then coarse atomic status rendering with `Clear`, `D3DSBT_ALL` restoration, loss/reset/recursion/fault gates, and a three-Clear bound. DW-16 did not run live rendering for visual/driver proof. See `docs/architecture/client-telemetry.md` and `docs/analysis/dev-workbench/worknotes/DW-16.md`.
Review fix: boot retains the actual fingerprint report for the later overlay install gate; the supported executable, Create9 detour hit, and active bridge are all required. An auxiliary device with a foreign vtable does not displace the accepted device or count as a failed patch. The live vtable swap is serialized and uses atomic compare/exchange, preserving the original callback when an intervening writer wins. Host tests cover concurrent same-vtable installs and repeated foreign probes. Render failures publish atomic reason bits and totals to one lab-only non-render worker; no EndScene JSON allocation.
Handoff repair: a successful auxiliary EndScene is not enough to displace a healthy owner, since two devices may present every frame. The selected owner stays until explicit loss or three successful foreign EndScenes without a successful selected-device EndScene. Both frame entry and transfer claim the same atomic guard, preserving an active frame's fault attribution. Fake lifecycle tests cover alternating presenters, absent-owner transfer, explicit loss and a barrier interleaving. Native visual proof remains pending.
