# Game Update review

The shell's `game_update_command` is separate from launcher self-update. Native
check context binds installed owner, current signed release and operation
revision. Only native verified catalog bytes enter the retained offer; the
renderer supplies no file path or manifest. Reopen discards the transient review.
Concurrent checks and intervening operations invalidate stale results.

Settings mounts native-held offer review and confirmed Apply. The shell retains
preparation through commit; observer loss does not replay a download. Native host
fixtures cover duplicate admission, cancellation, recovery and cleanup. Mounted
Effect UAT uses real signed archive download, replacement, lost-reply inspection
and reopened cleanup evidence. These fixtures do not prove actual game Update,
Windows shell behavior or release readiness.
See [owner/current release evidence](../../../docs/analysis/playtests/2026-10-03-macos-wine/worknotes/owner-current-release.md).

Native UAT also found rebuilt ad-hoc bundles can require fresh Documents-folder
permission. Confirm TCC logs before treating an open-file wait as corrupt saved
state. Stop automatic Play polling after a failed read; require explicit recheck.
See the campaign's native-window UAT evidence for this development-build limit.
