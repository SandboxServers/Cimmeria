# tools/ — Development Tools

Editor applications, reverse-engineering utilities, and the scripts that build, test and document the repo.

**Before you write a script, parser, decoder, extractor or CLI, look for one here first.** The [catalog](#tools-catalog) below lists every script under `tools/` and every crate binary, grouped by task; [`crates/README.md`](../crates/README.md) describes the library crates they are built on. Extend the tool that already does most of the job rather than adding a sibling. A new tool needs a one-line summary (a module docstring, a leading comment, `.SYNOPSIS`, or `//!` for a Rust binary) so the catalog picks it up. To preview its row, `git add` it and run `python tools/docs-gen/regen.py --skip-crate-graph`, but don't commit the regenerated block: the regen workflow on `main` does that after the merge.

Launcher release identity policy lives in `launcher-release/release_identity.py`,
called by `stamp.sh` and the rolling-feed check in `publish.sh` (D-LX15).
Run `python tools/launcher-release/test_release_identity.py` for the local
policy regressions. The existing `test-release-scripts.sh` harness performs
an actual stubbed `stamp.sh` dry run on Linux CI without keys or publication.

Launcher workflow/build policy regressions live in
`launcher-release/test_workflow_policy.py` (requires PyYAML 6.0.3).
They protect native validation coverage, main-only cache writes, PR cancellation,
`release-tools` profile use and the uncached signing boundary. Run
`python tools/launcher-release/test_workflow_policy.py`; the
[pre-PR checks](../docs/agents/pre-pr-checks.md#desktop-launcher-ci-policy-checks)
and [release contract](../crates/launcher/desktop/docs/release.md#build-time-and-signing-isolation)
explain the policy. These tests do not sign or publish a production release.

CI scheduling and cache policy live in the [runner reference](ci-runners/README.md)
and [pre-PR checks](../docs/agents/pre-pr-checks.md). Workflow policy guards run with
`python -m unittest discover -s tools/ci-runners -p "test_*.py"` (PyYAML 6.0.3).
The full/code-conditioned `contracts` job runs them alongside build-lane, docs-gen
and token-profile suites, independently of Rust compilation; gate and nightly
reporting retain their results. Container dependency reuse is documented in
[docker/README.md](../docker/README.md); baseline timings and unproved cases are in
the [CI iteration design](../docs/analysis/ci-iteration-speed.md).

Adds the i686 target, generates `CIMMERIA_LAB_MCP_TOKEN` and `CIMMERIA_TELEMETRY_HMAC_SECRET` when unset or short and sets `CIMMERIA_LAB_MCP_BIND`/`_URL` (127.0.0.1:8451) as user variables, writes `lab-account.json` when absent, checks the client's `LoginInternal.lua` for the `Local` row (adds it, with a backup, only with `--patch-login-internal`), then prints what is left. | `lab/instances.ps1` | Writes the account files for the extra lab instances (`init`) and reports each instance's account, profile seed and client (`status`). See [Parallel clients](../docs/guides/live-research-lab.md#parallel-clients-up-to-five). |
| `lab/labd-headers.ps1` | The `headersHelper` of the daemon's `.mcp.json` entry: prints the bearer header from the user environment, so the token never lands in `.mcp.json`. |

## Lint & Check Scripts

Load-bearing scripts run as part of the pre-PR checklist (see [`docs/agents/pre-pr-checks.md`](../docs/agents/pre-pr-checks.md)). Each ships in both a POSIX (`.sh`) and PowerShell (`.ps1`) flavor:

| Script | Purpose |
|---|---|
| `lint-md.sh` / `lint-md.ps1` | Markdown lint via `markdownlint-cli2` (warn-only; `--fix` auto-fixes) |
| `check-figure-sources.sh` / `check-figure-sources.ps1` | Verify each figure source DSL has a re-rendered SVG (blocking in CI) |
| `lint-figure-style.sh` / `lint-figure-style.ps1` | Figure style + format lint — Mermaid init directives, theme backdrops, caption numbering (blocking in CI) |
| `test-live-db.sh` / `test-live-db.ps1` | The live-DB test tier: runs the lib tests of every crate in its list in one `--profile=ci-live-db` nextest invocation (blocking in CI; `--llvm-cov` for the coverage job). Needs `DATABASE_URL`. |
| `main-red/main-red.sh` | `main-red.sh fail\|pass <check> <run-url>`: opens, comments on or closes the `main-red` issue ("main is red: `<check>`") for a check that runs on `main` after the merge queue. Called by the `report` job of `pr-container.yml` and the `nightly-report` job of `test.yml` (bash only; needs `GH_TOKEN` with `issues: write`). `ship.py merge` refuses code PRs while one is open. See [pre-pr-checks.md § Main is red](../docs/agents/pre-pr-checks.md#main-is-red). |
| `container-smoke.sh` | The container login smoke shared by `pr-container.yml` and `release-container.yml` (bash only; CI runs it on Linux). Starts the server image, waits for Postgres, the login port and the BaseApp socket, then runs the `login-probe` binary from `cimmeria-wireclient` as a client: wrong password rejected, seeded account accepted, advertised BaseApp endpoint checked, Mercury handshake. Prints and keeps the container and server logs. See [container distribution § CI login smoke](../docs/operations/container.md#ci-login-smoke). |

`docs-gen/regen.py` (Python 3.11+) owns every generated number and block in the Markdown: test counts, the RE findings count, the gap-analysis totals, and the crate graph. The `regen-docs` workflow runs it on `main` every six hours and commits what changed; PRs don't. See [docs-gen/README.md](docs-gen/README.md). `crate-graph/crate_graph.py` renders the crate dependency graph in `README.md` and `crates/README.md` from `cargo metadata` and still runs on its own; see [crate-graph/README.md](crate-graph/README.md).

`spec-lint/` is a small Rust crate (`cargo run -p cimmeria-spec-lint`) used for spec-document linting; see [spec-lint/README.md](spec-lint/README.md).
