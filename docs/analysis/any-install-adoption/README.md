# Any-Install Adoption

> Type: how-to. Audience: the Claude Code coordinator, packet workers and maintainers.
> Updated: 2026-10-11. Companions: [work packets](work-packets.md), [launcher consolidation ledger](../launcher-consolidation/README.md) (D-LX12, LX-10, LX-26), [desktop migration contract](../../../crates/launcher/desktop/docs/migration.md), [desktop launcher README](../../../crates/launcher/desktop/README.md), [player launcher guide](../../client/launcher-guide.md), [documentation index](../../readme.md).

## Purpose

Let a player adopt **any** existing Stargate Worlds client folder into the desktop launcher, whether or not the retired egui launcher ever touched it: a stock 2009 install, a hand-extracted client RAR, a folder with a modified `SGW.exe`, or an egui-managed folder. And let a player who already has the client archive on disk use it instead of downloading it again.

Today desktop adoption (`crates/launcher/desktop/engine/src/storage/adoption/`) only accepts a folder that the egui launcher installed, fully patched and byte-identical to the signed release, and it downloads the 4.1 GB seed to check that. With the egui launcher retired (LX-18, [#1641](https://github.com/SandboxServers/Cimmeria/pull/1641)), most new players arrive with a folder from somewhere else, and every one of those folders is refused.

The campaign ends with:

- one Settings entry, **Use an existing game folder…**, one folder picker, and a choice of adopting in place or making a verified copy;
- files that only lack the current patches are patched; modified or missing release files are replaced from the signed release after an explicit consent box, with the originals kept in a backup folder;
- when the content release publishes a signed file index, a complete folder verifies without downloading the seed;
- **Use a downloaded game archive…**: a player's own copy of the seed RAR replaces the download for Install, Repair, Update and adoption, after its SHA-256 matches the signed release.

All paths below are relative to the repository root. `engine/`, `shell/` and `frontend/` mean `crates/launcher/desktop/engine/src/`, `crates/launcher/desktop/shell/src/` and `crates/launcher/desktop/frontend/`.

## Facts that bend the user decisions

- **D-AI2, "only patches are fetched", has one more exception than the seed.** A modified or missing file whose last layer is a delta patch needs that patch's source bytes at their pre-patch state (F-12). The replay takes them from the player's own folder when they match; when they don't, it needs the seed. The review shows the download (seed or not, which patches, bytes) before consent, so the player sees the 4.1 GB cost before agreeing, and can point at their own archive (D-AI4) instead.
- **"Fetch the seed" always means the whole archive** (D-AI5). Individual seed files are extracted from the archive.org RAR or the player's archive, inside the operation's private folders; no per-file seed content is published anywhere, and nothing in this campaign caches seed bytes outside the player's machine.
- **The no-download path needs the index published** (AI-14, D-AI8). Until then the launcher builds the same index locally from the seed and patches, so everything else works, with the seed download it has today (or the player's archive).
- **Windows in-place adoption is broken today against the production seed** (F-7). AI-03 fixes it on its own, so LX-26's adoption rows can pass before this campaign lands.
- **A local archive is copied, not read in place** (F-21, D-AI15). The user asked which; reading in place cannot be made safe with the current extractor, and the pipeline deletes its input.
- **A stock 2009 install may not equal the seed's extraction.** The seed is the installer's own CAB set; what the installer writes beside it (uninstaller, redistributables, a different layout) has never been compared. Such files show as "not part of the release" and stay untouched; if the installer writes release files differently they show as modified and need consent. AI-17 measures it on a real stock install.
- **An adopted folder's first game Update still needs the full seed** (F-15, D-AI14), now from the download or the player's archive.

## Out of scope

- Incremental Update and Repair from the index (D-AI14).
- Hosting, mirroring or caching seed bytes for anyone (D-AI5).
- Elevation to adopt a protected folder in place (D-AI10). The copy covers it.
- Merging user files (hand-placed PAKs, configs) into `game`. They stay where they are, as today.
- Signing the index separately from the manifest. The manifest's hash reference is the signature (D-AI8).
