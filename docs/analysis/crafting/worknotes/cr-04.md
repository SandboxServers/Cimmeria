## Design decisions

- **One transaction.** `spend_in_db` begins, reads with `load_crafting_state_locked` (`FOR UPDATE` on the `sgw_player` row), runs the pure `check_spend`, then `UPDATE sgw_player SET discipline_ids = array_append(…), applied_science_points = applied_science_points - 1 … RETURNING applied_science_points` and upserts the expertise row at 1 (`ON CONFLICT … DO UPDATE`, which resets a stray row, audit C-02). A refusal returns before any write and the transaction rolls back on drop. The targeted writes run under the lock taken by the read, so they cannot race a GM grant (which CR-03 made lock too).
- **Check order.** Unknown discipline → already known → no ASP → paradigm level → prerequisites (first failing one, in `required_discipline_ids` order). Already-known comes before ASP so a replay after the last point was spent still says "You already know …". A missing paradigm level reads as 0.
- **Replay.** A duplicate request finds the discipline known, sends the "already known" line and writes nothing (CAT-F F-02).
- **Feedback.** New `CraftReject` variants, each with a `reason` for the `crafting` `rejected` log: `unknown_discipline`, `already_known`, `not_enough_asp` (the only one with a code: `onErrorCode(0, 0, 214)` after the text), `paradigm_too_low`, `prerequisite_missing`, and `unavailable` (no pool, catalog load failure, transaction error; "Learning disciplines is unavailable right now. Nothing was changed."). Texts: "There is no discipline N.", "You already know <name>.", "You have no applied science points.", "<name> requires <paradigm> paradigm level N; yours is M.", "<name> requires <prerequisite> at expertise 50."
- **No correction push after a refusal.** The client changes nothing on a click (cr-03 evidence), so D-CR14's "discipline and ASP state after a spend rejection" needs no packet here.
- **Success.** `completed` (`verb = "spend"`) at INFO, then `push_discipline(id, 1)` and `push_asp(total)` through `sync`. No blueprints (D-CR04).
- **Paradigm names.** The catalog carries no paradigm names, so `cell-catalog` gains `RACIAL_PARADIGM_NAMES` / `racial_paradigm_name`, pinned against `resources.racial_paradigm` by a live-DB test. CR-15's guide texts can use it.
