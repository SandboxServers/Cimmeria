## Changes from the plan

1. **#534 folded in.** The client sends the weapon's instance id (`InvItem.id`, `sgw_inventory.item_id`), not its design id: `FUN_00e1ee10` sends `item+0x0C`, which the item constructor fills from `id` (issue #534's decompile, and `inventory-wire-formats.md` § requestAmmoChange, "Weapon instance ID"). The handler matched the design id, so a real client's swap most likely never found its slot and the validation this packet adds would not have run in game. It is the same handler, and it is the precondition for "an allowed type is accepted". The whitelist is now read by the matched slot's design id, never by the wire value.
2. **`ambiguous_slot` is now a corrupt-state guard.** Two slots can hold the same design, but not the same instance id, since it is the table's primary key. The reason stays in the catalog and the refusal stays in the code, but it only fires on a duplicated instance id. The plan's guard ("a same-item duplicate-slot request is still rejected") became two tests: two instances of one design swap independently, and a duplicated instance id is refused.
3. **Feedback is a chat line, not `onErrorCode`.** No client Lua consumes `onErrorCode` (AT-E1), and the plan's "nothing was sent" wire test forbids an `onEntityProperty` resync. A refusal sends exactly one `onPlayerCommunication("SYSTEM", 0, CHAN_FEEDBACK, text)`.
4. **Audit A-09 holds; no new logic.** `load_item_defs` builds `allowed_ammo_types` straight from `resources.items.ammo_types` in SQL. AM-F's `standard_pistol_and_smg_accept_every_bullet_special` pins the cache against the column, so this packet's live-DB tests drive the handler with the loader's real cache instead of re-checking the conversion.
5. **Docs left for AM-12.** The file-ownership matrix gives `docs/gameplay/weapon-ammo-reload.md` to AM-12. The deltas it needs are listed below. #534 also asks for a citation in `inventory-wire-formats.md`.
6. **Tests moved.** The dispatcher tests lived in `crates/cell-methods/.../inventory/tests/ammo_change.rs` and relied on the fall-open and the design-id key, so they had to change. The file became the directory `tests/ammo_change/` (`mod.rs`, `live_db.rs`), which needs no edit to the parent `mod.rs`.

## The AM-02 hook

```rust
if super::switch_return::begin_switch_return(entity_id, slot, ammo_type, tx, space_mgr).await
    == super::switch_return::SwitchReturn::Deferred
{
    return;
}
```

It runs after every refusal check, so a refused type never returns rounds, and before `cur_ammo_type` is written. `switch_return.rs` holds a stub with the agreed signature that always returns `Proceed`. AM-02 replaces the file whole; the rebase should conflict only there.
