## Changes from the plan

1. **The seam is the pipeline, not an effect script.** `RangedPhysicalDamage` and its siblings run only for effects with a `script_name` (8 seeded effects use `RangedPhysicalDamage`), so wrapping them would modify a handful of abilities, not "any shot". Every ability hit goes through `damage_apply::apply_damage_to_target` → `calculate_damage_scaled`, so the modifier is applied there. This puts AM-04 in three files the ownership matrix did not list: `damage_apply/mod.rs` (about 45 added lines), `combat/damage/pipeline.rs` (a new function plus the armour line) and two one-line re-exports. No Wave-1 packet owns any of them. `scripts.rs` and `registry.rs` are untouched.
2. **`resolve.rs` needed no change.** Audit A-10's `default_ammo_type: 0, cur_ammo_type: 0` placeholders are in `resolve.rs`'s test fixture, not in production code. The damage path reads the real value with `CellEntity::active_ammo_type()`.
3. **The modifier is gated on `ammo.finite_special`.** While the flag is off, special reloads are free and AM-F's widening already offers Hollow Point on every Standard Pistol and SMG, so an ungated modifier would be free extra damage the day this merges. Gated, AM-04 ships dark and AM-12 turns both halves on together. The flag's own doc says it gates only the reserve draw; AM-12 should widen that sentence when it flips the flag.
4. **`penetration_mult` divides the armour term,** not the attacker's `PENETRATION` stat, which is 0 on every player (a multiple of 0 would leave the column dead).
5. **One new telemetry event:** `ammo_on_hit_effect_missing` (WARN) when a row names an effect that is not in `effect_defs`. It needs a catalog row in work-packets.md and a constant in `ammo_telemetry.rs` through the coordinator. Its `LogCapture` guard is `on_hit_effect_resolves_only_when_the_effect_exists`.

## Known limits

- `MITIGATION` is capped at 0 in `StatList::new`, so the armour term is 0 in live play and `penetration_mult` does nothing until mitigation is populated. Until then Armor Piercing is a plain 10% damage cut. This is the "MITIGATION 0/0" blocker already tracked for enemy combat, not new here.
- The Focus-pierce bleed that `RangedPhysicalDamage` adds on top of the pipeline damage (effect 641, Pistol Auto Attack) is not scaled. Scaling it needs an `EffectContext` field or a `scripts.rs` edit, both outside this packet.
- Penetration does not reduce cover. Cover has its own penetration term (`coverAccuracy`); tying ammo to it is a possible follow-up.
- The on-hit effect fires on any non-miss result, including the hit that kills the target, like the ability's own scripts.

## Extension point for Wave 2

Each family packet (AM-08 Incendiary, AM-09 EMP, AM-10 Explosive, AM-11a/b/c darts) touches only:

1. `db/resources/Abilities/Seed/ammo_modifiers_<family>.sql` with its `ammo_modifiers` rows, and one `\ir` line in `db/database.sql` directly after `Effects/Seed/effects.sql`. The same file may seed the family's on-hit `resources.effects` and `effect_nvps` rows from its reserved id block (effect and nvp ids both): 9110-9119 Incendiary, 9120-9129 EMP, 9130-9139 Explosive, 9140-9149 dart crowd-control, 9150-9159 dart tech, 9160-9169 dart support.
2. The row's `on_hit_effect_id` names that effect. Its `script_name` picks the behaviour: an existing script (`StatBuff`, `Stun`, `Suppression`, `MeleeDamage`, `RangedEnergyDamage`, ...) needs no code at all.
3. Only when no script fits: one zero-sized `impl EffectScript` in the family's `crates/cell-world/src/cell/effects/ammo_<family>.rs` and one `match` arm in `registry.rs`. `EffectContext.source_id` is the shooter and `target_id` the target. A pulsing effect (`pulse_count > 1`, `pulse_duration > 0`) registers and re-fires through the pulse tick with no extra wiring.
4. A test in the family's file (the script) and a live-DB seed guard modelled on `live_db_hp_ap_seed_rows`. The pipeline tests in `damage_apply::ammo_tests` already prove the on-hit dispatch.
