## Design

- **No native path.** `SGWGmPlayer.def` has no ammo method, and AM-01 found no receiver for `Event_NetOut_GiveAmmo`. Typing `/gmgiveammo` or `/gmsetinfiniteammo` reaches nothing on the server. The `gm*` names are registered as `.`-console aliases, so a tester who types the native name with a dot still gets the command.
- **Ammo type argument.** Any of these works: an `EAmmoType` ordinal, the label in any case (with or without `_`), the label without its family when that is unique (`hollowpoint`), `hp`/`ap`, or the reserve item id from `SpaceManager::ammo_catalog`. `emp` is refused as ambiguous. Default ammo is refused (`not_special_ammo`), and so is a special type with no `ammo_item_types` row (`no_reserve_item`: the daggers).
- **Grant.** The recipient is the selected player, else the caller. Counts above 5000 are clamped, and the GM is told. The cell forwards `GmGiveAmmo`. The base checks that the recipient's session still plays the character, then runs `return_rounds` in one transaction, resyncs the inventory and answers the GM. Leftover rounds are reported as "N did not fit: bags full". A grant where nothing fits is a refusal (`bags_full`).
- **Why not `GrantItem`.** It writes its whole count into one row when the count does not merge, so a 1000-round grant would be one 1000-stack over the 500 cap. That is filed as [#1045](https://github.com/SandboxServers/Cimmeria/issues/1045) and not fixed here.
- **Infinite ammo (D-AM09).** A process-wide set keyed by `player_id`. It survives zones and relogs until a restart, like `SpaceManager::gm_aggro_off`. It lives in `cimmeria-entity`, not `SpaceManager` (which is off-limits to Wave 1), so AM-02's reload path in `cimmeria-cell-combat` can read it. With `ammo.finite_special` off, the feedback says every reload is free anyway.

## Reader contract for AM-02

At the reload entrypoint, when the loaded type is special and `finite_special()` is on, check `cimmeria_entity::ammo_infinite::is_on(player_id)` first. `true` means skip the `draw` and refill as if the full request had been drawn. The clip still empties normally.

## Telemetry

Target `ammo`, span `ammo.gm_give` on both halves.

| Event | Where | Level | Fields |
|---|---|---|---|
| `gm_give_ammo` refused | cell | WARN | `reason` (`bad_args`, `unknown_ammo_type`, `not_special_ammo`, `no_reserve_item`, `bad_quantity`, `not_a_player`), `account_id`, `player_id`, `entity_id`, `ammo_type` |
| `gm_give_ammo` forwarded | cell | DEBUG | plus `subject_player_id`, `item_id`, `quantity`, `requested` |
| `gm_give_ammo` granted | base | INFO | plus `returned`, `remainder`, `stack_before`, `stack_after`, `stacks_touched` |

| `gm_infinite_ammo_toggled` | cell | INFO (WARN on a bad argument) | `on`, `changed`, `subject_player_id` |
