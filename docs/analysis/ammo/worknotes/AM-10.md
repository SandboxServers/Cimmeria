## Changes from the plan

1. **The splash is a pipeline step, not an effect script.** The extension point runs an on-hit effect as an `EffectScript` with a synchronous `EffectContext`. A script can write another entity's HEALTH, but it cannot send that entity's `onEffectResults` or `onStatUpdate`, run `resolve_death` or give threat (ADR decision 19 has the same reason for the death sweep). A splash written as a script would leave every secondary's health bar stale and every splash kill a zero-HP NPC with no corpse. So the effect is data only, and the combat pipeline fans it out, the same way cone secondaries are applied.
2. **This touches three `cimmeria-cell-combat` files outside the ownership matrix:** `damage_apply/mod.rs` (AM-04's file), `dispatch/mod.rs` (one visibility word) and `use_ability/kill_credit.rs`. No other Wave-2 packet edits them beyond AM-08's one `mod` line, which rebased cleanly.
3. **The splash is recognised by data, not by family.** Any on-hit effect with `TCM_AERadius` and a `SplashDamageFraction` in `(0, 1]` splashes. Only 9130 is one today.
4. **Kill credit fixed in the same pass.** `credit_single_target` drained the `last_aoe_deaths` scratchpad only when the primary target died and was tagged. A cone or splash kill whose primary survived was never credited on its own cast, and it stayed on the scratchpad until some later kill drained it and credited it to the wrong cast. The wrapper now drains the scratchpad on every cast, and `credit_ground_deaths` drains it too, so a splash kill from a ground cast is credited as well. Pre-existing for cones; splash made it common.

## The row and the splash (RECONSTRUCTION)

1446's cooked text: "Buff: / Toggle / Damage Type: Physical / Penetration: Decreased / Damage: Increased", `effect_ids` empty. Those are Hollow Point's directions exactly, and nothing in the cooked text or the handoff pack (§ 07, § 08) mentions a splash. The splash is this packet's design.

| Column / field | Value | Why |
|---|---|---|
| `damage_type` | `DT_Physical` | cooked text |
| `damage_mult` | 1.1 | "Damage: Increased", below Hollow Point's 1.25 because the round also splashes |
| `penetration_mult` | 0.5 | "Penetration: Decreased", as Hollow Point |
| `on_hit_effect_id` | 9130 | from AM-10's reserved block |
| effect 9130 `target_collection_method` | `TCM_AERadius` | the method every seeded blast effect uses |
| effect 9130 `tcm_param1` | `Short` (5 m, `EffectDef::tcm_range_meters`) | the tier the seeded grenade "Ground Blast Damage" secondary effects use |
| NVP `SplashDamageFraction` | 0.5 | each splash target takes half the shot |
| effect 9130 `script_name`, `pulse_count` | NULL, 1 | no script; one burst |

**Splash damage** is the shot's base damage × each secondary's own cover scale × `damage_mult` × 0.5, rolled separately per secondary (its own QR result and a fresh `effect_seq`), then the secondary's armour at the round's penetration. So a splash target can be missed or crit on its own roll.

## Who is splashed

- **Candidates:** the ground-AoE collector, `dispatch::collect_ground_targets`, anchored at the primary target: the attacker's space, alive, within 5 m (3D), and `combat::may_hit_in_area`, which for a player shooter is `player_may_attack` (hostile-faction NPCs that are not pets, plus an engaged duel partner). The primary and the shooter are removed.
- **Line of sight:** area abilities do not check it (ADR decision 20). The splash does: a candidate the space's collision occluder says is behind a wall from the target is dropped. It follows the fire-time policy: no occluder, or an off-grid (`Unknown`) ray, never drops a candidate, because the navmesh ray reads furniture as walls.
- **No chaining:** each secondary is applied as `HitKind::Splash`, which runs no on-hit effect (so no splash of its own), none of the shot's effect scripts and no pulsing effects.
- **Only a player's weapon shot splashes,** like every ammo modifier: NPCs fire unmodified.

## Known limits

- **Mitigation is 0 in the default stats,** so `penetration_mult` 0.5 does nothing in live play today. Explosive is a plain 10% direct-damage bonus plus the splash until mitigation is populated. When it is, the splash meets the secondaries' armour at the same reduced penetration.
- **Explosive is not client-visible as a splash.** Each secondary gets an ordinary `onEffectResults` from the shooter (the shot's `ability_id`, a fresh `effect_seq`), so the client shows a damage number on each splashed NPC. There is no explosion VFX; a splash effect sequence is a client-content question.
- **The shooter's own explosion is harmless.** Standing next to the target never hurts the shooter, by the brief.
- **Cone secondaries splash too.** A cone weapon shot runs the on-hit effect on every cone target it hits, so each can splash its neighbours. A splash target still never splashes.
- **Ships dark** behind `ammo.finite_special`, like every row.

## Client risk (for AM-12's UAT)

Effect 9130 is not in the client's cooked data, but **no message carries its id to the client.** The splash sends only `onEffectResults` (keyed by the shot's ability id and a per-target `effect_seq`) and `onStatUpdate`, the same messages as a cone secondary. 9130 has no script and does not pulse, so it registers no active effect and sends no `onTimerUpdate` or buff icon. The #938-class risk (a client choking on an unknown cooked id) does not apply as far as the server side can tell. UAT should still watch the first Explosive hit on a pack of NPCs: damage numbers on the neighbours, no error in the client log.

**Revert proof.** Each mutation failed its guards; restored, all pass:

- splash call disabled: five of the six pipeline and smoke tests failed (not `only_a_radius_on_hit_effect_splashes`, which asserts no splash);
- `kind.is_direct()` dropped from the on-hit filter (splash targets run the on-hit effect): `splash_does_not_chain` overflowed its stack, which is the unbounded chain;
- radius multiplied by 10: the radius test and the chain test failed;
- the occluder check disabled: the wall test failed;
- `may_hit_in_area` disabled in `collect_ground_targets`: the friendly test failed;
- the `TCM_AERadius` check in `splash_of` disabled: `only_a_radius_on_hit_effect_splashes` failed;
- the `ammo_splash_bad_fraction` event renamed: `a_bad_fraction_does_not_splash` failed;
- `kill_credit.rs` restored to its previous version: the primary-survives credit test failed; the ground drain disabled: the ground credit test failed;
- the `\ir` line removed and the database reloaded: `live_db_explosive_seed_rows` failed.

The shooter exclusion in `splash_targets` has no failing guard of its own: `area_candidates` never includes the shooter, so removing the exclusion changes nothing today. The test still asserts the shooter is untouched.
