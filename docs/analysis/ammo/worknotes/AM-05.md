## What shipped

All rows are in `db/resources/Loot/Seed/ammo_loot.sql`, loaded by one new `\ir` line after `loot_tables.sql`. Every ammo item is named through `resources.ammo_item_types`, never by id. `loot_id` comes from `loot_loot_id_seq`, which `loot.sql` leaves at its last id, so a later `loot.sql` row that bumps the `setval` never collides with these rows.

| Table | What | Chance | Quantity |
|---|---|---|---|
| 3, debug hub crate | Hollow Point, Armor Piercing, Incendiary, EMP, Explosive | 100 % each | a full stack: the item's `max_stack_size` (500) |
| 3 | 3235 SI 3 9mm Pistol (Standard Pistol) | 100 % | 1 |
| 3 | 3147 MPX 77 SMG (Standard SMG) | 100 % | 1 |
| 8, 9, Castle pre-Romney chest | Hollow Point | 100 % | 50-75 |
| 4, Castle NID guard | Hollow Point | 5 % | 10-25 |
| 5, Castle NID veteran | Hollow Point | 6 % | 15-30 |
| 5 | Armor Piercing | 3 % | 10-20 |
| 7, Castle hall NID guard | Hollow Point | 10 % | 10-25 |

Why these NPC tables: the Castle NID are the gun-carrying humans a level 3-4 player meets while holding Standard Pistols and SMGs. Only Hollow Point and Armor Piercing drop from NPCs (D-AM04's first pair). Incendiary, EMP and Explosive come only from the debug crate and `.gmgiveammo` until their Wave-2 damage packets ship. Table 2 (the Cellblock tutorial guard) and table 6 (the PRU drones, salvage only) drop no ammo.

The chance that a corpse drops nothing stays inside the bands `live_db_castle_loot` checks: table 4 goes from 30.5 % to 29.0 %, table 5 from 17.5 % to 16.0 %, and table 7 from 35 % to 31.5 %.

## Deviations and shared-file touches

1. **Files outside the ownership matrix, all in tests.** Existing guards pinned tables 7, 8 and 9 exactly, and one also rejected any Castle drop that is neither a working consumable nor a crafting component. Adding the ammo rows would have failed all three.
   - `crates/cell-catalog/src/cell/spawner/tests/live_db_castle_loot.rs`: ammo items count as an allowed Castle drop (but never on the PRU drones), and the table 7 pin skips ammo rows with a `NOT EXISTS` on `ammo_item_types`.
   - `crates/cell-content/src/cell/content/chain_replay_tests/castle_loot_containers.rs`: the same filter on the chest pin.
   - `crates/cell-catalog/src/cell/spawner/tests/mod.rs`: one `mod` line and one doc bullet.
   - The new test file is `crates/cell-catalog/src/cell/spawner/tests/live_db_ammo_loot.rs`.

   No runtime Rust changed.
2. **`ammo_loot_dropped` is not emitted.** The ownership matrix keeps AM-05 out of every Rust file. The event's correlators (`account_id`, `player_id`) exist only at grant time, not in `roll_loot_entries`. Today the roll logs `Loot generated` (`design_id`, `quantity`, `loot_table_id`) and the container logs `loot.container_*`. **Follow-up for the coordinator:** emit `ammo_loot_dropped` where `lootItem` sends `GrantItem` for an item that `ammo_catalog.ammo_type_for_item` knows. That is `crates/cell-interactions` `handle_loot_item`, which is not owned by any Wave-1 packet.
3. **Stale comments in `loot.sql`, which this packet must not touch.** The `TODO(#1026)` above tables 8 and 9 is now done, and the empty-corpse figures for tables 4, 5 and 7 are the pre-AM-05 ones (`ammo_loot.sql` carries the new ones). AM-12 should clean both up.

## Notes

- **The chest's Hollow Point does not fit either chest weapon.** Neither the 3127 High Capacity SMG nor the 3472 Serpent Staff is a widened family. The rounds are for a Standard Pistol or SMG the player already carries or finds. This is D-AM03 as decided. Flag it at UAT (step 8) in case the owner wants a widened weapon in the chest instead.
- **The AM-06 finding.** `GrantItem` inserts the looted count as one stack, uncapped, so every ammo row stays at or below `max_stack_size`, and the NPC guard checks this on every table. A "full stack" in the debug crate is exactly 500.
- **Crate size.** One open of table 3 now yields 11 certain entries, plus up to 6 chance ones. The five stacks take 5 bag slots, and the two weapons take 2. A tester with full bags gets the existing "left in the container" refusal, and the entries stay pending.
- **Darts.** AM-11a/b/c add their own rows to table 3 once a dart weapon accepts them. The stray-table guard does not need to change for that, but the debug-crate guard's `BULLET_SPECIALS` list covers bullets only.
