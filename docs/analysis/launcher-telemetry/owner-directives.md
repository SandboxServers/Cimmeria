# Owner directives: launcher-telemetry

Source: user, 2026-10-21 (these override any open question in the work packets).

1. **Default upload URL.** The launcher ships telemetry to the default Cimmeria URL out of the box. The colo already accepts it there. Remove the `http://localhost:8443/api/telemetry` fallback (`handlers.rs:512-521`) so a launcher on another machine no longer uploads to itself. No env var should be needed for a normal install. An override may stay, but only as an explicit override.
3. **Adopt rejections must say why.** (2026-10-21) The user has a working install on another laptop that will not adopt: the launcher goes from "validating" straight to downloading the whole game again, with no reason shown. Every adopt rejection needs a specific, user-visible reason (which check failed, which file or manifest entry, expected vs found), and the same reason must be logged and shipped as telemetry. See also docs/analysis/launcher-adopt-ux/.
4. **Publish the adoption file index as a packet.** (2026-10-21) Today the manifest has no `file_index`, so adopt falls back to downloading the 4.1 GB seed to verify (`verification.rs:537-556`; `launcher-adopt-ux/campaign-close.md:52`, owner step AI-14). Make publishing the `file_index` a work packet (not just an owner decision). Also make the silent index-fetch-failure fallback (`verification.rs:595-609`) emit a visible reason, a log line and telemetry. Reconcile with docs/analysis/launcher-adopt-ux/. Do not skip signing or the manifest-chain rules.
5. **D-LT4 decided: use https.** (2026-10-21) Launcher summaries and the default telemetry upload URL are https. No plain-http path. LT-22 and LT-23 are unblocked; the default URL in directive 1 must be an https URL the colo actually serves (verify, and make the packet blocked if the colo has no https endpoint yet).
6. **OQ-LT3 decided: no IP in logs.** (2026-10-21) Drop the peer IP from the dev-session refusal logs and from every launcher/telemetry log, field and attribute. Do not hash it. Refusal logs keep the reason and a count, never the address. Add a regression test that fails if an IP appears.
7. **Colo https origin now exists (2026-10-21, done by hands-on).** The board's Caddy proxy (`board-proxy` on node5) serves `https://play.cimmeria.app` and forwards only the five :8081 telemetry routes (dev-session mint/refresh, upload-chunk, upload-bundle, launcher-summary) to loopback :8081; everything else is 404. http :8081 is unchanged. So D-LT17 is resolved: LT-41 may use `https://play.cimmeria.app` as the built-in default (verify with a status-code probe first). Follow-ups to plan: (a) a code packet so the server trusts `X-Forwarded-For` from loopback only, for per-IP rate-limit keys ONLY, never logged or stored (directive 6 still holds); today all https callers share one proxy-address bucket (summary 12/min, chunk 600/min, bundle 30/h, mint 120/h) and will 429 at scale; (b) the Caddyfile edit lives on the host and must be mirrored into the private agent-board repo or a board-proxy redeploy undoes it (owner/ops task); rollback is restoring the Caddyfile.bak-* and `docker restart board-proxy`; (c) docs/operations/telemetry.md steps 2-3 (Cloudflare Tunnel never deployed) and the proxy-quota section (~line 382) must describe this route.
2. **No dead UI.** Every telemetry checkbox must do something real. Wire all launcher telemetry, and add telemetry wherever the launcher lacks it.
