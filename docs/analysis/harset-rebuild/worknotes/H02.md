## Behaviour implemented

### 1. Bounded stall deadlines on the four unbounded states

A single `Timers::stall_at` field, armed on every transition through
`RingTransporter::arm_stall`, polled by the existing 100ms ring tick as
`DeadlineKind::Stall`. Values (`transporter/mod.rs`, `STALL_TIMEOUTS`):

| State | Timeout | Waiting on |
|---|---|---|
| `SendWait` | 60s | the player physically reaching the pad |
| `RecvWait` | 65s | the source beginning its send |
| `RecvWarmup` | 15s | the source's own 4.0s warmup |
| `RemoteLoadWait` | 90s | the cross-world client world-load round trip |

`RECV_WAIT_TIMEOUT` is deliberately longer than `SEND_WAIT_TIMEOUT` so the
source always aborts first; otherwise the destination could go `Idle`, be
re-reserved by a third ring, and then receive the first source's passengers.
`REMOTE_LOAD_WAIT_TIMEOUT` is 90s rather than the 45s originally proposed —
see Advisor findings.

One field rather than four is justified by an exclusivity claim that
`only_externally_waiting_states_have_a_stall_bound` pins: the four bounded
states are mutually exclusive on a transporter and never overlap the four
existing deadlines (`SendWarmup` owns hide+warmup, `RemoteWarmup` owns
remote_warmup, `Cooldown` owns cooldown, and a new trip cannot start on a
non-`Idle` ring). `stall_at` is checked **last** in `elapsed_deadline` so a
real transition wins if that invariant is ever violated.

### 2. Abort semantics

`RingTransporterManager::abort_pair` returns both ends to `Idle`, clears every
timer and all transient trip state, and emits `ShowPlayer` then
`UnlockMovement` for each participant.

- **Show before unlock.** Unlocking first opens a window in which the player
  can move while witnesses still hold them hidden, and `send_visible` resolves
  its witness set at call time — a witness entering AoI in that window never
  receives the `onVisible(1)`. It also matches the happy path
  (`remote_warmup_timer_expired` shows, `cooldown_timer_expired` unlocks).
- **Participants only.** `send_players` union `expected_players` union
  `players_loaded`. Pad occupants (`players`) and reservers (`reserved_by`) are
  excluded: they were sent neither `LockMovement` nor `HidePlayer`, and a stray
  `onVisible(1)` for them would churn visibility for every one of their
  witnesses.
- **Peer back-pointer guard.** The peer is reset only when its
  `remote_region_id` names the aborting region. A mismatch is logged at warn
  (`reason = "peer_backpointer_mismatch"`) rather than silently dragging an
  unrelated healthy trip down.
- **No reposition.** An abort never teleports anyone. On every source-side
  abort nobody has moved (teleport and the source's reset to `Idle` happen in
  the same call); on the destination side, anyone in `players_loaded` has
  already arrived correctly.
- `reset_to_idle()` replaces every ad-hoc `state = State::Idle` write. The
  destination-busy rollback in `handle_select_destination` was the live case:
  it ran one statement after `enter_send_wait` armed the 60s deadline and left
  it armed on an `Idle` ring.

### 3. `expected_players` replaces the bare `num_remote_players` count

The destination now holds passenger **ids**; `num_remote_players()` is a
derived accessor so the readiness equality and the existing tests are
unchanged. This buys three things:

- A `RemoteLoadWait` abort can release passengers who are in flight but not
  yet loaded. That covers the two early-return paths in
  `Effect::TeleportPlayer` (entity missing from space; cell to base send
  failed) which leave a locked, hidden player in *no* set on either ring — the
  audit flagged the comments on those paths, but a timeout alone would not have
  recovered the player.
- A departing passenger is a set removal, not a decrement that can underflow.
- `forget_participant` removes from **both** destination sets. Removing only
  the expectation would leave `players_loaded.len() != num_remote_players()`
  permanently — a fresh stall in place of the old one.

### 4. `reserved_by` — the missing `SendWait` participant

Before H02 a `SendWait` trip had no participant recorded on either ring: the
player is in `players` only once they physically arrive and in `send_players`
only once warmup starts. `enter_send_wait` now records the selecting entity,
so a disconnect during `SendWait` frees the pad immediately instead of waiting
out the 60s bound. This is the Harset-specific case the H10 worker raised (see
Cross-packet findings).

### 5. Departure hooks

| Path | Hook | Timing |
|---|---|---|
| Client disconnect (`SpaceManager::disconnect_entity`, async, has `tx`) | `ring_transport::forget_player` | synchronous, **before** the `LeftAoI` fan-out and witness scrub |
| Every other destroy (GM despawn, gate travel, respawn, content transport) via `destroy_entity` (sync, no `tx`) | `RingTransporterManager::note_player_gone` | queued; the next ring tick does bookkeeping, state flip and effects together |

The queued path is deliberate, not a compromise: flipping FSM state in
`destroy_entity` while the wire effects waited for the tick would let a player
re-trigger the pad inside the gap and receive the *previous* trip's
`ShowPlayer`/`UnlockMovement` on top of their new one. Keeping both in the
tick removes that window by construction.

**The queued path is source-side only** (`players`, `send_players`,
`reserved_by`). `Effect::TeleportCrossWorld` calls `destroy_entity` itself as a
legitimate hand-off step while the destination is correctly parked in
`RemoteLoadWait` counting that traveller; touching `expected_players` from
there would fast-path the destination to `Idle` and strand them. A genuine
disconnect reaches the destination sets through `forget_player` only.
`cross_world_handoff_destroy_does_not_strand_the_traveller` pins this.

### 6. The three misleading comments

`dispatch.rs` — all three now describe what happens:

- entity-missing-from-space: the destination really does time out now
  (`REMOTE_LOAD_WAIT_TIMEOUT`), and the entity is already gone so nothing is
  left hidden or locked.
- cell to base send failed: the player *is* still locked and hidden and is in
  no set on either ring, which is why the expectation carries ids — the abort
  releases them.
- `GateTravel` send failed: the ring becomes selectable again at the timeout;
  the player still has to relog to recover their own session.

### 7. Adjacent fixes made in the same pass

Both are inside owned paths, both are defects this packet's new code would
otherwise multiply. Flagged here explicitly so they can be vetoed and split
out.

- **A fifth unbounded state the audit did not list.** `run_one_deadline`'s
  warmup branch returned on an unresolvable destination region **without
  clearing `warmup_at`**, so it re-fired every tick forever (bounded per tick
  by `MAX_PER_REGION`, re-armed the next tick) while the source sat in
  `SendWarmup` with every passenger locked and hidden. Reachable because
  `ring_regions` and `ring_transporters` are separate maps that can disagree.
  It now aborts. Guard:
  `warmup_with_a_missing_destination_region_aborts_instead_of_spinning`.
- **`BSF_MOVEMENT_LOCK` was written with a raw bitmask.**
  `wire_helpers::update_state_flag` did `state_field |= flag` / `&= !flag`.
  `crates/entity/src/cell_entity/state_flags.rs` names that flag as
  ref-counted with death and the `Stun` effect script as other writers, and
  calls mixing the two patterns "a real production hazard". Concretely: a
  player who dies during `SendWarmup` gets a counted `set_state_flag` from the
  death path, and the ring's raw clear would free the corpse. Migrated to
  `set_state_flag`/`unset_state_flag`, sending `onStateFieldUpdate` only on the
  returned transition. The ring is the only caller of this helper, so no other
  writer had to move.

### 8. Injectable clock

`RingTransporterManager` owns an `Arc<dyn Clock>`, reusing
`cimmeria_mercury::clock::Clock` — the trait `Channel` already reads time
through for RTO/keepalive — rather than inventing a second abstraction.
Mercury's own `TestClock` sits behind the `test-harness` feature that
`cimmeria-services` does not enable, so the tests carry a four-line local
`FakeClock` implementing the same trait. The clock lives on the manager rather
than being threaded through the `handle_*` signatures because those callers
(`cell_methods`, the content executor) are outside this packet's ownership.

## Gaps and things deliberately not done

- **Ring arrival navmesh validation** — excluded; see Integration requests.
- **Multi-player Matinee sync** — untouched. `all_players_loaded` still picks
  `players_loaded.first()` for the kismet; a passenger who dropped mid-load may
  have been the original first. The code uses `first()` rather than an index so
  it cannot panic, and the FIXME in `ring-transport-system.md` still stands.
- **Cross-world rings as a feature** — the `TeleportCrossWorld` path is
  unchanged apart from its comments and the hand-off note.
- **The four delay constants** — unchanged (3.5 / 4.0 / 3.0 / 2.5s).
- **Timeout values are judgement, not recovered data.** No 2009 evidence exists
  for any of the four; the Python original had no timeouts at all. They are
  chosen from the shape of what each state waits on. If a live UAT shows a slow
  client tripping `REMOTE_LOAD_WAIT_TIMEOUT`, raise it — a false abort there is
  worse than a late one.
- **`abort_pair` does not cascade past one hop.** A aborts B; if B were somehow
  also linked to C the chain stops. Unreachable today (a ring holds one
  `remote_region_id`), and C's own stall bound would catch it.

## Proposed text for H99 (`docs/gameplay/ring-transport-system.md`)

Two edits.

**(a) Extend the `#### Timing` table** (currently ends at "Cooldown | +2.5s")
with the bounded abort deadlines, and add a paragraph after "Total minimum
time":

> | Phase | Delay | What Happens |
> |---|---|---|
> | *(abort)* | +60s from `selectDestination` | `SEND_WAIT` expires — the player never reached the pad |
> | *(abort)* | +65s | `RECV_WAIT` expires on the destination |
> | *(abort)* | +15s | `RECV_WARMUP` expires |
> | *(abort)* | +90s | `REMOTE_LOAD_WAIT` expires — the cross-world arrival never reported loaded |
>
> **Bounded aborts (Cimmeria, not 2009).** The Python original had no timeouts:
> `SEND_WAIT`, `RECV_WAIT`, `RECV_WARMUP` and `REMOTE_LOAD_WAIT` waited
> forever. Because `selectDestination` refuses any destination that is not
> `IDLE`, one stalled trip removed that pad from every peer that could reach
> it — on Harset's five-ring mesh, permanently. Cimmeria adds a bounded
> deadline to each of those four states. On expiry both ends return to `IDLE`,
> every participant is re-shown and then unlocked (in that order), and the
> destination's expected-passenger set is cleared. A departing player is also
> removed from any ring holding them: immediately on client disconnect, and on
> the next ring tick for every other teardown path. Aborts log at `warn` with
> `region_id`, `peer_region_id`, `state` and a stable `reason`
> (`stall_timeout`, `player_gone`, `peer_aborted`,
> `destination_region_missing`). See the
> [H02 worknote](../analysis/harset-rebuild/worknotes/H02.md).

**(b) Add a note under `#### Harset (world 57) — 5 regions, fully connected
mesh`** (after the table at line ~350), flagging the two spellings:

> **Region 8's tag has two spellings in the source data and both are
> load-bearing.** The DB row's tag is `HarsetinRingRightRegion` (rendered
> `HarsetinRingRight` in the table above), while the 2009 space script
> `deprecated/python/cell/spaces/Harset.py` keys the same ring as
> `HarsetRingRight` (see the Space Scripts section below). The other four rings
> agree between the two sources; only region 8 diverges, and it looks like an
> authoring typo that shipped. Anything matching on the tag must use the
> spelling from the source it is reading — the seed's `HarsetinRing…` for
> `ring_transport_regions`, the script's `HarsetRing…` for the legacy
> interaction map. H10's five `interact_tag` chains key on the seed spelling.

Whoever lands H99 should verify the cross-link anchors resolve; H02's test
fixture `tests/support.rs::harset_rings` carries the seed spelling byte-exact
so a future rename that fixes only four of the five rows trips a test.
