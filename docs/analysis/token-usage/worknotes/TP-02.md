# TP-02 worknote: quiet build and test output (lever B)

> Packet of [#957](https://github.com/SandboxServers/Cimmeria/issues/957). Ledger: [../README.md](../README.md). Updated 2026-10-03.

## Done

- `tools/build-lane/lane.sh`: when stdout is not a terminal and neither `LANE_VERBOSE=1` nor `CI=true` is set, the command's output goes to `$LANE_ROOT/logs/<worktree>/<time>-<pid>.log` and stdout gets a summary. One stderr line up front names the log, so a caller whose tool times out still has it. nextest's reporter is set through `NEXTEST_STATUS_LEVEL=fail`, `NEXTEST_SHOW_PROGRESS=none` and `NEXTEST_FAILURE_OUTPUT=final`, only when the caller hasn't set them. Logs are pruned to the newest `LANE_LOG_KEEP` (20) per worktree and to `LANE_LOG_DAYS` (7) days. The job log gains `quiet` and `log` fields.
- `tools/build-lane/lane_summary.py`: extracts the summary. It handles rustc and clippy diagnostics (deduplicated, capped at 8 errors of 14 lines), libtest and nextest counts, failing tests with their panic excerpt, and warnings as one line each. A failure it doesn't recognise falls back to the log's last 25 lines. Without Python, the lane prints the last 40 lines of the log.
- `tools/build-lane/rm-worktree.sh` deletes a retired worktree's logs.
- Tests: `tools/build-lane/test_lane_summary.py` (16 tests). They use real cargo, clippy and nextest output in `tools/build-lane/fixtures/summary/` (compile error, nextest build error, clippy deny and warning, cargo test and nextest failures with an assertion and an index panic, successes), and run lane.sh in quiet, `LANE_VERBOSE=1` and `CI=true` modes, with log pruning and the no-Python fallback. One assertion in `test_lane_stats.py` now checks stdout as well as stderr for `pruned`.
- Docs: build-system.md §3, development-workflow.md (Build through the lane), CLAUDE.md lane item 5, copilot-instructions.md, troubleshooting.md (new entry), and a comment in `tools/test-live-db.sh`.

"Before" is the same lane with `LANE_VERBOSE=1`, which is the old behaviour. The failure cases were scratch edits, reverted.

## CI

CI keeps full output in two ways. GitHub Actions sets `CI=true`, which turns quiet mode off, and a test covers that. And CI's live-DB jobs call `tools/test-live-db.sh` directly, not through the lane. The build-lane unit tests run in CI under `CI=true`, and the quiet-mode tests unset it themselves.

## Left / open questions

- The lane doesn't stream progress in quiet mode. An agent that wants it can `tail -f` the log named on stderr, or set `LANE_VERBOSE=1`.
- `tools/test-live-db.ps1` is unchanged: it runs from PowerShell, outside the lane.
