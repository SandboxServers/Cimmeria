## Reproducing

The scripts were scratch, outside the repo, because they handle PR titles and branch names next to transcript-derived data. The steps:

1. Copy the profiler database (read-only use); `report.db.open_db` and `scope` give the `rcost` view.
2. `report.sections.prs.pr_records(db, Scrubber(), merged)` for the merged PRs; it leaves `temp.report_pa`, one row per attributed request with its weight, trigger kind, context and gap.
3. Per request: the first-request context of its transcript (session plus agent), its tool calls (fingerprint, result characters, later requests) and its predecessor in the transcript. Apply the computations in the study's teardown table.
4. GitHub: one GraphQL query over merged PRs, 20 per page, newest first, stopping at PRs created before 2026-09-01 (fetch any merged PR older than that by number): title, dates, additions, deletions, changed files, labels, reviews with commit, commits with check suites and workflow run, cross-referenced events with the source PR's title and merge time, and the first 100 files with their line counts.

Scrubber: both committed files pass `Scrubber().assert_clean` with the local deny list.
