## Where read exposure goes

Exposure is result characters times the later requests in the same context, the profiler's `exposure_chars`. Over the window, file reads returned 146M characters, 15.8G exposure:

| Read kind | Calls | Result chars | Exposure |
|---|---:|---:|---:|
| Bash `sed -n` | 17,653 | 48.9M | 5.35G |
| `Read`, whole file | 4,690 | 43.5M | 4.61G |
| Bash `cat` | 9,987 | 29.9M | 3.91G |
| `Read` with `offset` / `limit` | 3,798 | 19.6M | 1.41G |
| Bash `head` / `tail` | 4,779 | 4.2M | 0.49G |

Bash calls are counted per file named, so a command that reads two files counts twice and its result is split between them. That is why the `sed -n` count is higher than the 9,050 calls whose fingerprint is `sed -n`: pipelines and compound commands slice several files.

By location: code under `crates/` 6.8G; paths outside the checkout (spilled tool results, background-task output, scratch files) 2.4G; campaign ledgers under `docs/analysis/` 1.6G; the rest of `docs/` 1.5G; other Markdown (root, agent memory, READMEs) 0.8G; seeds 0.5G; 0.7G unresolved (relative paths after a `cd`).

Why agents read them whole or page through them:

- **Size.** `Read` returns at most about 25k tokens, and 56% of whole-file `Read` characters came from results over 20k characters. In the experiment, nine of the ten whole-file reads came back truncated.
- **Long lines.** Grep prints `[Omitted long matching line]` for a line over about 500 characters (between 399 and 542 here), so a hit in a long table row or paragraph needs a `Read` anyway. `Read` cuts lines at 2,000 characters, and a page of long rows trips the token cap, so `offset` / `limit` reads get refused: three refusals on `observability.md` in the experiment. 4,481 Markdown lines in 398 files are over 500 characters. Long lines are a deliberate style here (MD013 is off), so only the pathological ones were changed.
- **Ledgers that grow.** Campaign `work-packets.md` and `README.md` files are re-read at every packet start, and their rows grow to thousands of characters.
- **`sed -n` is mostly not whole-file dumping.** Its median slice is 41 lines (p90 131, p99 291) and its median result 2,012 characters. The volume is the call count. Only 233 file-in-context pairs paged through 80% or more of a file with `sed` (2.6M characters). Shell slicing is a habit rather than an over-read. The rule steers it to `Read` with `offset` / `limit`, which costs about the same and satisfies `Edit`'s read-first check.

## Experiment C

Ten questions drawn from what agents looked up in the top files: `content-engine.md` and `abilities-and-effects-system.md` two each, and one each in `services-crate-split.md`, `observability.md`, `negative-logging-convention.md`, `TESTING.md`, `gap-analysis.md` and `castle_cellblock_chains.sql`. The answer key was written before either arm ran.

Each arm was a fresh `general-purpose` subagent, blind to the key and to the other arm, with its own random question order, told to treat every question as a fresh lookup. The whole-file arm could use only `Read` without `offset` / `limit`, then paged reads if the answer was cut off. The slice arm could use only `Grep`, then `Read` with `offset` / `limit`. Characters are the lengths of the tool results in the arms' transcripts. The files were as on `main` before the splits.

|---|---:|---:|
| Q1 range units (abilities ADR) | 110,021 / 4 (1 refused) | 3,352 / 2 |
| Q2 `display_dialog` speaker (content-engine) | 93,489 / 2 | 4,214 / 2 |
| Q3 Pattern D field (negative-logging) | 44,571 / 1 | 3,211 / 1 |

- **Correctness:** 10/10 in both arms. On Q9 both arms also listed `dialog_set_open`, which the doc puts in the same "authorable but never dispatched" state; the key had missed it.
- **30 times fewer characters, 38% fewer calls.** The whole-file arm's context ended at 395k tokens against 90k, and its context summed over its requests was 6.4M tokens against 1.4M.
- **Long lines cost the slice arm too.** Q6 took three calls because both greps hit a 900-character bullet and got it back as an omitted line.
- **Not measured:** the mixed habit (grep, then read the whole file). The two arms bracket it.
