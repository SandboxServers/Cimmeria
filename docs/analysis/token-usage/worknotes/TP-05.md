All repeats are within one session (150 requests, 856 records; 0 others). "First file keeps it" was right in principle but discovery read subagents alphabetically, so 58 requests went to a fork that sorted before its parent. The ingest now reads forks after their parents (by fork depth) and counts `fork_copied_records` apart from `duplicate_request_records`. Test: `ForkAndCostStateTest` (fails with the old order). ## Acceptance criterion

The OTel half needs telemetry data; SigNoz had no `claude_code` logs or metrics at 13:40Z (checked through the SigNoz MCP: no `api_request` events in 24 h, no matching field keys).

## Steps for the controlled session

1. Restart Claude Code with the Path A settings, note the UTC start, and run a short session that spawns one subagent and runs one `WebSearch` (it should show as an OTel-only request). Exit Claude Code cleanly so the `cost-state` record and the last OTel batch are written.
2. Re-ingest: `python tools/token-profile/ingest --db <db> --repo . --fetch-prs`.
3. Export the session's events to a file. With the SigNoz MCP: `signoz_search_logs` with `query = "body = 'claude_code.api_request' AND session.id = '<id>'"`, a time range covering the session and a `limit` above its request count; save the raw JSON result. (An OTLP file export works too.)
4. `python tools/token-profile/reconcile --db <db> --since <start> --otel <file> --out <scratch>`. Expect `matched_token_mismatch`, `matched_cost_residual` and `profiler_only` to pass, and the OTel-only table to account for the cost-state gap by `query_source`.
5. If the loader finds no events, the SigNoz result shape differs from the one the tests assume (`attributes_string` / `attributes_number` maps under rows); adjust `otel._flatten` with a fixture from the real export.
