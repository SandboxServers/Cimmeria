# CT-87 worknote (operation epoch)

Status: done. Wave 9 review fixes N1-N5 applied on this branch; N2 and N3 are in `sign_in/driver.rs`, `driver_continue.rs` and their test files, N5 is this note.

## Epoch design

- `SignInDriver::epoch` is an atomic counter. `run` captures it on entry, so every request runs under the epoch it started with.
- `supersede` (driver.rs) bumps the counter under the state lock, then cancels the parked flow. Sign out (`sign_out`) and Cancel both call it, so a bump always precedes the clear of the session or the pending choice.
- `host_slot::Epoch` is the fence of one step: it holds the counter and the value read at the start, and `is_current` compares them.
- `adopt_signed_in` (session.rs) checks the fence under the host slot lock before it writes the store. A stale fence sends a best-effort `/logout` and returns `Superseded`, which maps to `Cancelled`.
- `installable` (driver_epoch.rs) is read under the state lock by `install` and `keep_choice`. It refuses when the epoch has moved or the target has moved (`same_target`). Those two are the only places a completion installs the signed-in session or keeps the `needs_link` choice.
- `link()` keeps a pending choice after a retryable link error only while the epoch is unchanged (N2).
- `continue_flow` (driver_continue.rs) returns the other server's status without an account when the reply is for a server other than the session's base (N3).

## Residual race (known, accepted)

The epoch can move after `adopt_signed_in` has written the store but before the `installable` check. The install is then refused while the token stays in the store. A first sign-in in flight therefore leaves Sign out with no session in `DesktopState` to clear, so the stored token survives that Sign out. Closing it needs Sign out to clear the host slot by host when the state holds no session. That change is outside this packet.
