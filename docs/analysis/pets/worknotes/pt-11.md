3. **Lo'taur look.** No seeded template uses `AR_G_Underlings`. `body_components` declares nine

   pauldron was left off (a servant, not a guard); `BS_GM_Boots_00` and `BS_GM_Hair_03` were

   350 now does too.

## Design decisions

- **Flags 1024, not 1032.** "Same shape as 350" except `NoPetLeveling`, per D-PT02 (evidence 8).
- **Deviation: the Prime keeps 159's staff.** The packet lists 1654 for the Prime. 1654 alone is a
  silent no-op, so a Prime with only 1654 would never hurt anything. 352 copies 159, which carries
  set 4, so set 352 = 584, 710, 1654. Accepted by the coordinator (round 2).
- **Abilities that do nothing (round 2, coordinator decision).** One predicate,
  `cimmeria_entity::abilities::ability_is_unimplemented` (`crates/entity/src/abilities/implemented.rs`):
  no event set and no effect with `HealthDamage`/`FocusDamage` > 0 or a `script_name`. It is used by
  - CM 88 (`cell-methods .../player/pet/invoke.rs` `check_invoke`, after the toggled-off check):
    refused before the cast with `onErrorCode` 167, the chat line "Your pet can't use that ability
    yet." (`pets::order_feedback_text`) and DEBUG `pets.command reason=ability_not_implemented`;
  - the pet AI's pick (`npc_ai/pet/mod.rs` `ability_allowed`, pets only; a mob is unchanged), so a
    pet whose kit is all no-ops (the Lo'taur) holds fire;
  - the NA43 allowlist guard `animation_allowlist_entries_deal_no_damage`.
  An ability with no definition is not treated as unimplemented (left to the existing paths). The
  pet-command test fixtures give their bare abilities event set 3 so they stay ordinary casts.
- **Straegis level (round 2).** Template 350 drops `NoPetLeveling` (flags 1032 -> 1024); PT-S's
  exact-flags guard now pins `ENTITYFLAG_Pet` alone and that bit 8 is clear.
- **1652 gets event set 3.** Its description is "Staff: Ranged Single Target Attack" and effect
  2015 has 646's shape (Medium/Narrow, the same -250F -25H text). Without a set the pet-bar order
  plays nothing, which breaks the first-press feedback rule. 1654 and the Lo'taur abilities have no
  data-backed set, so they are allowlisted in the NA43 linter instead, with reasons.
- **Allowlist premise guard.** `animation_allowlist_entries_deal_no_damage` fails as soon as an
  allowlisted ability gains damage, a script or an event set, so the allowlist cannot hide a silent
  hit later.
- **Ability sets 351-353** follow PT-S's rule (pet sets use the pet template ids).

- **Known gap: the Lo'taur cannot heal (friendly-target pet abilities are unsupported).** Its whole
  kit is refused on order and skipped by the AI, so it holds fire.
- **No-op kits.** 1652, 1654, 1653 and 3326-3329 do nothing (evidence 4). Making them real is
  effect work: damage NVPs or a script for 2015/4086, a pulse model for the 2- and 8-pulse
  effects, and for the Lo'taur an ally-target AI branch before `HealHealth`/`HealFocus` are bound.
- **Silent orders:** fixed in round 2 (refused with feedback, see Design decisions).
- **Range units.** Coordinator files a server-wide issue; no change here.
- **Range detail.** 1652 `max_range` 3000 and 1653 800 are read as world units (probably cm in the
  data). The pet AI therefore fires 1652 from any distance while 584 cools, and CM 88 accepts a
  1652 order from 3000 u. Server-wide, not pet-specific.
- **knownPetAbilities** is unimplemented; 1652/1654 are on every Jaffa/Prime from L1.
- **Straegis level** (evidence 8): fixed in round 2.
- **Renders.** The Lo'taur composite is unproven; the Jaffa and Prime looks are placed today but
  never as class 0x05.
