## Design decisions

1. **Pet = NPC + boxed `PetState`.** `CellEntity` grows by one field, as the contract fixes. `entity_struct.rs` is over the file cap, so everything else lives in `pet.rs`.
2. **The spawn reshapes the template record before spawning.** `spawn_pet_from_template` clones the cached prototype and sets `class = "pet"`, `flags |= ENTITYFLAG_Pet`, the owner's faction and level, and clears loot, respawn, patrol, wander, tag, aggression override and cover. Then it calls the existing `spawn_npc_from_record_in_space`. Health from level, `use_cover` and the wire class therefore come out of the one spawn routine. Nothing is patched afterwards. The class is forced to `pet` whatever the template row says.
3. **`ENTITYFLAG_NoPetLeveling` is honoured.** A template with it keeps its own level. Everything else follows D-PT02.
4. **Stance mask from the `ENTITYFLAG_No*` bits.** Bit `1 << stance` per allowed stance. The start stance is Defensive when it is allowed, otherwise the first allowed stance. The flag-to-list mapping is inferred from the flag names (code map §0); PT-E1 did not contradict it.
5. **Position.** 2 u behind the owner (`yaw` convention `(sin, cos)`), facing the owner's heading. The navmesh grounding in the spawn routine fixes Y.
6. **One `NpcAoIData` constructor.** Both `EnteredAoI` sites now call `NpcAoIData::from_entity`. Before, they built the struct field by field in two places, and a new field (here `pet_owner_id`) could reach one intro path and miss the other. This is a structural edit to `aoi.rs` and `request_entity_update.rs` beyond the purely additive (see "Integration edits").
7. **Owner binding to every witness, lists to the owner only.** This is the coordinator's routing call on the PT-E1 result. The owner id rides the cascade for all witnesses. `onPetAbilityList` and `onPetStanceList` go to the owner only, through `WitnessEntityMethod`, from one helper (`pet_create_on_client_events`) that both intro sites call. `onPetStanceUpdate` is sent only when the stance is not Defensive.
8. **Teardown layers.**
   - `destroy_entity` and `destroy_space` scrub the registry for any pet they remove.
   - `disconnect_entity` calls `forget_owner`, which despawns the owner's pets through `despawn_npc` (`LeftAoI` + witness scrub) before the owner's own AoI teardown.
   - `pet_owner_sweep` runs every 100 ms AoI tick. It despawns a pet whose owner is missing, in another space, or has `BSF_DEAD` (the state bit, not HEALTH). It returns at once when the registry is empty.
   - `destroy_entity` does not despawn a destroyed owner's pets itself. It has no `tx`, so the sweep does it within one tick.
9. **Class filters (A-22).** `ai_driven_npc_entity_ids` admits `SGWPET_CLASS_ID`. `all_npc_entity_ids` and `npc_ids_in_space_of` keep `== SGWMOB_CLASS_ID`, with comments. Both now use named constants instead of `0x04`.
10. **Log target** `pets.lifecycle`:
    - INFO `summoned`, `despawned`;
    - WARN `summon_failed`, `despawn_failed`;
    - DEBUG `registry_scrubbed`.

    `OTEL_FILTER` gains `pets=debug`, a prefix row that also covers the later `pets.command` and `pets.ai`.

## Known gaps (other packets)

- Nothing in production spawns a pet yet: summon is PT-03, the `.pet` console is PT-07.
- A pet is AI-ticked as a plain mob. With the owner's faction it never proximity-aggroes, and it has no patrol or wander, so it stands where it spawned. Follow, stance and owner-relative leash are PT-05.
- `onOwnerDeath` / respawn / gate travel / transfer are covered only by the sweep, within one AoI tick. PT-02 makes them immediate and adds the same-space teleport.
- A dead pet stays a corpse until the sweep sees its owner gone; the 10 s pet-corpse despawn (D-PT08) is PT-02 (`PetState::despawn_at` exists for it).
- `credit_recipient` exists but nothing calls it yet (PT-06).
- The owner gets a `LeftAoI` for its own pet during its own disconnect (`despawn_npc` notifies every player whose witness set holds the pet, and the owner is still in the space at that point). The base routes it through `send_to_witness_reliable` to a session that is closing. This is expected to be harmless, but it was not checked end to end.

## Integration edits for the coordinator

- **Beyond-additive edits on the AoI create path:** `space_manager/aoi.rs` and `request_entity_update.rs` now build `NpcAoIData` with `NpcAoIData::from_entity` instead of a field-by-field literal. `NpcAoIData` has a new field `pet_owner_id`, so any literal elsewhere (crafting, guilds) needs `pet_owner_id: None` or `..Default::default()`. Nothing in `create.rs` changed structurally: the owner binding is one new `if let` block after the `DatabaseId` block.
