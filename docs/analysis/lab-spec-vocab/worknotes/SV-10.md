# SV-10 worknote: lab_uat_calibrate

Implementer notes (rust-gameserver-dev, 2026-10-11). Code: `crates/lab/src/uat/calibrate/drive.rs` (the sweep), `calibrate/candidate.rs` (one candidate: stand, camera, probe, confirmations), `crates/lab/src/server/calibrate.rs` (the tool). Tests: `calibrate/drive_tests.rs`, `server/lease_tests.rs`, `lease/policy.rs`.

## For SV-14 (lab guide tool table and the calibrate how-to)

- `lab_uat_calibrate { section, row, pose?, specs_dir?, budget_minutes?, radii_m?, bearing_step_deg?, lease_id? }` (own lease, owner `lab_uat_calibrate`; `instance` is the router's usual argument). Returns `{ "run_dir": "<run folder>", "outcomes": [{ ok, section, row, pose, score?, confirmed, changed?, diff_path?, probes, reason? }] }`, compact. `run_dir` is there even when nothing is proposed; `diff_path` is on the first outcome that proposed only (the one diff carries every proposal, and its header names the spec file).
- Refusals, before anything moves (one outcome per pose, `reason` set): the section's `account` is not `gm`; no server lab MCP (`CIMMERIA_LAB_MCP_URL/_TOKEN`); `lab_client_status` is not `in_world`. A missing row, pose or a row with no `client_world_click` pose is an outcome reason too.
- With no `pose`, every pose a `client_world_click` step of the row names is calibrated, in step order, each once.
- The run folder is a normal UAT run folder under the UAT root (`run.json` included). It holds `calibrate.jsonl` (one line per probe: `{pose, i, r, b, yaw, pitch, ok, hits, score}`, plus `confirm: n` on a confirmation re-probe and `miss: "stand" | "camera" | "probe"` when a candidate never reached a probe verdict), the rewritten spec copy `<file name>`, and `<section>.diff` (a `git apply` diff against `docs/guides/uat-specs/<file>`). The spec file itself is never written.
- `changed` holds only the fields that differ at the precision the pose line writes them: `{ "bearing_deg": [322.5, 0.0] }`. A field the old pose did not set shows as `"none"` (D-SV12: no nulls).
- When the winner is the pose as it already stands, the outcome is `ok` with an empty `changed`, and the diff updates only that pose's `calibrated` stamp.
- `reason` on an `ok` outcome says the sweep stopped early: `budget: swept <k> of <n> candidates`. A pose after the first that the spent budget never started says `budget: not started`; a revoked lease says `lease revoked: <why>` on the pose it cut and every pose after it.
- The budget is for the whole call (default 15 minutes, at most 30), checked between candidates, not only between stands. The first pose's first candidate always runs; a later pose starts only while budget is left. A winner already found is still confirmed after the budget is spent, for up to 2 minutes past it (`CONFIRM_GRACE`).
- `budget_minutes` must be above 0 (a value too large for a duration is the 30-minute cap). `radii_m` must be within 1.0 to 8.0 m (a pose's valid range), `bearing_step_deg` from 1 to 360, and the grid at most 1999 candidates a pose (`MAX_CANDIDATES` 2000 with the current pose); anything else is refused as invalid params.
- Confirmation: stand at the opposite bearing (b + 180), then back at the winner, camera, probe; each of the 3 must be `ok` with at least 6 jitter hits. The sweep stops at the first failed confirmation and tries the next best, at most 3 winners.

## Deviations from the packet

- **Pitch of the new pose.** An explicit candidate pitch is written as the pitch the candidate asked for, not `absolute.pitch.got`. `client_camera` only succeeds when the readout is within 0.5 degree of the request, so the readout adds only noise, and with it a recalibrated, unchanged pose would show a spurious `pitch_deg` change and a diff. A candidate that kept the face pitch records the readout (`view_after.pitch_offset_deg`), as the packet says.
- **Yaw of the new pose.** A pose with no `yaw_offset_deg` keeps none when the winner's yaw is 0 (the candidate grid reads a missing yaw as 0).
- **Zoom.** The new pose always records the zoom it ran at, so a pose with no zoom gains `zoom = 250.0`.
- **The unchanged pose.** When nothing but `calibrated` would change, the diff still proposes the new stamp (coordinator decision in review): a re-measurement must leave provenance, and SV-15 reads it. `changed` stays empty, since it lists only the pose's geometry.
- **Several poses in one call** build one cumulative rewrite, so `<section>.diff` carries every proposed pose line; only the first outcome that proposed names it (D-SV12).
- **The candidate log** carries `pose`, `confirm` and `miss` besides the packet's fields: several poses share one log, and a miss needs its step to be diagnosable.
- **The `instance` argument** is not declared on the tool: the router strips and routes it before any tool sees it (as for `lab_uat_run`).
- **Stamp.** The tool has no server-version argument, so `calibrated` is `"<date> 3/3"`.
- **Lease loss.** A sweep whose lease is revoked stops at the next candidate, or at the next confirmation re-stand, and proposes nothing (`reason: "lease revoked: ..."`); the poses after it are not started.
- **Lease plumbing.** `RouterInvoker` and its new constructor are `pub(super)` (the server module is the only user), and `RunLease::acquire_own_as` takes the owner name; `lab_uat_run` keeps `acquire_own`.
- **Tests.** The sweep tests use a client fake with geometry (`/gmgotoxyz` moves the player, the hover answer depends on where it stands and how the camera points) under paused tokio time, not the runner's `Fake` / `FakeServer` with canned queues: those are private to `runner`, and a geometry fake proves the re-stands of a confirmation rather than a reply order. Two tests go beyond the packet's list: the budget is checked between candidates that share a stand point, and an out-of-world client is refused after one status read.

## Review fixes

Two reviewers and a test audit, applied in one follow-up commit on the rebased branch.

- **Off-screen avatar.** The real `client_hover_probe` sends `avatar_px: null` when the avatar does not project. `score::parse_probe` required a number, so a real hit was thrown away. A null `avatar_px` is now the D-SV6 cap (400 px, "far"); a missing field is still no probe.
- **Bounded inputs.** `budget_minutes` uses `Duration::try_from_secs_f64` (1e300 is the cap, not a panic) and must be above 0. `bearing_step_deg` must be at least 1, and a grid over `MAX_CANDIDATES` (2000, the current pose included) is refused before anything is built; `grid::candidates` also stops at the cap whatever it is given.
- **Bounded confirmations and later poses.** The pose loop checks the lease before each pose and the budget before each pose after the first (`budget: not started`). `confirm` checks the lease and a confirmation limit before every re-stand. The limit is the budget deadline plus `CONFIRM_GRACE` (2 minutes). Worst case after the budget is spent: one re-stand already under way when the grace runs out, so the grace plus one re-stand (two `stand_at` calls of at most 5 s polling each, a camera call and a probe). Without the grace the bound would be 3 winners x 3 re-stands.
- **D-SV12 output.** The result carries `run_dir` once at the top. The per-pose `spec_path` is gone, and `diff_path` is set on the first outcome that proposed only.
- **Unchanged pose.** See deviation 3: a stamp-only diff is now proposed.
- **Tests.** `drive_tests.rs` is now the fake and the harness; the tests moved to `drive_sweep_tests.rs`, `drive_confirm_tests.rs` and `drive_bounds_tests.rs`. The fake refuses hover arguments as `HoverRequest` does and answers `avatar_px: null` for the winner of the main test; every sweep runs the no-click allowlist check in the harness; new tests pin the camera's exact arguments, `aim = "point"`, a tie going to the earlier candidate, the three-winner bound, the 6-hit confirmation boundary, a two-pose cumulative diff, a failed stand, a lease revoked mid-sweep and mid-confirmation, and a spent budget skipping a later pose. The lease test's holder call now loads a real section and stops on its grid argument, which only a call that did not try to take its own lease can reach (a valid grid would drive and write a run folder into the real UAT root).
- **Rebase.** `ActionRecord` gained `optional` on main (SV-11); the scratch record sets it to false.
