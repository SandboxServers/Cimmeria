# SV-06 worknote: client_hover_probe

Doc deltas for SV-14, and deviations from the packet.

## For SV-14 (lab guide tool table)

- `client_hover_probe` (leased, world actions): hover an `entity_id` or a `point` (with optional `expect_entity`) without clicking. Result: `verdict` (`"ok"`, `"off_screen"`, or the miss: `"own"`, `"nothing"`, `{"other_entity": id}`, `{"ui": "<window>"}`), `pixel`, `hover`, `jitter_hits` of `jitter` (8, ring radius `jitter_px`, default 12), `avatar_px` (null with `avatar_error` when the avatar could not be read or projected; null without it when the avatar is off screen), `edge_px`, `cursor_restored`, `entity` (entity aim), plus the standard `native_level` / `steps` fields.
- It never turns the camera: an aim off screen is `verdict: "off_screen"`, so face the target with `client_camera` first.
- A HUD window over the pixel outranks mouse-over: the hover is `{"ui": name}` whatever the client reports.

## Deviations

- `WorldIo` gained `cursor()` (not in the packet's contract): the probe reads the cursor before its first move so it can put it back. `LiveWorld` reads it through `Supervisor::cursor()`; the sim returns its `cursor` field. A failed read fails the probe at step `read_cursor` before any cursor move.
- The window-rect read and its 90% backdrop filter live in `world/lua.rs` (`window_rects_chunk`, `parse_window_rects`, `BACKDROP_AREA_SHARE`), with a unit test, so `io.rs` only wires them. The filter measures against the root window's own rect, which is the screen.
- An entity aim whose body heights never hover the entity scores the first height that is on screen (the packet names only the matched case).
- Jitter points off the screen are not hovered and count as misses.
- The result also carries `cursor_restored` (and `cursor_restore_error` when the restore failed) and `entity`.
- The sim's avatar mouse-over (`avatar_radius_px`, default off) projects the player's body heights from the head camera, so it shows only at a negative `cam_pitch`; the avatar test pitches down to -1.2 rad.
- The HUD window rects are read once, after resolving the aim and before any cursor move, not at each hovered pixel. A tooltip or highlight the hover itself spawns would otherwise count as a window covering the pixel. A window that opens during the probe is not seen.
- The rect walk descends into full-screen windows (at or above the 90% share) and keeps their visible children, down to 4 levels below the root (`WINDOW_RECT_DEPTH`), so a HUD parented under a full-screen container still counts. Only the walk's shape is unit-tested; the live HUD layout (which windows sit under which container) still needs a lab check in SV-15.
- A failure after the cursor first moved still restores the cursor. If that restore also fails, a `warn` is logged and the error's `state` carries `cursor_restored: false`, `cursor_restore_error` and `cursor_start`.
- `avatar_error` (`snapshot: ...` or `project: ...`) separates "avatar distance unknown" from "avatar off screen".
- Jitter points are on screen when `0 <= x < w` and `0 <= y < h` (pixel coordinates, exclusive of the far edge).
- The sim gained three knobs for these tests: `fail_mouse_over_after` (the mouse-over read fails after N answers), `fail_cursor_restore` (a `place_cursor` without a mouse move fails) and `unhoverable` (entities mouse-over never reports).
