## For SV-14 (the UAT guide, the lab guide and tools/README.md)

- `lab calibrate <section> <row> [-Pose <id>] [-Instance <name>] [-Prepare <row ids>] [-BudgetMinutes 1-30] [-SpecsDir <dir>] [-Apply] [-Json] [-Quiet]`. With no `-Pose`, every pose a `client_world_click` step of the row names is swept, in step order. `-SpecsDir` defaults to this checkout's `docs/guides/uat-specs` (as `lab uat`).
- Pre-flight as `lab uat`: argument checks first (exit 2, whatever the daemon's state), then the daemon must answer, the instance (`-Instance`, else the first free hosted one) must be free, and no `SGW.exe` outside the lab may run (exit 3).
- `-Prepare FS-01,FS-02,...`: one `lab_uat_run` of those rows on the same instance first, so the client stands in world where the row starts. A prepare row that does not PASS stops with exit 3 naming it (`prepare row FS-P2 FAIL: ...`).
- Output: one line per pose, then the diff text unless `-Quiet`, then how to apply it.
  - `frost: score 8312, confirmed 3/3, bearing 322.5 -> 330.0; diff <run folder>\first-session.diff`
  - `supply: score 7400, confirmed 3/3, unchanged` (the diff then only restamps `calibrated`)
  - `frost: no proposal: <reason> (best score 5100, confirmed 1/3)`
  - An `ok` pose whose sweep stopped early ends `(budget: swept 40 of 108 candidates)`.
  - Field labels: `radius`, `bearing`, `pitch`, `yaw` (`yaw_offset_deg`), `zoom`; an unset field reads `none`.
- `-Json` (D-SV12): one object, `{ok, section, row, outcomes: [{pose, ok, score, confirmed, changed: {bearing: "322.5 -> 330.0"}, diff, reason}], applied}`, no nulls and no empty arrays; `score`, `changed`, `diff`, `reason` and `applied` only when set. Errors are `{"ok":false,"exit":N,"error":"..."}`. The candidate list is never printed; it is `calibrate.jsonl` in the run folder.
- `-Apply`: `git apply` of the proposed diff in this checkout. Refused with exit 2 when the spec file has uncommitted changes, staged or not (`git diff --quiet HEAD -- <file>`): checked once before any lab time is spent (`docs/guides/uat-specs/<section>.toml`, when that file exists) and again on the file the diff's `+++ b/` line names, just before applying. A diff for a file outside `docs/guides/uat-specs/` (a custom `-SpecsDir`) is not applied. A failed `git apply` is exit 2 too; the diff stays in the run folder. Nothing is ever staged or committed.
- `-BudgetMinutes` bounds the whole sweep (default 15, the tool's). The CLI's own call timeout is the budget plus 5 minutes.
- Exit codes: 0 every pose has a proposal or is unchanged; 1 a pose found none (or no outcomes came back); 2 usage, or `-Apply` refused or failed; 3 the pre-flight, a prepare row, or the `lab_uat_calibrate` call itself failed.
- `lab uat ... -Heal` (D-SV8 (a)): needs `-Leases 1` (exit 2 otherwise, before the daemon is asked). After the batch, the distinct `(row, pose)` pairs of the failed rows' `heal` hints (SV-11) are recalibrated one `lab_uat_calibrate` call each, on the batch's instance, with the tool's default budget. A proposal is copied to `heal-<row>-<pose>.diff` in the batch folder and printed (its line, then the diff text; under `-Json` or `-Quiet` neither is printed, and under `-ProgressToStderr` only the line, on stderr). `batch.json`, `summary.md` ("Heal proposals (spec diffs to review; nothing was applied)") and the `-Json` object gain `heal: [{row, pose, diff}]` only when a proposal was written. Exit 8 then, over every other code (5 and 1 included). With no hints it prints `heal: no failed row carries a heal hint` and exits as the batch would. The spec file is never written.
- `lab watch` (LW-02) is not in this tree yet; nothing here reads `calibrate.jsonl`. The tool writes it, so `lab watch` only has to find the newest run folder.
- `tools/README.md` rows: `calibrate.ps1` (the command), `calibrate-lib.ps1` (its library, also dot-sourced by `uat.ps1` for `-Heal`), `test-calibrate.ps1` (its checks, picked up by `lab.yml`'s glob).

## Deviations from the packet

- **The heal pass runs after the `finally`, not inside it.** A PowerShell `finally` cannot be stopped, and a heal is up to 15 minutes of lab time a pose: inside it, Ctrl+C on a batch would start (and be unable to stop) the calibrations. The summary is written in the `finally` as before; the heal follows, and the summary files are rewritten with `heal` when a proposal was written. Ctrl+C during the batch therefore skips the heal.
- **`-Apply` checks `git diff --quiet HEAD -- <file>`**, not `git diff --quiet -- <file>`: a staged edit is an uncommitted change too, and the packet's form misses it.
- **`-Apply` also checks before the sweep** (the section's conventional file name), so a dirty spec does not cost a 15-minute sweep first.
- **`-Json` carries `reason`** (cut to 40 characters) on a pose that has one, and `applied: true` after `-Apply`. D-SV12's list has neither, but a failed pose with no reason gives an agent nothing to act on. A pessimistic two-pose object (two changed fields, a 100-character run folder, a long reason) measures 398 characters in the test.
- **`-SpecsDir`** is on `lab calibrate` too, as on `lab uat`; the packet's synopsis omits it.
- **The call is not named twice in errors**: `Invoke-McpTool` already throws `lab_uat_calibrate failed: ...`, so only a timeout gets the prefix added.
- **The heal outcome is matched by pose**, not taken as the first outcome, and a heal line names the batch copy of the diff rather than the run folder's.

## Open for the coordinator

- **SV-15 conflicts with `-Apply`'s refusal.** SV-15 step 2 first deletes FS-P3's and FS-P4's pose values in the worktree's spec, then runs `lab calibrate ... FS-P3 -Apply` and `... FS-P4 -Apply` on the same file; step 3 applies four SGU rows in turn. As specified (and built), every one of those `-Apply` calls is refused: the file has uncommitted changes, from the deletion or from the previous apply. Either SV-15 commits between steps (delete, commit; apply, commit; ...), or the rule changes to "refuse when the spec changed during the sweep" (hash it when the call starts, compare before applying; `git apply` is atomic and context-checked, so edits that were the diff's base are safe). The second needs a decision; I kept the packet's rule.
