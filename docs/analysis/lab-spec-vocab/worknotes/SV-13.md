# SV-13 worknote: first-session.toml on the new vocabulary

Implementer notes (rust-gameserver-dev, 2026-10-11). Nothing here was run live; SV-15 calibrates and runs it.

## Deviations

- **The wait matches the real release line.** `crates/base-world-entry/src/base/world_entry_appearance/cinematic_aoi_hold/mod.rs` logs `"Cinematic AoI hold: released, held entity introductions flushed"` on target `aoi.cinematic_hold` with `event = "hold_released"`, `witness_id` (u32), `witness_name`, `reason`, `flushed`, `held_ms`. The packet's `log = "Cinematic AoI hold: released"` is a substring of that message, so it was kept as written; `fields = { witness_id = "${player_entity_id}" }` compares numerically (SV-08).
- **`@stand` stays in FS-P3 to FS-P5's fixtured rows.** Their fixtures set no `position`, and in a full run the rows continue the chain without the fixture, so the stand is what places the player either way. The header says so.
- **FS-P4 keeps the 500 ms after the tutorial X** (the packet keeps the tutorial and dialog steps) and drops the trailing 1500 ms, since `step-80622` now polls.
- **The SGU poses carry no `zoom` either**, like `pitch_deg` and `yaw_offset_deg`: uncalibrated until SV-15.
- **The plan test is a new file**, `crates/lab/src/uat/runner/first_session_plan_tests.rs`, not `runner/tests.rs` (over the cap). `committed_specs_plan_against_main_tools` no longer checks first-session (it would now see BLOCKED rows without a server); `MAIN_TOOLS` and `Fake::tools` became `pub(super)` for the new file.
- **`@world_click { pose }` adds `rotate_camera = false` (SV-07)**, but the four SGU clicks pass `rotate_camera = true` (an explicit argument beats the pose default, `runner/targets.rs` `expand_target_args`). Their poses have no pitch or yaw, so after the face the target may sit behind the avatar and an unrotated click would hit the player; they keep the click tool's own rotation until SV-15 calibrates them.

## Review fixes

- **Target introduction is a 1500 ms sleep after each `@stand`** (FS-P3, FS-P4, FS-S3 to FS-S6, end of setup). `@stand` polls only the client's own reported server position; nothing waits for the target entity to reach the client before `@camera` / `@world_click` address it by entity id. No existing capability can wait on an entity id: `client_wait_for` takes only `lua_condition` / `timeout_ms` / `poll_ms`, `wait_server` waits on a log line with fixed fields (the resolved tag's entity id is not a `${var}`, and in a chained run the target entered AoI long before the watermark), and an `@entity_find { pose }` step does not poll. **Candidate:** a `@wait_for` entity-presence condition by pose or tag (or `@stand` waiting on the pose target too), which would replace these six sleeps.
- **Two UI-guard sleeps restored**, each commented "kept until SV-15 proves it removable": FS-P5's 3000 ms between `equip` and `@key b`, and FS-S6's 3000 ms (its original value) after the click, before the optional teardown `@finish_dialog`.
- **Header:** without `CIMMERIA_LAB_MCP_URL`/`_TOKEN` the pose and `wait_server` rows (FS-P2, FS-P3, FS-P4, FS-S2 to FS-S6) are BLOCKED, not UNVERIFIED; only the other rows' server clauses are UNVERIFIED. `@stand` polls the client's reported server position, not the server's record.
- **#1341 tagging, unchanged on purpose.** `tools/lab/cli/uat-lib.ps1` still tags `FS-[PS]2` failures with reason `movie-over`. A real #1341 (the release is logged, the client drops the entities) still fails the `movie-over` clause and is tagged. A wait that expires instead (no release line, or a `witness_id` mismatch) fails the `movie-over` step and is reported untagged, because it is not #1341. The table was not widened.
