# SV-03 worknote: spec schema

Review outcomes (packet-reviewer, 2026-10-10). The merged code is the reference where it differs from the packet.

## Deviations

- `to_inline_toml` rounds each value first and clamps it into the validation range, so every line it writes loads again: a bearing of 359.96 writes as `0.0`, a pitch of -78.75 as `-78.7`. A written pose can therefore differ from the in-memory one at those edges. SV-09 and lab-record write through it.
- `calibrated` must not contain control characters (validated); the writer turns them into spaces, so a pose is always one line (D-SV2).
- `aim_dy_m` is range-checked at -3.0..=3.0 (the contract gave no range; NaN was accepted).
- `FakeServer` moved to `runner/test_server.rs` with `pub(super)` fields; `Fake::without` is `pub(super)`.
- `PoseSpec` helpers carry `#[cfg_attr(not(test), allow(dead_code))]` until SV-07/SV-08 call them. Remove it there.

## Left over

- `crates/lab/src/uat/runner/tests.rs` is about 890 lines (823 before this packet), over the 700 cap. Split the `Fake` and its canned-reply helpers (`next_canned`, `canned_outcome`) into `runner/test_fake.rs` in a follow-up; SV-07 and SV-08 should not grow it further.
- A `pose` argument together with `name`, `entity_id` or `point` is not flagged (the contract forbids that clash only for `tag` and `face_tag`). SV-07's resolution should treat `pose` as winning, or SV-04 adds the rule.
- The `ExpectSpec.timeout_ms` doc describes 250 ms polling for tool and server clauses, which SV-08 implements.
