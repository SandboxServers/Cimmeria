# SV-05 worknote: absolute camera

Review outcomes (packet-reviewer, 2026-10-10). The merged code is the reference where it differs from the packet.

## Deviations kept

- `yaw_offset_deg` is camera **world yaw** in -180..=180, through the signed `yaw_gain`. On a camera without yaw inversion (flag 0x4) that is the `+yaw_counts` direction the packet names; on an inverted one the counts are negative. A spec value then means the same view on every client. SV-14 should say so in the authoring guide.
- `abs_pitch` learns rotator units per count from each look that moved the camera, instead of trusting the readout's `pitch_gain` on every look. With an exact readout this changes nothing; with a wrong one the old loop over-shot and ran out of looks.
- The sim's readout gains can be scaled (`readout_gain_scale`) so the tests exercise the corrections.

## Fixed from review

- The yaw correction is capped at 4x the first move and `sent` saturates (a swallowed look could ask for a 32,000-degree spin).
- A zero or non-finite readout gain fails the step before any look.
- `yaw_offset_deg` beyond 180 is refused as `arguments`; `0` sends no look.
- At the pitch limit the loop fails at once instead of sending `(0, 0, 0)` looks.

## Left over (not blocking)

- The readout is checked only inside `abs_pitch`/`abs_yaw`, after the relative looks and face have run. A pre-check before any input would fail earlier.
- `an_occluder_stops_the_click` no longer pins the last look's `dy`; pin it to `restore_pitch_counts(start, now)`.
- `zoom` with `zoom_notches` resolves silently to `zoom` (as `zoom_to` already did).
