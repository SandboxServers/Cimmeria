### Common seed and test lane

Content-chain packets own only their named new `db/resources/Content/Seed/tollana_<arc>_chains.sql` file, the corresponding `db/database.sql` include once the first chain lands, their named replay test module under `crates/cell-content/src/cell/content/chain_replay_tests/` (and its module registration), and defects proven in exact existing mission/dialog rows under `db/resources/Missions/Seed/` and `db/resources/Dialogs/Seed/`. World population packets own `db/resources/Worlds/Seed/spawnlist.sql` and, only when the sealed placement manifest calls for them, `spawn_sets.sql`, `spawn_points.sql`, `respawners.sql`, `ring_transport_regions.sql` and a specific entity-template seed. Shared seed files have **one wave writer**; later packets rebase on that integrated SHA. No packet changes Rust runtime merely to make its mission fit; a missing primitive becomes a separate architected upstream packet.

Every behavior packet adds a chain-replay or relevant unit guard that demonstrably fails when its chain/fix is removed, plus live-DB seed-join/persistence tests where DB rows are changed. **Telemetry (owner decision, 2026-10-13):** every chain, mission or encounter packet emits progress telemetry (chain fired, step advance, objective credit, refusal reason) sufficient to debug it from SigNoz alone, and its acceptance names those events. Check in order: `cargo fmt --all -- --check`; targeted `pwsh tools/build-lane/lane.ps1 cargo clippy -p cimmeria-cell-content --all-targets -- -D warnings`; targeted `pwsh tools/build-lane/lane.ps1 cargo nextest run -p cimmeria-cell-content`; `pwsh tools/build-lane/live-db-test.ps1 <test filter>` for changed seed. Add other crates only when a sealed contract explicitly changes them. The coordinator runs full local CI-equivalent checks on each integrated wave and at campaign close, per [execution contract](execution-contract.md). Every runtime packet updates `docs/content/mission-chains.md` and the `tollana-continuation/` ledger; placement and UAT packets update the ledger's placement table and `docs/guides/unified-uat.md` as the doc-update map requires. `docs/content/zone-audit.md` and the campaign status docs change only in the shared close-out FZ-99. Do not hand-edit generated blocks. Retire each packet worktree with `pwsh tools/build-lane/rm-worktree.ps1 --force <name>` once it is integrated; packet branches are never pushed, so `--merged` does not find them.
