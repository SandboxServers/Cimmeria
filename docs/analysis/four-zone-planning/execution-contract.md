# Four-zone Haiku campaign execution contract

Status: planning contract only. This document governs four future campaigns; it does not dispatch them. The owner has chosen a campaign feature branch with wave integrations, local CI-equivalent checks and review before one remote PR per complete campaign. This overrides the older `campaign-packet` skill's per-packet PR example for these campaigns. Repository merge-queue and lab-lease rules still apply.

## Budget and worker brief

- Give a fresh `packet-coder` one packet, one registered worktree, one test database and one bounded file allowlist. Target **50–60k working tokens** for the coder's implementation, test and final report. Budget **under 100k billed tokens per packet across coder, packet review and fixes**, with roughly 60k coder, 15k initial review, 15k fix/re-review and 10k reserve. The coordinator checks token-profile data after each stage and stops/re-scopes if projected to cross the cap. Three review rounds remain a quality gate; if their cost cannot fit, split the remaining correction into a new packet rather than declaring an issue resolved. Cache accounting varies, so a brief cannot itself guarantee a billing total. Never resume an expired worker to save a report; use its commit and worknote in a fresh session.
- The brief names its exact section in the zone `*-work-packets.md`, base SHA, source evidence, branch/worktree, owning files, preconditions, behavior, negative cases, test type, revert proof, lane commands, docs, commit subject and stop conditions. Copy the 5–10 relevant repo rules into the brief for a Haiku coder that omits `CLAUDE.md`; do not ask it to discover the architecture anew.
- The frozen manifest assigns **each quest beat and encounter** a provenance class from [the index](README.md): `RESTORED_SOURCE`, `CIMMERIA_RECONSTRUCTION`, or `CIMMERIA_AUTHORING`. It records the exact source file/ID/build if known, the reconstructed or invented portion, and the mission/lore advisor's approval. A historic ID with a newly invented step is mixed provenance; mark that step reconstruction or authoring explicitly. Client text and public docs must not present either as a verbatim 2009 restoration.
- The worker writes a `worknotes/<packet>.md` handoff (what changed, evidence, tests, decisions, risk, commit SHA) and returns one line. A coordinator reviews the result and tracks actual token use. A scope that needs a new primitive, client patch, map design, unreserved ID, incompatible historical revision or more than 60k working tokens is split or returned to an architect/domain advisor; Haiku does not decide that design in flight.
- Never hand a small model a research gate as if it were an implementation packet. `game-archaeology-specialist`, domain advisors, `documentation-writer` and the architect own evidence, prose and decisions. Packet-coder receives a frozen contract only after those outputs are incorporated.

## Branch and wave topology

For each zone `<zone>`, the coordinator creates a dedicated integration worktree on `content/<zone>-campaign` from current `origin/main`, after auditing current worktrees, branches, board and old ledger. Independent packet workers branch from the integration branch at a recorded SHA: `<zone>/<packet>-<slug>` in `.claude/worktrees/<zone>-<packet>`. One worker owns a file at a time. Each worker commits locally and stops; no worker pushes, opens a PR, merges into main or edits another packet's worktree. The integration coordinator merges reviewed packet commits into `content/<zone>-campaign` in dependency order and records the integrated SHA in the ledger.

`tools/build-lane/mk-worktree.ps1` always creates its new branch at `origin/main`, regardless of the campaign SHA. After creating a packet worktree, verify its branch is the requested new branch, its worktree is clean, and its HEAD equals the recorded `origin/main` SHA. Then run `git -C <packet-worktree> rebase --onto <recorded-feature-sha> origin/main <packet-branch>` on that empty branch. Verify `git -C <packet-worktree> rev-parse HEAD` equals the recorded feature SHA and `git -C <packet-worktree> merge-base HEAD <feature-branch>` equals that SHA before dispatch. Stop if any check differs; never use a destructive reset to repair an unexpected worktree. Record the SHA and command in the ledger. Repeat the base check for every later wave, since the helper never inherits the campaign tip automatically.

Packet waves are small enough for a reviewer to understand in one fresh context, generally **2–4 implementation packets**, fewer when they share seed tables or content-engine dispatch. Finish the evidence/contract wave before runtime waves. Keep one feature branch for the campaign across waves, and do not publish a remote wave PR. At every wave boundary write `RESUME.md` (at most 40 lines: base SHA, integrated packets, worktrees, current checks, next action, blockers), update the packet status table, and compact/restart agents rather than carrying a large stale context. Status vocabulary: Ready, BlockedDependency, BlockedDecision, BlockedEvidence, Writing, Review, Integrated, UATPending, Done.

## Review and local CI gate for each wave

1. Inspect each packet's commit against its contract. Confirm its revert-proof regression guard, docs and ID/coordinate ownership. Give any client-data mutation to `server-authority-enforcer`, movement to the movement advisor, mission/content to the mission advisor, item paths to the items advisor, and other domains to the relevant advisor. Reviewers are fresh and read-only.
2. Integrate the packet commits on the campaign feature branch. Reload **that worktree's** seed into its isolated `sgw_<worktree>` database using `seed-change` procedures. Run local CI-equivalent checks in order: `cargo fmt --all -- --check` (non-compiling), `pwsh tools/build-lane/lane.ps1 cargo clippy ... -- -D warnings` for changed crates, targeted nextest through the lane, full workspace nextest and live-DB tier through the lane before a wave is marked Integrated. Use the exact current pre-PR checklist and exclude syntax from `CLAUDE.md`; never call compiling cargo directly. Run seed lints, doc/Markdown checks and client override validation that the touched files require. Capture commands, exit codes, run IDs and counts in the ledger. A green packet worktree is not a substitute for the merged feature branch check.
3. Give the **whole integrated wave diff** and packet specs to a fresh read-only adversarial reviewer. Verify findings, then assign every accepted fix to a **separate fixer agent** working on the feature branch (or a fix worktree merged back before retest). The original coder does not fix review findings. Rerun affected targeted checks and the wave gate. Send the resulting full diff to a **new fresh reviewer**. Repeat for at most **three review rounds** total; stop early when a reviewer finds no actionable issues. A disputed or still-open finding after round 3 blocks the wave and goes to the architect/owner with evidence; it does not become an automatic pass. Record reviewer identity/session, reviewed SHA range, findings, fixer commit and recheck results for every round.
4. After the wave passes, mark its rows Integrated or UATPending. Never mark a player-facing story Done solely from seed tests. Client UAT requires the owner's explicit approval before any lab lease or client/server change; list approved and pending rows separately. Do not claim local CI covers client appearance or dialog/journal presentation.

## Campaign completion and remote PR

After **all planned active waves** are integrated, run the full local pre-PR suite and seed reload again on the final feature-branch tip. Have a fresh campaign-level reviewer inspect the entire diff, cross-zone handoffs, test inventory, provenance labels, doc-update map, memory and close-out rows. Apply the same fixer → fresh reviewer loop, at most three rounds, and block on unresolved issues. UAT rows that cannot run without a lab lease remain explicitly UATPending; the PR states that limitation. Update `docs/gap-analysis*` and `docs/project-status.md` once in the close-out packet, and reconcile `docs/guides/unified-uat.md`.

Only then use `tools/build-lane/ship.py pr` from the registered campaign worktree to push and open **one campaign PR** against `main`, with its attribution footer, evidence, checks and UAT limits. Attach the PR to the task. Wait for required PR checks and merge via `ship.py merge` and the merge queue; do not bypass CI or use an administrative merge. Fix any remote CI/review failures on the same feature branch, repeat local checks and fresh review of the changed range, and push again. Retire packet and integration worktrees after merge, preserve worknotes and final handoff, and mark Done only when the remote merge and required UAT state are honestly recorded.

## Cross-campaign order and ownership

Cellblock escape and Castle share one story boundary; Castle may return while Cellblock stays one-time. Harset and Tollana share mission handoffs. Freeze a single owner for each cross-zone chain and let the receiving zone test the handoff without duplicating it. The four campaigns may plan in parallel, but implementation waves that depend on another campaign's unmerged contract wait. No new authored quest is labeled as shipped 2009 content. Side stories and repeatables follow restoration UAT, use the [story source guide](story-research.md), and begin with useful supplies and modest XP/currency.

**Client mission catalog prerequisite:** current `crates/resources/src/base/resources/apply_overrides.rs::apply_mission_overrides` skips IDs absent from `CookedDataMissions.pak`; a server seed and `MissionOverride` alone cannot make a net-new quest visible. A shared Cellblock-owned infrastructure packet must insert and serialize new mission XML through the **existing ResourceCache PAK update path** (category metadata, `InvalidKeys`, `resourceFragment`) and prove the result in the client, or establish a verified reusable catalog slot. It then merges before Castle, Harset or Tollana authored-quest packets run. Until then those packets are `BlockedDependency`. Preserve existing mission overrides and resource version behavior; no zone worker invents a second distribution path.
