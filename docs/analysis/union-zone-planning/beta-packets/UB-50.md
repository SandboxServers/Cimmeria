   ```sql
   INSERT INTO content_triggers (chain_id, event_type, event_key, scope, once, sort_order) VALUES (23480, 'mission_completed', '1423', 'player', false, 0);

   INSERT INTO content_conditions (chain_id, condition_type, target_id, target_key, operator, value, sort_order) VALUES (23480, 'mission_status', 1423, NULL, 'eq', 'completed', 2);
   INSERT INTO content_actions (chain_id, action_type, target_id, target_key, params, delay_ms, sort_order) VALUES (23480, 'grant_xp', NULL, NULL, '{"amount": 300}', 0, 0);
   ```

   The shape matches offer-bind chain 23040 in `beta_e1_m381_chains.sql` (`once false`, like every Beta chain: a mission completes once, and `once` would make the replay tests stateful). If the existing seed differs from the shape above, the existing seed wins. Race gates (D-UB1): Human `gte 1` and `lte 4`, Free Jaffa `eq 7`, Asgard `eq 5`. Check the `grant_xp` param name against `crates/content-engine/src/loader/action.rs` (`amount`).
2. **Register** the `\ir` line and the `CHAIN_FILES` entry. No interact-tag linter rows (no `interact_tag` trigger).
3. **`mod.rs`.** Add `mod rewards;`. Add the arm `Action::GrantXP { amount } => format!("grant_xp({amount})"),` to `summarize`. Add `pub(super) const REWARD_CHAINS: std::ops::RangeInclusive<i64> = 23480..=23499;` and `pub(super) fn without_rewards(set: BTreeSet<i64>) -> BTreeSet<i64>` that drops ids in that range.
4. **Existing tests.** Run `live-db-test.ps1 chain_replay_tests::beta_e1`. A whole-seed test that fires `MissionCompleted` and asserts an exact `chains_matched` set may now also see a reward chain. For each failure whose only difference is a 23480-23496 id, wrap the actual set in `without_rewards(..)`. Change nothing else. Any other failure (a cross-race guard, a dialog count, a bind) is a real bug: return `blocked` and name the test.
