## Why

World 18 (`Omega_Site`) has no respawner. A player who dies on the hub therefore respawns where they fell, and `target.rs` logs that only at its fallback. In the client, Omega is a safe hub, and the gate plaza is where an arriving player stands (D-UO7). One respawner row puts every hub death back on the plaza. The Defeat Window also lists the plaza by name, so a player who dies sees a choice on their first press. This is CIMMERIA_RECONSTRUCTION: the respawner table is server data, and the client ships none for world 18.

## Contract excerpt

- Table: `respawners (respawner_id, world_id, name, pos_x, pos_y, pos_z)`, all `NOT NULL`, with no sequence. Model row: `db/resources/Worlds/Seed/respawners.sql:33`.
- Respawner 26 is world 80's, 3.9 m east of pad 17 (`respawners.sql:202-207`). Do not touch it.
- Resolution (`crates/cell-interactions/src/cell/respawn/target.rs:73-180`): a death that names no respawner takes the nearest valid one in the same world. The search is `cimmeria_cell_catalog::cell::respawner_fallback::nearest_valid_respawner_def(respawners, world_name, near, navmesh, bounds)` (`respawner_fallback.rs:79`). With no row in the world, the player respawns in place.
- Loader: `cimmeria_cell_catalog::cell::spawner::load_respawners(&pool)`. It returns `RespawnerDef { respawner_id, world_name, name, pos: [f32; 3] }`, joined to `worlds.world`, so world 18 reads `"Omega_Site"`.
- `NavMesh` is `cimmeria_entity::navigation::NavMesh`. `SpaceBounds::FALLBACK` comes from `cimmeria_entity::movement_validation::SpaceBounds`, and `Vector3` from `cimmeria_common::Vector3`.
- UO-02's `spawner_tests/union_omega/mod.rs` gives you `mesh`, `vector`, `standable_and_connected(mesh, point, anchor, label)`, `HUB_MESH` and `MODI`.

2. **Test.** Replace `hub.rs` with:

   ```rust
   //! UO-03: Omega's hub respawner 180 (`Omega Site Gate Plaza`).
   //!
   //! A death anywhere on the gate plaza resolves to respawner 180, which
   //! stands on the hub mesh, connected to Modi. Before UO-03, world 18 had
   //! no respawner, and a hub death respawned in place.

   use cimmeria_cell_catalog::cell::respawner_fallback::nearest_valid_respawner_def;
   use cimmeria_cell_catalog::cell::spawner::load_respawners;
   use cimmeria_entity::movement_validation::SpaceBounds;

   use super::{mesh, standable_and_connected, vector, HUB_MESH, MODI};
   use crate::test_support::require_db_or_skip;

   const RESPAWNER_HUB: i32 = 180;
   /// UO-01 worknote, § C4: where SGC's US-32 lands a player.
   const ARRIVAL: [f32; 3] = [/* worknote C4 x, y, z */];

   #[tokio::test]
   async fn live_db_a_hub_death_resolves_to_the_gate_plaza_respawner() {
       let pool = require_db_or_skip!();
       let respawners = load_respawners(&pool).await.expect("load_respawners");
       let row = respawners
           .iter()
           .find(|r| r.respawner_id == RESPAWNER_HUB)
           .expect("respawner 180 must be seeded");
       assert_eq!(row.world_name, "Omega_Site");
       assert_eq!(row.name, "Omega Site Gate Plaza");
       let hub = mesh(HUB_MESH);
       standable_and_connected(&hub, row.pos, MODI, "respawner 180");
       for (label, death) in [("Modi", MODI), ("the C4 arrival point", ARRIVAL)] {
           let chosen = nearest_valid_respawner_def(
               &respawners,
               "Omega_Site",
               vector(death),
               Some(&hub),
               &SpaceBounds::FALLBACK,
           )
           .unwrap_or_else(|| panic!("a death at {label} found no respawner"));
           assert_eq!(chosen.respawner_id, RESPAWNER_HUB, "a death at {label}");
       }
       let dx = row.pos[0] - ARRIVAL[0];
       let dz = row.pos[2] - ARRIVAL[2];
       assert!(
           (dx * dx + dz * dz).sqrt() >= 3.0,
           "respawner 180 must stand at least 3 m from the arrival point"
       );
   }
   ```

   Fill `ARRIVAL` from the worknote. The `vector` in the parent module is private, but a child module may use it.
