# LR-07 worknote: the record tools

> Type: worknote. Packet: [LR-07](../work-packets-2.md#lr-07-mcp-tools).
> Decisions: D-LR1, D-LR2, D-LR16; findings F12, F13. Offline only: fakes,
> no lab, no running client.

## What was built

`crates/lab/src/server/record/` (a directory: five files would not fit the
500-line cap as two):

| File | Holds |
|---|---|
| `mod.rs` | The `record_router` with the three tools and their argument types. |
| `run.rs` | `start` and the sampler task, `Failure` (D-LR16's failure body), `max_minutes_of`. |
| `stop.rs` | `status`, `stop`, `draft_outcome`. |
| `fakes.rs`, `tests.rs` | A scripted server, a client probe that checks the lease permit, and the tests. |

- **Start** refuses, in this order and before any server call: `max_minutes`
  0, an empty section, a bad character name, a bad instance name, a busy
  slot, a held lab. It then takes its own lease (`RunLease::acquire_own_as`,
  owner `lab_record`, purpose `recording a human: <section>`), spawns the
  task, waits for its start line and tick 0 to be on disk, and arms the slot.
  The recording folder is created with `create_dir`, so a second recording
  never writes over a first's log.
- **The task** builds its `TapStopGuard` before `Sampler::begin` and runs
  inside `permit::scope` for its lease. Each tick it stops on: the stop
  signal, the keep-alive's revocation, a failed `touch` of the lease
  (`lease_lost`), host time past `max_minutes` (`max_minutes`), a failed log
  write (`write_failed`) or `Sampler::full()` (`max_minutes`, `size_cap`).
  `finish` writes the last tick and the stop line; the lease is released
  when the task ends.
- **Status** is open and routes like every tool (F12). `recording` is false
  once the task has ended by itself and waits for a stop to collect it.
- **Stop** is open and gated by the recording id (`RecordSlot::take_if`): a
  wrong id is refused with exit 2 and the recording keeps running. It
  signals, awaits the task, reads the log, transforms it with `base` = the
  named section's meta when `load_sections(specs_dir)` holds it, and writes
  `<specs_dir>/drafts/<file_name>` with `create_new`, so an existing draft is
  never overwritten. A failed transform keeps the raw log, writes its whole
  error to `transform-error.txt` beside it, and answers
  `{"ok":false,"exit":1,"error":"transform: ...; raw log kept in <dir>"}`.
- Answers are one compact JSON object under 400 characters. A refusal or
  failure is `{ok:false, exit, error}` returned as a tool error
  (`isError: true`); exit 2 means nothing changed, exit 1 that something
  failed. `Failure::body` cuts the error to fit, measured on the serialized
  text (JSON doubles a Windows path's backslashes).

## The four items carried from LR-06

1. **Done: the sampler runs inside a `Permit::Lease` scope.** A forced
   takeover makes the client probe's bridge calls fail ("lease revoked") and
   stops the recording with `lease_lost`; the taker's lease is untouched.
2. **Done: wall-clock limit.** `max_minutes`, default 30 and capped at 30,
   checked on the host clock every tick beside `max_ticks` (which is set to
   the same minutes in ticks). The stop reason is `max_minutes`.
3. **Done, small: the camera pair is cached.** `RecordSlot` keeps the
   `PlayerCamera` the last good `camera_read` resolved; the next read seeds
   `LiveWorld` with it (`LiveWorld::with_camera`), which re-checks both
   vtables before use, and a failed read drops it. The ASLR slide is not
   cached: a client restart changes it, and `module_info` is one cheap call
   a tick. No test drives this (it needs the bridge); it is LR-13's to see.
4. **Done: `named_target` reads through `decode::decode_call`**, and
   `segment::count_anchors` counts anchors with `decode_call` too (interact,
   useItem, moveItem, useAbility; a region is not counted live, because it
   anchors only when a later snapshot changes). The hand-rolled offset
   decoding is gone. The budget tests' `setTargetID` fixture used base
   `msg_id` 200 with no `method_index`, which `decode_call` rightly reads as
   no cell call; it now carries `msg_id` 0x80 and `method_index` 0.

## Deviations from the spec, with reasons

- **Files.** `server/record/` is a directory of five files, not
  `server/record.rs` plus one test file: start, the task and stop together
  came to 500 lines, and the fakes pushed the tests past 600. `RecordHandle`
  gains `specs_dir` (start's argument, which stop needs); `RecordSlot` gains
  `take_if` (the stop's id gate, atomic) and the camera cache.
- **`acquire_own_as` already existed** in `lease/run.rs` (merged with
  SV-10's `lab_uat_calibrate`). This packet adds `RECORD_OWNER` and the unit
  test `an_own_lease_as_reports_its_owner`.
- **`lab_record_start` takes no `lease_id`.** It is `OWN_LEASE` in the policy
  (as the spec says) but always takes its own lease, since D-LR2 names the
  owner; a caller holding the lab is refused and must release first.
- **Status adds `recording_id`** beside D-LR16's fields, so a caller that
  lost the start's answer can still stop the recording.
- **Stop with `no_draft`** answers `{ok, recording_id, ticks, raw}`.
- **Dead-code allows.** Removed: `uat/record/mod.rs` (and its unused
  `pub use log::*`, which nothing read), `record_slot.rs`, the
  `TapStopGuard` re-export, `camera_read.rs` and the `Supervisor.record`
  field. What that exposed, all used only by tests: `RecordSlot::take` and
  `Sampler::player_entity` are now `#[cfg(test)]`; `INV_MISSION` and
  `Inline::Array` keep an item-level `cfg_attr(not(test), allow(dead_code))`
  with the reason. The allows on `TransformOptions.profile`, `max_actions`
  and `max_bytes` stay for LR-09 and LR-15.

## Tests

`server/record/tests.rs`, each checked to fail with its rule reverted (the
first three by mutation: no `permit::scope`, no host-time check, counting by
`msg_name`):

- `a_takeover_stops_the_recording_with_lease_lost`
- `max_minutes_stops_on_host_time`, `max_minutes_defaults_to_and_is_capped_at_30`
- `status_counts_anchors_with_decode_call`
- `start_refuses_a_second_recording_on_the_instance`,
  `start_is_refused_while_the_lab_is_leased`
- `stop_with_a_wrong_id_is_refused_and_keeps_recording`
- `stop_writes_the_draft_and_releases_the_lease` (also the under-400 output
  budget for a typical stop, with realistic path depth)
- `stop_never_overwrites_a_draft`
- `a_failed_transform_keeps_the_raw_log_and_answers_the_failure_shape`,
  `a_short_failure_is_not_cut`
- `status_and_stop_route_by_instance` (over the daemon's HTTP transport,
  two hosted instances)

Elsewhere: `lease/policy.rs`
`record_start_takes_its_own_lease_and_stop_is_open`; `lease/run.rs`
`an_own_lease_as_reports_its_owner`; `supervisor/record_slot.rs`
`only_the_running_id_empties_the_slot`.

## Left over

- The camera cache and the lease scope over the real supervisor's bridge
  calls are seen live only in LR-13.
- `lab_timeline` on a recording instance still drains the recorder's tap
  (D-LR2 says not to call it; nothing enforces it). A refusal there would be
  a small follow-up if LR-13 shows it matters.
- LR-08's CLI should treat a tool error whose text parses as
  `{ok:false, exit, error}` as the D-LR16 failure and print it as is.

## Tool rows for LR-12

| Tool | Purpose |
|---|---|
| `lab_record_start` | Record a person playing this instance by hand: every 500 ms read the player's tap, server entity, camera readout, windows, dialog and (after server activity) a DB snapshot into `<uat root>/records/<recording_id>/record.jsonl`. Takes its own lease (owner `lab_record`) until the stop; stops by itself after `max_minutes` (default and at most 30) or on `lease_lost`. `{section, character?, specs_dir?, max_minutes?}` → `{ok, recording_id, instance, section, dir}`. Open. |
