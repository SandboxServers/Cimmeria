> Type: worknote. Packet: [LR-07](../work-packets-2.md#lr-07-mcp-tools).
> Decisions: D-LR1, D-LR2, D-LR16; findings F12, F13. Offline only: fakes,

## What was built

`crates/lab/src/server/record/` (a directory: seven files would not fit the
500-line cap as two):

| File | Holds |
|---|---|
| `mod.rs` | The `record_router` with the three tools and their argument types. |
| `checks.rs` | The argument checks: `section`, `specs_dir`, `character_expr`. |
| `run.rs` | `start` and the sampler task, `Failure` (D-LR16's failure body), `max_minutes_of`, `claim_dir`. |
| `stop.rs` | `status`, `stop`, `draft_outcome`. |
| `fakes.rs`, `tests.rs`, `stop_tests.rs` | A scripted server, a client probe that checks the lease permit, and the tests. |

- **Start** refuses, in this order and before any server call: `max_minutes`
  0, a section that is not `^[a-z0-9][a-z0-9-]{0,47}$`, a `specs_dir` that
  is a UNC or `\\?\` path or not an existing directory (it is canonicalized
  here, so a bad one fails at start, not at stop), a bad character name, a
  bad instance name, a busy slot, a held lab. It then takes its own lease
  (`RunLease::acquire_own_as`, owner `lab_record`, purpose `recording a
  human: <section>`), spawns the task, waits for its start line and tick 0
  to be on disk, and arms the slot. The task claims the recording folder
  with `create_dir` before `Sampler::begin`; a taken `<id>` becomes
  `<id>-2`, `<id>-3`, ... (the suffix after the instance, so LR-05's
  `draft_file_name` still reads the time stamp), and a failed begin removes
  the empty folder. Start and stop are traced (`lab.record`, info), and a
  failed start warns.
- **The task** builds its `TapStopGuard` before `Sampler::begin` and runs
  inside `permit::scope` for its lease. Each tick it stops on: the stop
  signal, the keep-alive's revocation, a failed `touch` of the lease
  (`lease_lost`), host time past `max_minutes` (`max_minutes`), a failed log
  write (`write_failed`) or `Sampler::full()` (`max_minutes`, `size_cap`).
  `finish` writes the last tick and the stop line; the lease is released
  when the task ends.
- **Status** is open and routes like every tool (F12). `recording` is false
  once the task has ended by itself and waits for a stop to collect it.
- **Stop** is open and gated by the recording id. A `character_expr` that
  is not `^[A-Za-z0-9 _${}]{1,64}$` is refused first. A wrong id is refused
  with exit 2 ("that recording_id is not the running recording on instance
  p2"; with nothing armed, "no recording on instance p2; pass `instance` to
  pick another"), never naming the live id, and the recording keeps
  running. Otherwise it signals the task under the slot's lock
  (`RecordSlot::signal_stop`), waits at most 60 s with the recording still
  in the slot, and takes it out (`take_ended`) only once the task has ended.
  It then reads the log, transforms it with `base` = the named section's
  meta when `load_sections(specs_dir)` holds it, and writes
  `<specs_dir>/drafts/<file_name>` with `create_new`, so an existing draft
  is never overwritten; a write that fails part-way removes the file. On a
  timeout, or any failure before the draft is written (log read, transform,
  draft write), the recording stays in the slot (`RecordSlot::restore`;
  ended, not running) and answers exit 1, so a second stop, perhaps with
  another `character_expr`, retries. `RecordHandle.ended` keeps the task's
  result, since a `JoinHandle` gives it once. A failed transform also
  writes its whole error to `transform-error.txt` beside the log and
  answers `<raw dir>; see transform-error.txt; transform: <error>`.
- **The stop gate guards against accidents only** (a stale id, the wrong
  instance). It is not authorization: `lab_record_status` returns the
  `recording_id` to anyone, and this is a single-operator lab.
- Answers are one compact JSON object under 400 characters with legal
  inputs, at worst a 48-character section, a 16-character instance and deep
  folders. So no answer carries a path: start returns no `dir` (the folder
  is `<uat root>/records/<recording_id>/`), stop's `draft` is the file name
  and `raw` the recording id. When the task ended with an error
  (`write_failed`, a panic), the stop answer adds `ended`, cut to 80
  characters. A refusal or failure is `{ok:false, exit, error}` returned as
  a tool error (`isError: true`); exit 2 means nothing changed, exit 1 that
  something failed. A failure names the raw folder first and in full;
  `Failure::body` cuts only the error after it to fit, measured on the
  serialized text (JSON doubles a Windows path's backslashes).

## The four items carried from LR-06

1. **Done: the sampler runs inside a `Permit::Lease` scope.** A forced
   takeover makes the client probe's reads fail ("lease revoked") and stops
   the recording with `lease_lost`; the taker's lease is untouched. The
   supervisor's `ui` and `pump` reads go through `bridge_call`, which checks
   the permit; `camera_read`'s memory reads go straight to the bridge, so it
   calls `permit::ensure` itself first. `real_client_reads_check_the_permit`
   runs all three on a real `Supervisor` under a taken-over lease.
2. **Done: wall-clock limit.** `max_minutes`, default 30 and capped at 30,
   checked on the host clock every tick beside `max_ticks` (which is set to
   the same minutes in ticks). The stop reason is `max_minutes`.
3. **Done, small: the camera pair is cached.** `RecordSlot` keeps the
   `PlayerCamera` the last good `camera_read` resolved; the next read seeds
   `LiveWorld` with it (`LiveWorld::with_camera`), and
   `camera_read::resolve_player_camera` reuses it only while both vtables
   match and the controller's `+0x2b0` still points at that camera (a
   camera freed and replaced at the same address keeps its vtable);
   otherwise it rescans. A failed read drops it. The ASLR slide is not
   cached: a client restart changes it, and `module_info` is one cheap call
   a tick. `a_cached_camera_is_reused_until_the_controller_points_elsewhere`
   drives the reuse and the rescan over a fake `Memory`; the live read is
   LR-13's to see.
4. **Done: `named_target` reads through `decode::decode_call`**, and
   `segment::count_anchors` counts anchors with `decode_call` too (interact,
   useItem, moveItem, useAbility; a region is not counted live, because it
   anchors only when a later snapshot changes). The hand-rolled offset
   decoding is gone. The budget tests' `setTargetID` fixture used base
   `msg_id` 200 with no `method_index`, which `decode_call` rightly reads as
   no cell call; it now carries `msg_id` 0x80 and `method_index` 0.

## Deviations from the spec, with reasons

- **Files.** `server/record/` is a directory of five files, not
  `server/record.rs` plus one test file: start, the task and stop together
  came to 500 lines, and the fakes pushed the tests past 600. `RecordHandle`
  gains `specs_dir` (start's argument, which stop needs) and `ended`;
  `RecordSlot` gains the stop's gate (`signal_stop`, `ended`, `take_ended`,
  `restore`) and the camera cache.
- **`acquire_own_as` already existed** in `lease/run.rs` (merged with
  SV-10's `lab_uat_calibrate`). This packet adds `RECORD_OWNER` and the unit
  test `an_own_lease_as_reports_its_owner`.
- **`lab_record_start` takes no `lease_id`.** It is `OWN_LEASE` in the policy
  (as the spec says) but always takes its own lease, since D-LR2 names the
  owner; a caller holding the lab is refused and must release first.
- **Status adds `recording_id`** beside D-LR16's fields, so a caller that
  lost the start's answer can still stop the recording.
- **Stop with `no_draft`** answers `{ok, recording_id, ticks, raw}` (`raw`
  is the recording id here too).
- **Dead-code allows.** Removed: `uat/record/mod.rs` (and its unused
  `pub use log::*`, which nothing read), `record_slot.rs`, the
  `TapStopGuard` re-export, `camera_read.rs` and the `Supervisor.record`
  field. What that exposed, all used only by tests: `RecordSlot::take` and
  `Sampler::player_entity` are now `#[cfg(test)]`; `INV_MISSION` and
  `Inline::Array` keep an item-level `cfg_attr(not(test), allow(dead_code))`
  with the reason. The allows on `TransformOptions.profile`, `max_actions`
  and `max_bytes` stay for LR-09 and LR-15.

## Left over

- The camera cache and the lease scope over the real supervisor's bridge
  calls are seen live only in LR-13.
- `lab_timeline` on a recording instance still drains the recorder's tap
  (D-LR2 says not to call it; nothing enforces it). A refusal there would be
  a small follow-up if LR-13 shows it matters.
- The same `specs_dir` check (local, existing, canonicalized, no UNC or
  `\\?\`) belongs on `lab_golden_record`, `lab_uat_run` and
  `lab_uat_calibrate`.
- A random stop token in place of the recording id would make the stop
  gate harder to hit by accident; it is not needed while the gate guards
  accidents only.
- LR-08's CLI should treat a tool error whose text parses as
  `{ok:false, exit, error}` as the D-LR16 failure and print it as is. Its
  answers carry no paths: the draft is `<specs_dir>/drafts/<draft>` and the
  raw log `<uat root>/records/<raw>/record.jsonl`, so the CLI joins them if
  it prints paths. On exit 1 from a stop, the recording is still there:
  the CLI can offer the retry.

## Tool rows for LR-12

For the `| Tool | Purpose |` table in `docs/guides/live-research-lab.md`:

| Tool | Purpose |
|---|---|
| `lab_record_start` | Record a person playing this instance by hand: every 500 ms read the player's tap, server entity, camera readout, windows, dialog and (after server activity) a DB snapshot into `<uat root>/records/<recording_id>/record.jsonl`. Only reads. Takes its own lease (owner `lab_record`) until the stop; stops by itself after `max_minutes` (default and at most 30) or on `lease_lost`. `{section, character?, specs_dir?, max_minutes?}` → `{ok, recording_id, instance, section}`. No lease argument. |
| `lab_record_status` | This instance's recording: `{ok, recording, recording_id, instance, section, age_s, ticks, anchors}`. Open. |
| `lab_record_stop` | Stop the recording named by `recording_id` (a wrong id is refused and it keeps running), transform the log, and write `<specs_dir>/drafts/<section>-<yyyyMMdd-HHmm>.toml`, never over an existing file. `{recording_id, character_expr?, profile?, no_draft?}` → `{ok, draft, rows, steps, todo, dropped, raw, ended?}` (`draft` a file name, `raw` the recording id); a failure is `{ok:false, exit, error}`, keeps the raw log and leaves the recording for a retry. Open. |

Also for LR-12: `lab_record_start` is the third `OWN_LEASE` tool in the
lease section's list, and `lab_record_status` / `lab_record_stop` join the
open tools.
