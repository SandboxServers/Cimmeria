- **`lab_record_transform { dir, section?, character_expr?, profile?, specs_dir? }`**
  is open: it reads a folder on disk and touches no client. It checks
  `section`, `character_expr` and `specs_dir` with LR-07's `checks.rs`
  first, then finds the folder: `dir` is a recording id (read under the
  records root) or a path; `..`, UNC and `\\?\` are refused before anything
  is touched, then the path is canonicalized and must be a direct child of
  the canonical `<default_root()>\records\`. It reads the log with the
  stop's `read_raw`; a given `section` replaces the recorded one (it names
  the draft and picks the base section); then the stop's `write_draft`
  transforms it and writes `<specs>/drafts/<name>` with `create_new`. The
  answer is the stop's: `{ok, draft, rows, steps, todo, dropped, raw}`, or
  `{ok:false, exit, error}` as a tool error. The work runs on
  `spawn_blocking`.
- **`lab record`** dot-sources `common.ps1`, `uat-lib.ps1` (MCP helpers,
  `Hide-LeaseIds`, `Get-UatRoot`, `Get-DefaultSpecsDir`) and
  `record-lib.ps1`. All logic is `Invoke-RecordAction` in the library, which
  takes the tool call and the daemon probe as scriptblocks; `record.ps1`
  passes `New-McpSession` / `Invoke-McpTool` / `Close-McpSession` and
  `Get-LabStatus`, and prints. Arguments are checked before the daemon is
  asked (exit 2 whatever its state).
- **State file** `%LOCALAPPDATA%\cimmeria-lab\record-<instance>.json`
  (`Get-LabHome`, so the tests' `CIMMERIA_LAB_HOME` moves it), holding
  `{recording_id, instance}`. The instance is checked against
  `^[A-Za-z0-9_-]{1,32}$` before any path is built, both `-Instance` and
  the instance start's answer names (an unrouted start saves under the
  answer's instance, normally `default`). Stop reads it, deletes it only on
  success, and keeps it on any failure: on exit 1 the recording is still on
  the daemon (LR-07), and the text offers the retry.
- **Exit codes**: 0 ok; 1 the tool failed; 2 usage, or a tool refusal with
  nothing changed; 3 the daemon is not answering (the probe, or a call that
  throws anything but a tool error); 4 the instance is busy. A tool error
  whose text is D-LR16's shape is printed as it came back; when its exit is
  2 and the error says `leased`, `already running`, `is starting`, `still
  finishing` or `busy`, it becomes 4 in both the exit code and the printed
  body. A tool error that is not the shape is exit 1 (4 when it says
  leased). Transform without the daemon prints "the transform runs in the
  lab daemon; start it with `lab start`".
- **Output**: `-Json` prints one compact line, the tool's answer or the
  failure, nulls and empty strings dropped, a failure's error cut until the
  line is under 400 characters. Without `-Json`, one line to stdout on
  success (start says how to stop; stop and transform join the names in
  the answer into the draft's and raw log's paths), the error to stderr on
  failure. Every printed string goes through `Hide-LeaseIds`.

## Deviations from the spec, with reasons

- **`lab_record_transform` takes an optional `specs_dir`**, checked like
  start's. An installed daemon runs with the lab home as its working
  directory, so its own `specs_dir()` can find no spec folder, and the
  transform would then fail with "no spec directory for the draft". Without
  it, the daemon's default is used as the spec says.
- **`dir` may be a bare recording id**, and must be a *direct* child of the
  records root (recording folders are; "under" would also admit deeper
  folders nothing writes).
- **The tool code is `server/record/transform.rs`**, not `server/record.rs`:
  LR-07 made `record` a directory.
- **CLI extras**: `-SpecsDir` on start and transform (default the
  checkout's `docs\guides\uat-specs`, as `lab uat` passes it, for the same
  installed-daemon reason); `-RecordingId` on stop, to stop a recording
  whose state file is gone (`lab record status` shows the id); `-Section` on
  transform as the spec lists. `transform` refuses `-Instance` (it is not
  routed).
- **A busy refusal's printed body says exit 4**, so the JSON and the
  process exit agree; every other failure body is printed unchanged.
- **Busy is matched on the refusal text**: the tools have one refusal code
  (2), so the CLI tells busy apart by the words of the slot and lease
  refusals. A reworded refusal falls back to 2.

## Left over

- `lab_record_transform` does not refuse the folder of a recording still
  running; its log has no stop line yet, so the read or transform fails
  with exit 1 and nothing is written.
- Busy detection by text (above) would be sturdier as a refusal code from
  the tools (exit 4 in the body); that is a D-LR16 change.
