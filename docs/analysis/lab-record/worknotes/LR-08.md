- **`lab_record_transform { dir, section?, character_expr?, profile?, specs_dir? }`**
  is open: it reads a folder on disk and touches no client. It checks
  `section`, `character_expr` and `specs_dir` with LR-07's `checks.rs`
  first, then finds the folder: `dir` is a recording id (read under the
  records root) or a path; `..`, UNC and `\\?\` are refused before anything
  is touched, then the path is canonicalized and must be a direct child of
  the canonical `<default_root()>\records\`. It reads the log with the
  stop's `read_raw` and refuses (exit 1, nothing written) a log without
  its stop line: "recording has no stop line; stop it first". A given
  `section` replaces the recorded one (it names the draft and picks the
  base section); then the stop's `write_draft` transforms it and writes
  `<specs>/drafts/<name>` with `create_new`. With `suffix_on_exists` set
  (the transform only) an existing name moves on to `<name>-2.toml`,
  `-3`, ... up to `-99`, each opened with `create_new`; the stop keeps the
  plain refusal. The answer is the stop's: `{ok, draft, rows, steps, todo,
  dropped, raw}`, or `{ok:false, exit, error}` as a tool error. The work
  runs on `spawn_blocking`; a panic there is logged at `warn` on
  `lab.record`.
- **`lab record`** dot-sources `common.ps1`, `uat-lib.ps1` (MCP helpers,
  `Hide-LeaseIds`, `Get-UatRoot`, `Get-DefaultSpecsDir`) and
  `record-lib.ps1`. All logic is `Invoke-RecordAction` in the library, which
  takes the tool call and the daemon probe as scriptblocks; `record.ps1`
  passes `New-McpSession` / `Invoke-McpTool` / `Close-McpSession` and
  `Get-LabStatus`, and prints. Arguments are checked before the daemon is
  asked (exit 2 whatever its state).
- **State file** `%LOCALAPPDATA%\cimmeria-lab\record-<instance>.json`
  (`Get-LabHome`, so the tests' `CIMMERIA_LAB_HOME` moves it), holding
  `{recording_id, instance, specs_dir?}`; `instance` and `specs_dir` are
  read with `Get-RecordField`, so a file without them still works under
  StrictMode. `specs_dir` is the folder the start sent (the daemon fixes
  the draft's folder at start); the stop prints the draft's path from it,
  or `<specs>/drafts/<name>` literally when it is unknown (no state file,
  or a start that sent none). A start whose state file cannot be written
  exits 1 with an error naming the recording id and
  `lab record stop [-Instance <i>] -RecordingId <id>`. The instance is checked against
  `^[A-Za-z0-9_-]{1,32}$` before any path is built, both `-Instance` and
  the instance start's answer names (an unrouted start saves under the
  answer's instance, normally `default`). Stop reads it, deletes it only on
  success, and keeps it on any failure: on exit 1 or 3 the recording is
  still on the daemon (LR-07), and the text offers the retry.
- **Exit codes**: 0 ok; 1 the tool failed; 2 usage, or a tool refusal with
  nothing changed; 3 the daemon is not answering (the probe, or a call that
  throws anything but a tool error); 4 the instance is busy. A tool error
  whose text is D-LR16's shape is printed as it came back and its exit is
  the command's, straight through: the tools answer 4 themselves (review
  fix, below). A tool error that is not the shape is exit 1. Transform
  without the daemon prints "the transform runs in the lab daemon; start it
  with `lab start`". `-MaxMinutes` is taken as a string and checked by
  `Test-RecordArguments`, so `-MaxMinutes abc` exits 2 with one JSON line
  under `-Json`. Any unexpected exception in `record.ps1` is caught: exit 1,
  and under `-Json` one `{ok:false,exit:1,error}` line. An unknown switch
  still fails at parameter binding, before the script runs, with
  PowerShell's own message and exit code; that is accepted.
- **Busy (exit 4) from the tools** (review fix): `run.rs` has `busy(...)`
  beside `refused`, used where the instance is busy: `slot.reserve`
  refused (already recording, or a start under way), the recorder's own
  lease refused because the lab is leased, the stop's `take_ended` (the
  recording still finishing), and the `arm` race. **This amends D-LR16's
  exit list for the ledger: 4 = busy (the instance or the lab), nothing
  changed.** LR-07's `start_refuses_a_second_recording_on_the_instance` and
  `start_is_refused_while_the_lab_is_leased` now assert 4.
- **Output**: `-Json` prints one compact line, the tool's answer or the
  failure, nulls and empty strings dropped, a failure's error cut until the
  line is under 400 characters. Without `-Json`, one line to stdout on
  success (start says how to stop; stop and transform join the names in
  the answer into the draft's and raw log's paths), the error to stderr on
  failure. Every printed string goes through `Hide-LeaseIds`, the `-Json`
  success line included.

## Deviations from the spec, with reasons

- **`lab_record_transform` takes an optional `specs_dir`**, checked like
  start's. An installed daemon runs with the lab home as its working
  directory, so its own `specs_dir()` can find no spec folder, and the
  transform would then fail with "no spec directory for the draft". Without
  it, the daemon's default is used as the spec says.
- **`dir` may be a bare recording id**, and must be a *direct* child of the
  records root (recording folders are; "under" would also admit deeper
  folders nothing writes).
- **The tool code is `server/record/transform.rs`**, not `server/record.rs`:
  LR-07 made `record` a directory.
- **CLI extras**: `-SpecsDir` on start and transform (default the
  checkout's `docs\guides\uat-specs`, as `lab uat` passes it, for the same
  installed-daemon reason); `-RecordingId` on stop, to stop a recording
  whose state file is gone (`lab record status` shows the id); `-Section` on
  transform as the spec lists. `transform` refuses `-Instance` (it is not
  routed).
- **Busy is exit 4 in the tool's own answer** (D-LR16 amended, above);
  the first version matched busy on the refusal text in the CLI, which the
  review replaced.
- **A re-transform is suffixed, not refused**: the spec's "never over an
  existing file" holds, and a second transform of one recording (another
  `-CharacterExpr`, say) gets `-2`, `-3`, ...

| Command | What it does | Exit codes |
|---|---|---|
| `lab record start <section> [-Instance p2] [-Character <name>] [-MaxMinutes 30] [-SpecsDir <dir>] [-Json]` | starts recording a person playing the instance by hand (`lab_record_start`); saves the recording id to `%LOCALAPPDATA%\cimmeria-lab\record-<instance>.json` | 0; 1 the tool failed; 2 usage or refused; 3 no daemon; 4 the instance is leased or already recording |

| `lab record transform <recording id or folder> [-Section <id>] [-CharacterExpr ...] [-Profile ...] [-SpecsDir <dir>] [-Json]` | drafts a stopped recording already on disk again (`lab_record_transform`), as `<name>-2.toml`, `-3`, ... when the draft exists; needs the daemon, no lease, no client | 0; 1 (also: no stop line yet); 2; 3 the daemon is not running ("start it with `lab start`") |

For the `| Tool | Purpose |` table:

| Tool | Purpose |
|---|---|
| `lab_record_transform` | Transform a recording already on disk into a draft again, with other options: `{dir, section?, character_expr?, profile?, specs_dir?}`. `dir` is the recording id or its folder, a direct child of `<uat root>/records/`; anything else (another path, `..`, UNC, `\\?\`, a link out of the folder) is refused, and so is a recording without its stop line. Writes `<specs_dir>/drafts/<section>-<yyyyMMdd-HHmm>.toml`, or `-2`, `-3`, ... when that exists, never over an existing file, and answers like `lab_record_stop`. Open: no client, no lease. |

Also for LR-12: `lab_record_transform` joins the open tools in the lease
section's list.

Also for LR-12 (security note): the open `lab_record_transform` can write a
`.toml` into any existing local `specs_dir` (under its `drafts/`), the same
as `lab_record_start` can name one; both check `specs_dir` with
`check_specs_dir` (local, existing, no UNC or verbatim), but neither limits
it to the checkout.

Also for LR-12 (D-LR16 amendment): exit 4 is "busy" in the tools' own
answers (an instance recording, starting or finishing; the lab leased), not
only in the CLI.
