## Design choices

1. **The signature is granted in the crate chain, with the gear.** The crate
   is this zone's class-identity milestone (OD-CS06), the ability is usable at
   once in the barracks fight of step 2355, and the step gate (2354 active)
   already makes the chain fire once per character. Granting on mission
   completion (chain 1103) would have needed five more gated chains on a
   three-trigger completion chain for no gain. The grant is the last action, so
   a refused loot window or grant never blocks the step advance.
2. **In-chain order on 1005 is clear bit, pistol, step, abilities, tutorial.**
   The review rule says new actions take a `sort_order` past the highest
   existing one, so the two new rows follow `advance_step`. What the
   [vocabulary](../../../content/content-engine-vocabulary.md#show_tutorial-params)
   asks for (pistol before abilities before tutorial) holds.
3. **Splits partition every archetype value.** Chain conditions only AND, so
   "Humans and Loyalist Jaffa" is written as "not 5, 6 or 7" on 1005 against
   "5 to 7" on 1010; the crate is one `eq` chain per class against a fallback
   with five `neq`s. No value falls between chains: mission 622 cannot lose
   its pistol and the crate cannot go dead. A missing archetype (-1) takes
   1005 and, at the crate, 1195.
4. **Every grant row names its archetypes**, the tutorial grant included
   (`[1, 2, 3, 4, 8]`). The cell and the base both check the player's real
   archetype, so a trigger that lost its `archetype` param cannot teach a
   Goa'uld the core abilities. `show_tutorial` has no such gate; only the
   chain condition keeps 5882 from a Goa'uld.
5. **The holding state is its own pair of chains** (1010, 1195), labelled
   `NON_CANONICAL_BLOCKED_LEGACY` in the seed, so it can be removed or
   narrowed without touching the class chains. 1010 covers Asgard and Shol'va
   as well as Goa'uld: neither has a Cellblock start profile, and "Humans and
   Loyalist Jaffa only" is the scope. 1195 must stay as the crate's fallback
   after Egypt is playable.
6. **Per-class dialogs.** The class chains show 2517 (Soldier), 4408
   (Scientist) and 4409 (Archaeologist): cooked, button-less rows of the same
   crate topic whose text names exactly the ledger's items. 3942 would tell a
   Soldier he found a stealth suit. This is our authoring; see open question 1.
7. **Chain ids.** 1010 was the last free id of the mission 622 range.
   1192-1195 come from the 1191-1199 block the Cellblock rebuild reserved for
   GC2, the per-class rewards gate that OD-CS02 reopens.
8. **Table 10 is shared** by the Commando chain and the holding chain rather
   than copied, because OD-CS08 says the holding state keeps "the Human M687 /
   loot-table-10 reward".

## Open questions

1. **Per-class crate dialogs.** The ledger names items and abilities but no
   dialog. I wired 2517, 4408 and 4409 because their text matches the items
   exactly. If the owner wants 3942 for every Human instead, change three
   `display_dialog` rows and the three ids in `CLASS_REWARDS`.
2. **Loyalist Jaffa armor.** The Gear matrix says 4342 Standard Chestplate, so
   table 11 no longer gives the Armored Prison Jacket (3482) that the legacy
   script granted. 4342 has the missing-icon image. Confirm the swap is wanted
   rather than an addition.
3. **Soldier signature and weapon.** 598 Quick Burst needs an automatic weapon
   and the crate gives the Soldier an LMG, which does not qualify (ledger,
   preflight). Until CS-07 the server lets it fire with anything. The ledger
   already accepts this; it will read oddly in UAT.
4. **Asgard and Shol'va in the Cellblock** take the holding chains (pistol
   only; the Commando crate set; no grants). Neither can start here, so this
   only matters for a GM-moved character.
5. **OD-CS13 is still "pending lomiada's acknowledgement"** in the ledger.
   Nothing here loads a clip, so nothing changes if it is reversed except the
   `charges` assertion's comment.

Added by the items and loot review before the PR (2026-10-05). The first two
are how `open_loot` already worked for the two-way crate; CS-04 makes that
path carry every class's gear.

6. **Loot left in the crate is lost on a relog or a restart.** The roll is
   pending only while the container entity lives
   ([loot-system.md](../../../gameplay/loot-system.md)), and
   `once_per_character` never rolls again. A Soldier who presses the crate,
   closes the window without taking the LMG and relogs gets "You have already
   taken everything from this" from chain 1191, and the gear is gone. Whether
   a relog tears down the player's CellBlock instance was not checked here;
   CS-08 should try it. A fix belongs in the loot system (persist the pending
   roll, or clear the once flag while items remain), not in these chains.
7. **A refused `open_loot` does not stop the rest of its chain.** If a GM
   resets M687 or changes a character's archetype after the crate was looted,
   step 2354 is active again with the once flag set: the press shows the
   dialog and "already taken", then advances the step and grants the
   signature with no gear. No test covers a refused window followed by a
   grant. Rare, and GM-only.
8. **6843 Hologram Emitter goes to the mission bag.** Its `container_sets` is
   `{2}`, so the Archaeologist finds it there, it cannot be banked, and
   ability 802 does not need it. It matches the Gear matrix and dialog 4409.
   UAT should look for it in the mission bag and check whether completing a
   mission clears it.

On question 2, the review found that the swap also answers the "Jaffa armor
not right" note of the
[2026-09-18 colo playtest](../../playtests/2026-09-18-colo-castle/README.md):
4342 has a real Jaffa visual component (`AR_J_Standard`); only its icon is
missing. Nothing else in the seeds or code depends on 3482 coming from this
crate.
