## Differences from the contract

1. **`LabChaos::clear` returns `usize`** (entries removed), not `()`. The
   CH-05 `server_chaos_clear` tool reports `{cleared: n}`, and counting
   inside the lock is the only race-free way to get `n`. Callers that ignore
   it are unaffected.
2. **`addr_hash` is keyed per process.** It is a SipHash of the address
   under a `RandomState` made when the registry is created, printed as 16 hex
   digits. Rows from one server run correlate; across restarts they do not.
   An unkeyed hash of an IPv4 address can be reversed by hashing every
   address, which would make it the address under another name.
3. **`seed` is 0 when the profile has none** (`flush` delay, pack and a fixed
   shift). Otherwise it is the net seed, else the flush seed.
4. **`LabChaos` also implements `Default`** (clippy's `new_without_default`).
5. **One extra test**, `set_logs_a_hash_never_the_address`, guards the
   logging rule. `install_refuses_without_developer_mode` also checks that a
   refused install leaves `current()` empty and that `install(true)` then
   installs: it is the only test that touches the process-wide registry, so
   the two halves cannot race another test.

## Review fixes (second commit)

The CH-04 review (security, authority and packet reviewers) moved the
limits into the registry, so no later caller can skip them.

- **`set` signature:**
  `set(addr, entity_id, label, net, flush, ttl_s, now) -> Result<Instant, ChaosRefused>`.
  It refuses `ttl_s == 0` (`BadTtl`), `ttl_s > MAX_TTL_S` (`TtlTooLong`), an
  expiry past the clock (`BadTtl`), a request with neither profile and any
  knob out of bounds (`BadKnob`). It returns `expires_at`, and it sweeps
  every expired entry, so the map stays bounded. `DEFAULT_TTL_S` is the
  caller's to apply.
- **`SessionChaos` carries `entity_id` and `label`** (the CH-01 header text,
  such as `flush:pack seed=7`). The set WARN logs the label as `level` (D-CH2).
  `status()` returns `Vec<SessionChaos>` sorted by entity id, with no address.
- **Knob bounds:** `latency_ms` and `jitter_ms` <= 5000; `loss_per_thousand`
  and `dup_per_thousand` <= 1000; `reorder` <= 1000; `Delay { ms }` <=
  60 000; `Pack { records }` 1 to 255; `Shift { len }` 0 or 2 to 36. A length
  of 1 is impossible: the filler is `updateFrequencyNotification` (0x02,
  exactly 2 bytes) or `voiceData` (0x33, 3 to 36).
- **Teardown clear:** `teardown_session` clears the address's entry after its
  owner check passes. A relaunch takeover (`crates/base/src/base/login/eviction.rs`)
  tears the old session down through that path before it inserts the new
  one, so the new session never inherits the old one's chaos. A late
  owner-checked teardown that finds a newer session returns before the clear,
  so it cannot wipe chaos set on the newer session.
- **`clear_if_not(addr, entity_id)`** removes the entry at `addr` if it was
  set for another entity. Two gaps remain that the teardown clear cannot see,
  and the later packets close them with it:
  - **CH-05:** between resolving `entity_id` to an address and calling `set`,
    the session can end and another can take the address. After `set`,
    re-resolve `entity_id`; if it no longer maps to that address, call
    `clear_if_not(addr, <the entity now there, or 0>)` and refuse with
    `NoSession`.
  - **CH-07:** a `logOff` to character select keeps the session (and the
    address) but ends the player entity, and the next character gets a new
    one. Before reading `flush_for`, call `clear_if_not(addr, player_entity_id)`
    so a new character starts clean.
- **CH-05 also must:** refuse a `ttl_s` over the cap at the tool layer with
  the registry's refusal text, and clamp nothing silently (D-CH3's "clamped"
  is superseded: over the cap is refused); apply `DEFAULT_TTL_S` only when the
  request names no TTL; report entity ids from `status()`, never an address;
  and never wire `set` or `clear` into admin-api or the console.
  `lab_chaos_callers` (`crates/server/tests/`) fails if `current()` is read
  outside the allowlist.
- **CH-06:** every `net_for` takes the registry's one mutex. On the per-send
  path, consider a cheap "nothing set" check first.
- **CH-07:** `ShiftSweep` must draw its length from 0 and 2 to 36, never 1
  (the packet's `rng % 37` can give 1).
- **CI:** `build-and-test` now runs `cargo nextest run --profile=ci -p
  cimmeria-base-session --features lab-chaos` and `cargo check -p
  cimmeria-server --features lab-chaos`, so the question in "Other rows"
  below is settled.
