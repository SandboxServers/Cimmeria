## Differences from the spec

1. **Errors under chaos.** The spec says a chaos-only divergence does not
   exit 5. A diff that could not be made (`error: ...`) is not a
   divergence: it is reported under `chaos_divergence.errors`, its line is
   not prefixed, and it still exits 5, as under `-DiffGolden`.
2. **No key when everything matched** (reversed by review fix 5). "A matching row has no key" is read
   batch-wide: a chaos batch whose compared runs all matched has neither
   `golden` nor `chaos_divergence`. The per-run value is still in
   `batch.jsonl` (`Golden`).
3. **Chaos is detected from the runs.** `Merge-UatResults` keys on a run's
   `Chaos` (the runner's header, CH-08), not on the typed `-Chaos`. A run
   that errored before returning a header has no `Golden` either, so
   nothing is lost.
4. **Tests are in `test-uat-chaos.ps1`, not `test-uat.ps1`** (CH-08 moved the
   chaos checks there; `test-uat.ps1` is at 573 lines). The existing chaos
   checks there that call `uat.ps1` now point `Get-DefaultSpecsDir` at a
   temp folder holding a golden, and the loopback MCP stub answers
   `lab_golden_diff`.
5. **The progress line** still says `; golden: <value>` per run under
   `-Chaos`; only the summary and `-Json` relabel it.

## Review fixes

Second commit, after the adversarial review. Each fix has a check that
fails when it is reverted.

1. **Grouping on the unprefixed line.** `Merge-UatChaosDivergence` is now
   `Merge-UatGolden` over the chaos runs, with the same lines, so five runs
   with one divergence are one group of five (they were five groups, one
   per seed). `Merge-UatGolden` takes an optional `$RunRef`; the chaos one
   (`Get-UatChaosRunRef`) names each run `<instance>#<index> seed=<n>`, so
   `summary.md` and `batch.json` say which runs (by seed) showed each group.
   `batch.jsonl` already carries each run's full header. The header is the
   top-level `chaos` key only, never part of a line or of `first`.
2. **Budget.** `first` is cut to 120, as `golden`'s is. The realistic check
   (5 runs, 6 rows, `cpu:safe; net:latency=120,loss=1`, 20-digit seeds,
   the same divergence on every run) gives 591 characters, under 600. The
   margin is small: most of it is the batch header, which still lists the
   first run's full header and counts the rest (CH-08's
   `Select-UatChaosHeader`); a shorter header is a CH-12 option if a longer
   batch path is a concern.
3. **`-Chaos -PlanOnly` needs no golden.** A plan drives nothing, so the
   golden check is skipped; a refused spec (`burst`, an unknown profile)
   still exits 3 from the plan call. With no local spec folder a chaos run
   is no longer refused for `-SpecsDir`: the daemon resolves its own
   (`lab_golden_diff` with no `specs_dir`), and a missing golden there is
   each run's diff error, so the batch exits 5 after it ran. The local
   check refuses only when it can locate the golden file and it is missing.
   `-DiffGolden` alone still needs `-SpecsDir`.
4. **Contract.** The coordinator note is in
   `docs/analysis/lab-golden/contract.md` (Stable API), with a dated bullet
   in both ledgers' review outcomes.
5. **Compared and clean.** Deviation 2 is reversed. The contract's
   `golden` key is present whenever a run was compared, `{match: n,
   diverged: 0}` included, so `chaos_divergence` follows the same rule: a
   clean chaos batch reads `{match: n, diverged: 0}`, and a batch never
   compared has no key.
6. **Mixed batches.** A run without the runner's header stays under
   `golden` (and its divergence exits 5) even when other runs of the batch
   ran under chaos (`Select-UatChaosRuns`); before, one chaos run moved the
   whole batch under `chaos_divergence`.
7. **Nits.** `golden.rs` doc and the `uat.ps1` help reflowed; Rust tests for
   `"chaos": null` (recorded) and a chaos run in first place (refused).

Tests added in `test-uat-chaos.ps1` (50 checks): the unprefixed group and
its seed ref, `first` at most 120, the header as the `chaos` key once, the
summary line with the run and seed, the 5-run budget and one-group checks,
