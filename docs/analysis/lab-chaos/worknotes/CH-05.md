## What landed

  `server_chaos_clear` and `server_chaos_status`, with their argument types
  and logic. It is the only lab-mcp file that reads
  `lab_chaos::current()`, by its full path, as `lab_chaos_callers` requires.
- `crates/lab-mcp/src/tools/mod.rs`: `mod chaos` under
  `#[cfg(feature = "lab-chaos")]`, the test module, and
  `LabTools::new` adding `chaos_router()` to the router under the feature.
- `crates/lab-mcp/src/tools/chaos_tests.rs`: one test in every build that
  the three names are routed exactly when the feature is on, and ten
  feature tests: every tool refuses while the registry is not installed;
  the default TTL applies only when `ttl_s` is absent; a named TTL (1801,
  0) and an out-of-bound knob get the registry's refusal text unclamped; an
  entity with no session is refused; the race guard; clear's count; the
  status cap of 10 and its entity-id-only rows; the label; knob conversion.
  Reverting the race guard's `clear_if_not` or the router merge fails a
  test (checked by hand).
- `docs/guides/live-research-lab.md`: the three rows in the server tool
  table, marked "lab-chaos builds only", and a line in the server tool list.

## Differences from the spec

1. **The router lives in `chaos.rs`.** A second
   `#[tool_router(router = chaos_router, vis = "pub(super)")] impl LabTools`
   block sits beside the tool logic, and `mod.rs` merges it. `mod.rs` was
   560 lines; the three tools in it would have taken it past 600, and it
   keeps every `lab_chaos` path in the one allowed file.
2. **A refusal is a successful call.** The reply is `{refused: reason}`,
   unlike the other tools, whose failures are tool-error results. The audit
   row still logs WARN with `outcome=error` and the reason, so a refusal is
   visible in the audit trail.
3. **An optional `label` argument.** The spec's call shape takes "the
   request's spec text if given", but the contract table lists no argument
   for it. `label` is it, refused over 120 characters because every set
   WARN logs it.
4. **Refusals before the registry**, worded like its `BadKnob`
   (`bad chaos knob: ...`): a negative `loss` or `dup` (the cast to the
   registry's unsigned per-thousand would read it as 0), a flush mode
   missing its knob, an unknown mode, a `shift` word other than `sweep`, and
   a long label. A percent too large for `u32` saturates and the registry
   refuses it. A request with neither profile, and every bound, is the
   registry's.
5. **One `seed` for both profiles.** It seeds the net RNG and the flush
   `reorder` and `sweep` modes. Absent means 0.
6. **Status rows** spell net loss and dup in percent, as set takes them,
   and carry the seed; a sweep shift shows `"shift": "sweep"` with its seed.
7. **`names.rs` is unchanged.** It holds Rule 6 name helpers, not a tool
   list.
8. **The not-installed test reads the tool replies only.** The lab-mcp test
   binary never installs the registry (only the server's `main` may), and
   the test cannot assert `current()` directly: `lab_chaos_callers` allows
   that path only in `chaos.rs`.
