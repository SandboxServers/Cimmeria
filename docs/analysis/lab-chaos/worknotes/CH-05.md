## What landed

- `crates/lab-mcp/src/tools/chaos.rs`: `server_chaos_set`,
  `server_chaos_clear` and `server_chaos_status`, with their argument types
  and logic. It is the only lab-mcp file that reads
  `lab_chaos::current()`, by its full path, as `lab_chaos_callers` requires.
- `crates/lab-mcp/src/tools/mod.rs`: `mod chaos` under
  `#[cfg(feature = "lab-chaos")]`, the test module, and
  `LabTools::new` adding `chaos_router()` to the router under the feature.
- `crates/lab-mcp/src/tools/chaos_tests.rs`: one test in every build that
  the three names are routed exactly when the feature is on, and ten
  feature tests: every tool refuses while the registry is not installed;
  the default TTL applies only when `ttl_s` is absent; a named TTL (1801,
  0) and an out-of-bound knob get the registry's refusal text unclamped; an
  entity with no session is refused; the race guard; clear's count; the
  status cap of 10 and its entity-id-only rows; the label; knob conversion.
  Reverting the race guard's `clear_if_not` or the router merge fails a
  test (checked by hand).
- `docs/guides/live-research-lab.md`: the three rows in the server tool
  table, marked "lab-chaos builds only", and a line in the server tool list.

## Differences from the spec

1. **The router lives in `chaos.rs`.** A second
   `#[tool_router(router = chaos_router, vis = "pub(super)")] impl LabTools`
   block sits beside the tool logic, and `mod.rs` merges it. `mod.rs` was
   560 lines; the three tools in it would have taken it past 600, and it
   keeps every `lab_chaos` path in the one allowed file.
2. **A refusal is a successful call.** The reply is `{refused: reason}`,
   unlike the other tools, whose failures are tool-error results. The audit
   row still logs WARN with `outcome=error` and the reason, so a refusal is
   visible in the audit trail.
3. **An optional `label` argument.** The spec's call shape takes "the
   request's spec text if given", but the contract table lists no argument
   for it. `label` is it, refused over 120 characters because every set
   WARN logs it.
4. **Refusals before the registry**, worded like its `BadKnob`
   (`bad chaos knob: ...`): a negative `loss` or `dup` (the cast to the
   registry's unsigned per-thousand would read it as 0), a flush mode
   missing its knob, an unknown mode, a `shift` word other than `sweep`, and
   a long label. A percent too large for `u32` saturates and the registry
   refuses it. A request with neither profile, and every bound, is the
   registry's.
5. **One `seed` for both profiles.** It seeds the net RNG and the flush
   `reorder` and `sweep` modes. Absent means 0.
6. **Status rows** spell net loss and dup in percent, as set takes them,
   and carry the seed; a sweep shift shows `"shift": "sweep"` with its seed.
7. **`names.rs` is unchanged.** It holds Rule 6 name helpers, not a tool
   list.
8. **The not-installed test reads the tool replies only.** The lab-mcp test
   binary never installs the registry (only the server's `main` may), and
   the test cannot assert `current()` directly: `lab_chaos_callers` allows
   that path only in `chaos.rs`.

## Review fixes

A second commit on the branch takes the CH-05 review's verified findings.

1. **Nothing a request names is ignored.** `SetArgs`, `NetArgs`,
   `FlushArgs` and `ClearArgs` deny unknown fields. A `net` whose knobs are
   all absent or zero is refused (`net sets no knob`), and so is a flush knob
   the mode does not read (`flush pack does not use delay_ms`) and a `seed`
   when neither `net` nor a flush `reorder` or `"sweep"` reads it.
2. **A malformed call reaches the tool.** The argument types moved to
   `chaos_args.rs`, and set and clear take raw JSON (`SetCall`,
   `ClearCall`) whose schema delegates to the typed arguments, the
   `server_stage_fixture` pattern. A negative or too-large integer, a
   fraction for `records`, a bad `shift` type or a string `ttl_s` is now
   `{refused: "bad chaos knob: <field>: ..."}` with an audit row, instead of
   an rmcp protocol error with none. The parse runs before the registry
   check, so it answers even on a server with chaos off. `chaos.rs` remains
   the only lab-mcp file that reads `lab_chaos::current()`.
3. **Entity 0 is refused.** The roster lists a session with no player
   entity as id 0. Set and clear refuse `entity_id: 0` with the
   `no session for entity 0` text, and the address lookup skips id-0 rows.
4. **Clear works by the entity tag.** New `LabChaos::clear_entity` removes
   every entry tagged with the id, wherever its session is now, so an entity
   that went back to character select (still listed by status) can be
   cleared. Clear no longer reads the roster. CH-06's atomic `has_net`
   count is not on this branch; whoever merges the two must make
   `clear_entity` keep that count right, as `clear` does.
5. **A return to character select clears the session's chaos.** The
   session survives that path, so no teardown ran and chaos set for the old
   character would have hit the next. `clear_lab_chaos_on_character_select`
   in `session_teardown.rs` (allowlisted) does it, and the logOff handler's
   character-select branch calls it under `#[cfg(feature = "lab-chaos")]`
   (`cimmeria-base`'s feature forwards `cimmeria-base-session`'s). The
   helper's behaviour is tested in the registry's process test, the one test
   allowed to install the registry. The call site has only a text guard
   (`character_select_logoff_clears_the_sessions_chaos` in
   `lab_chaos_callers`): `install` is allowed only in the server's `main`
   and the registry module, so no `cimmeria-base` test can drive the
   handler with live chaos.
6. **Labels.** A label with a control character is refused like an
   over-long one, and the audit row never carries a label set would refuse:
   it reads `<label: N chars, refused>` instead.
7. **Percent precision.** `loss` and `dup` must be whole tenths of a
   percent; 0.05 and 0.04 are refused instead of rounded (0.04 would have
   armed no loss at all).
8. **Status says what it left out.** Over ten sessions, the reply adds
   `more: n`.
9. **Guide.** The chaos rows left the "Both are reads" table for their own
   table and paragraph in `docs/guides/live-research-lab.md`.

Tests: the arguments' tests moved to `chaos_args_tests.rs` (malformed calls
through the tool entry point, the delegated schema, unknown fields, empty
net, unused knobs and seed, tenths, labels in the audit row);
`chaos_tests.rs` gained clear-after-character-select, entity 0, `more`, the
seed refusal at set and the control-character labels; the registry gained a
`clear_entity` test.
