## Design decisions

- **How the base gets the catalog.** `ability_tree::shared_catalog(pool)` holds the process's one `Arc<AbilityTreeCatalog>` in a `tokio::sync::OnceCell`, loaded by `AbilityTreeCatalog::load` on first use. Cell startup now takes its `SpaceManager.ability_tree_catalog` from it (a clone of the snapshot), and the base's player load reads it. Result: one SQL read per process, and the base and cell hold the same snapshot, so content and order cannot diverge. A failed load is not cached; the next caller retries.
  - Rejected: threading an `Arc<AbilityTreeCatalog>` through `BaseService` → connect loop → `handle_play_character` / `handle_gate_travel` → `query_player_load_data`. That touches a dozen positional signatures and their tests, and collides with other packets.
  - Rejected: changing `SpaceManager.ability_tree_catalog` to `Arc`. AT-01's tests and the in-flight AT-03/AT-04 branches assign and `push` into it directly.
  - Caveat: the catalog does not reload without a restart. That matches the cell's existing startup caches; the table is seed data.
- **`tree_info(catalog, archetype, player_id)`** groups the catalog tree into the three wire branches in catalog order. An empty tree emits one WARN: target `abilities` (already in `OTEL_FILTER` at debug, so no filter change), `event=tree_missing`, `reason=archetype_has_no_tree`, `player_id`, `archetype_id`. A node outside branches 0..=2 (impossible under `tree_index_sanity`) is dropped with an ERROR `reason=tree_index_out_of_range`.
- **Catalog load failure at player load** sends an empty tree and logs ERROR `abilities event=tree_catalog_load_failed reason=catalog_load_failed`. Player load does not fail.
- **No DB (`default_player_load_data`)** now carries an empty tree instead of the Soldier copy.
- **World-data test fixture.** `fixture_ability_tree()` builds a catalog with the retired Commando branch sizes (28/30/27) and synthetic ids `9000 + 100*branch + n`, so the fragmentation tests keep the payload size they were calibrated on.
- **Wire.** Unchanged for seeded archetypes (live-DB equivalence test). No `docs/protocol/` change.

## Known gaps

- `shared_catalog` keys on nothing: a process that talks to two databases would get the first one's catalog. The server has one.
- The trainer's `onTrainerOpen` list order still comes from `trainer_abilities`, not the catalog. The client joins the two by id (AT-E1), so this is not a mismatch, but a future "trainer lists the whole tree" (D-AT07) should iterate `catalog.tree()`.
