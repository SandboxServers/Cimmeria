# LN-12 — RE: Black Market reopen sends no `BMSearch` (F8, D-LN2)

Agent: game-archaeology-specialist · 2026-10-22 · static only (no lab, no code edits)

## Answer in one paragraph

The bug is in our own overlay Lua, not in the 2009 binary. `BlackMarketMod.now()`
(`crates/client-patches/overlay/Content/UI/Core/BlackMarket/BlackMarket.lua` L125-131)
uses `worldGetDeltaSeconds()` as a clock, but that binding returns the **per-frame delta**
(about 0.016-0.033 s), not elapsed time. So after the first search the 4-second
`searchSuspended` cooldown never expires (`now - searchDelayTime` is about 0, always under
`SEARCH_DELAY = 4`). Every later open then hits `openSession`'s
`if searchSuspended then setStatus('Press Search to list auctions.')` branch (L511-512) and
sends nothing. The Search, Next and Prev buttons also stay disabled for the life of the
client process (`updateSearchNavButtons` L1330 needs `searchSuspended == false`), and the
15-second pending timeout never fires either. The My Auctions tab is incidental: it does not
suppress anything.

Wire signals the client sends around a reopen (from the same Lua, all through `CimmeriaBMNative`):

- **Close** (`onCloseClicked` L474): nothing.
- **Reopen**: the client sends only the NPC interaction. The *server* then sends `onBMOpen`
  (client method 90, cell `content/executor/black_market.rs` `open()` L62-176), which
  shows the window. The server therefore already knows every open, because it initiates it.
- **Tab 1 (Search) click** (`showTab(1)` L1275-1304): nothing, by design. The cached search
  rows stay, because `onAuctions` for view 1 replaces only view 1 and `pruneAuctions` keeps
  view-0 ids. A tab return without closing should still show items. If the run saw an empty
  list on a pure tab return, that is a separate symptom; check it in LN-13.
- **Tab 2 (My Auctions) click**: `requestView(MyAuctions)` sends `BMSearch` with
  `clientKey = 1` and an empty filter (L963-973).
- **Tab 3**: `BMSearch` with `clientKey = 2`.

The DLL is stateless and delivers queued receives in order (`crates/client-patches/src/deliver/`),
and `CimmeriaBM.onAuctions` (L313-368) needs no outstanding request: it fills view
`clientKey` whenever a reply arrives. So an **unsolicited `onBMAuctions` with
`clientKey = 0` is accepted and rendered** ("Found N auctions.").

## Options (D-LN2)

**(a) Server-only push. Viable, but only a partial fix.** After `open()` sends `onBMOpen`,
the cell also forwards `CellToBaseMsg::BMSearch { entity_id, player_id, options: <default
empty filter, clientKey 0, sortId 0, bForward true> }`. That reuses the existing base path
(`base-methods/.../black_market/search.rs` `handle_search`/`run_search`), so the list fills on
every open. Order is safe: `onBMOpen` → `show()` → `openSession` resets the store
synchronously before the pushed reply is delivered. On a first open the client also searches
itself; the second reply just overwrites the first. **What it does not fix:** Search, Next and
Prev stay dead after the first search, filtered searches are impossible, and pending timeouts
never fire. The Black Market is still not "working". Pushing on the `clientKey = 1` request
instead is worse: it would overwrite a filtered search.

**(b) Fix the overlay clock. This is the root cause and the recommended option.** It changes
only our own overlay Lua, which the BM client-patch decisions (D1-D8) already cover. No
binary patch, opcode or wire change. About 6 lines:

```lua
BlackMarketMod.clock = 0
function BlackMarketMod.now() return BlackMarketMod.clock end
-- first lines of onPreRender:
local ok, dt = pcall(worldGetDeltaSeconds)
if ok and type(dt) == 'number' and dt > 0 and dt < 1 then BlackMarketMod.clock = BlackMarketMod.clock + dt end
```

Also, in `openSession`, set `BlackMarketMod.searchSuspended = false` (each open is a fresh
session, and the clock does not advance while the window is hidden, because `PreRender` only
runs while it is subscribed or visible). Fix the stub (`stubs.lua:200`) to return a per-frame
delta, and make `run.lua` advance time by calling the PreRender handler with a delta. Add the
regression test "open → reply → close → reopen ⇒ a second `search` send". It fails on today's
`now()`. Ships through the signed overlay manifest, so lab-load it first (project rule).

**(c) Document as a client bug.** This is not warranted: the bug is ours and cheap to fix.

**Recommendation: (b).** It is the smallest correct change and it also fixes the dead
Search/Next/Prev buttons. Use (a) only as a stopgap if the owner will not republish the
overlay soon. In that case, ship it with a log line so it can be removed after (b).
