### What the client does not ship

A name search for `RomneysFiles|Romney|FileCabinet|EscortZuritskaRestart|BehindThrone` across all 21 cooked PAKs found only the records above, plus unrelated lore (703's Romney hunt, dialogs 30/522/524/2559/2576/2577/2982/4546/4983/963, item 2135 "Romney's NID Badge", VO bank `dialog_castle/lore/Romney` in Kismet sequences 283/284). In particular:

- **No interaction map binds offer dialogs 2042 or 2043.** Set 512 has exactly one map, 2817 (the turn-in). The seed agrees: no `dialog_set_maps` row has dialog 2042 or 2043, and `dialogs.accepts_mission_id` is NULL for both.
- **No record names the cabinet** outside `TextStrings.pak`: no interaction map, no Kismet sequence or set event, no item record.
- **No Castle package names it.** An ASCII scan of the 216 `CookedPC/Castle*` packages found no `Cabinet`, `Filing`, `Files` or `Romney` name. Only 75 of the 216 have a plain-text name table; the other 141 are compressed and were not decompressed. This is an absence boundary, not proof that no actor exists.
- **No seed row places the cabinet.** No `entity_templates` row has `name_id` 7547, no spawn uses it, and the H30 sweep (`crates/cell-content/src/cell/content/chain_replay_tests/mission_567.rs:4-10`) found no 2698 grant in any content, loot, reward, event-set, item-list or blueprint table.

The `ItG` prefix is shared by 17 object monikers (Harset Data Duplication Console 7600, Hebridan Burtonol File Cabinet 8418, Ihpet obelisks 7726-7735 and others). Reading it as "item giver" fits, but it is **inferred from naming**. Harset's reconstructed `ItG` objects (for example template 246, moniker 7603, `entity_templates.sql:957-959`) are `RECONSTRUCTION`, so they are not a source for 567.

### Verdict: BlockedEvidence

The missing proofs, any one of which would unblock a sealed graph:

1. **Grant of item 2698**: an event set, loot row, Kismet sequence or recovered script that gives 2698. None exists in the cooked client or the seeds.
2. **2000 → 2012 transition**: what completes objective 2338 (tasks 2933/2934/5696). Cooked missions never carry this; it was server script, and `deprecated/python/cell/spaces/Castle.py` has no 567 code (reconciliation.md:11).
3. **Cabinet actor**: a Castle actor or spawn named by moniker 7547, with a position. The best remaining lead is the 141 compressed `Castle*` packages, which `tools/upk_parser.py` / `tools/extract_actors.py` can decompress and trace.
4. **2012 → 4039 transition**: "safely off of the Castle" names no event. A `stargate_crossed`-style trigger would be a reconstruction.
5. **Offer binding**: which actor and set present dialogs 2042/2043. The speaker on 2042 is the Castle Copplemann, which is evidence for the giver but not for a set map.

Harset keeps step 4039. Chains 6503/6504 stay disabled. Chain block 1394-1397 stays unused.

### Reading the lineage

- The slot number `02` matches 702 (`opc_02RescueZuritska`), not 704 (`opc_04HackCommunications`). The step text repeats 702's beat: 702 step 2402 is "Make your way to the Interrogation Block." The name says "Escort", which is 704's step 2405, "Escort Dr. Zuritska to the Communications Room".
- The flags (no XP, not shareable, cannot abandon, cannot fail, not a story) fit a system-granted repair mission. They do not prove one.
- **No client record binds 1376.** No dialog, interaction map, Kismet sequence or set event names the mission or its monikers (same name search as above; numeric `1376` hits are unrelated IDs in other namespaces, such as dialog set 1376 "Tactical Strike"). Missions are offered by the server, and no cooked record tells the client when to offer this one.
- A restart variant of 704 offered after an escort failure is **plausible from naming** (a restart of the 02 rescue/escort arc), but no source says so.

### Verdict: hold (no chain)

The 704 escort re-arm is covered without a new mission: chain 1302 (`interact_tag Castle_Zuritska_Cell`, gated on 704 step 2405, `db/resources/Content/Seed/castle_702_704_chains.sql:655`-`665`) lets the player re-click Zuritska to restart the escort (see also `:142`, `:306-307`, `:621-622`). Chain 1302 does not show a 702-arc restart (CIMMERIA inference). Activating 1376 would add a second, unsourced path for the 704 need. Step 4098 stays seeded and disabled. Reopen this if a recovered script or a compressed Castle package (above) binds 1376 to a failure event.

**Not checked:** whether `SGW.exe` references mission ID 1376 directly. No Ghidra pass was run. A hard-coded mission ID in the 2009 client would be unusual.

## Method (reproducible)

All reads were done from PowerShell with `System.IO.Compression.ZipFile` over the PAKs named above. Each PAK entry `_<id>` is one UTF-8 XML record. The G-706 join extracted `MissionDefn`/`MissionID` from every `CookedDataMissions.pak` entry and matched it exactly against the `texts.sql` `DN_ms_` rows. The blank texts were then re-checked in `TextStrings.pak` itself. The 216-package `CookedPC/Castle*` ASCII scan (75 plain-text name tables, 141 compressed) was run by hand and its command was not recorded; it is **unreproduced**, and the 75/141 split is recorded as observed, not as a checked method.
