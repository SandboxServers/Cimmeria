# CS-02b0 — Base session-bound minigame sends

> **Type:** Reference. **Audience:** Castle packet implementers and reviewers.
> **Last updated:** 2026-10-14. **Status:** Integrated after independent rereview.
> **Companions:** [Castle ledger](../README.md), [receipt architecture](../work-packets.md#cs-0203-conditional-graph-candidates-not-runtime-seals), [test policy](../../../../TESTING.md).

## Purpose and boundary

This packet makes each minigame Mercury launch, close and launch-failure send
stay bound to one Base connection instance while it is prepared and sent. It
also makes an undeliverable launch release only its own SmartFox ticket. It
does not redeem a result, change the Cell callback handler, or wire a Castle
chain. CS-02b1 owns one-use result receipts and original-launch Base identity;
CS-02b2 owns Cell incarnation and per-launch generation. Castle 1520/1521
victory callbacks stay disabled until CS-02a, CS-02b0, CS-02b1 and CS-02b2
all pass.

The current generic `send_to_witness_reliable` resolves entity → address,
reads a key, reserves a sequence, sends and registers retransmission in
separate steps. A replacement at that address can make later steps use its
key, sequence or channel. The current Base minigame Start registers before
checking a live entity/player owner, and does not act on the URL send result.
`cancel(entity_id)` would be unsafe cleanup because an old launch can race a
new registration. This packet isolates a replacement connection's key,
sequence, ACKs and TX window from the send, and closes ticket cleanup races.
It does not claim that a late result belongs to its original launch.

## Reviewed implementation shape

Mint a process-unique, nonzero `session_instance_id` when Phase 3 creates
`ConnectedClientState`. Use a monotonic 64-bit ID or an equivalently strong
process-unique token; `connected_at` is a clock value, not identity. Tests
that construct a state directly must mint an ID too, and address-takeover
tests must use distinct IDs and distinct encryption keys. No client, DB or
SmartFox wire field changes.

Add an opt-in Base reliable send that takes an expected recipient snapshot:
entity ID, player ID where available, socket address and Base connection
instance. Validate the current `entity_to_addr` mapping and connected state
against that snapshot before packet preparation. For a Start URL, its
feedback, or a result-time close, revalidate `player_entity_id` and
`active_player_id` in the same
connected-state lock window that reserves ACKs and sequence numbers: the
same Base connection may log off one character and play another. Through
the single-packet and fragmentation paths, use only the captured session
key/version and reserve ACKs and sequence numbers only from the expected
instance. ACK requeue and sequence rollback must also check that instance;
neither may mutate a replacement state at the same address. Before
registering a sent packet in the retransmission window, require the same
instance still owns the channel. If ownership changes after a packet is
built, a send may reach the old address with the **old** key; it must never
use the replacement key or register in the replacement channel. Preserve
the generic helper's behavior for unrelated callers, packet bytes, 1472-byte
limit, fragmentation, ACK and reliable sequence semantics. Return the
existing `WitnessSendOutcome` or a narrowly extended equivalent so callers
can distinguish success from refusal. Do not add a second copy of the
Mercury framing implementation. A same-instance character switch **after**
sequence reservation can still receive the old URL or close; dropping a reserved
reliable sequence instead would create a stream gap. B0 claims the earlier
owner check and replacement-instance isolation only. Later b1/b2 identity
gates must prevent any resulting mission callback.

At `StartMinigame`, require a current Base session whose
`player_entity_id == Some(entity_id)` and
`active_player_id == Some(player_id)` with `player_id > 0`. Snapshot its
instance and address, register the SmartFox session, then send the existing
`onStartMinigame(URL)` bytes only to that instance. A changed owner or send
failure calls new registry `cancel_if_ticket(entity_id, ticket)`; it may not
call entity-wide `cancel`. The method cancels/removes only an exact current
ticket, signaling its SmartFox task and cleaning its board as `cancel` does.
If registration refuses a duplicate, leave the first board and ticket
intact. Send launch-failure feedback only when the captured instance still
owns the same player and entity; never send it to a foreign session.

At result handler time, keep the current replacement-ticket check and
unchanged Cell forwarding. Scope any `onEndMinigame` send to the Base session,
entity and player captured by that handler, and recheck all three in the
reservation lock window; a character switch between the snapshot and
reservation must emit no close. This does **not** bind the close to the original
launch: a late old result first handled after same-character relog can still
see a new current session. CS-02b1 must retain the original Base instance in
the redeemed ticket receipt and compare it together with original entity
and player before closing UI; CS-02b2 must
guard Cell mutation after redemption. Do not claim those outcomes in b0.

## Tests and revert proof

Pick concurrency and fan-out-byte tests under `TESTING.md`, with wire-format
assertions for the existing minigame method bytes. A real-loopback Mercury
session test is outside this packet; no client acceptance is claimed. Use
barriers in a transport or at the scoped-send seam rather than timing sleeps.
Bound every spawned task/barrier wait with a timeout and propagate each
JoinHandle result, so a deadlock cannot turn into a hanging test.

- A matching entity/player starts and receives the same
  `onStartMinigame(URL)` bytes; missing, wrong-entity, wrong-player and zero
  player ownership register no ticket and emit no URL or launch-failure
  feedback to a foreign session. A duplicate Start leaves the first ticket
  and board usable and sends feedback only to that same instance.
- Replace `connected[addr]` with a different instance and key after the
  recipient snapshot but before preparation: no replacement-key packet or
  TX registration. Also switch the character on the **same instance** after
  Start snapshot but before ACK/sequence reservation; no old-character URL
  may be reserved or sent. Replace it while transport send is paused: any
  bytes sent remain encrypted for the old instance, and the new channel has
  no registered packet. In both takeover cases assert the replacement's
  `next_seq`, pending ACKs and TX window are unchanged; decrypt/parse any
  sent ciphertext with the old key and identify the expected method. A
  failed URL releases only its ticket.
- A current result still emits the same `onEndMinigame` bytes; the existing
  replacement-ticket test still suppresses a stale close. A send-time
  address takeover cannot close the replacement by its key. A same-instance
  character switch after close snapshot but before reservation emits no
  close and changes none of the new owner's sequence, ACK or TX state.
- A deliberately oversize minigame URL takes the fragmentation path with
  the same instance guard. Assert fragment count, contiguous sequence
  numbers, each datagram at most 1472 bytes, exact reassembled URL and no
  registration or ACK/sequence mutation in the replacement channel.
- `cancel_if_ticket` removes/signals only an exact match; a stale ticket
  leaves a newer registration. Removing its ticket comparison must make
  this test fail. Removing the scoped sender's instance check must make
  the distinct-key takeover test fail. Removing failed-URL outcome cleanup
  must leave a usable phantom ticket and fail its assertion. Record failed
  assertion, exit code and restored pass for all three temporary reverts.

## Implementation and verification — 2026-10-14

The packet branch adds a process-unique Base connection instance at Phase 3.
`StartMinigame` requires the current entity/player owner before registration;
the existing URL, failure feedback and result-time close use an opt-in
instance-bound reliable sender. That sender captures the old key/version,
checks owner before ACK/sequence reservation in both single and fragment
paths, and registers TX bytes only on the same connection instance. A failed
URL cancels exactly its ticket. Existing generic Mercury send callers and
Cell result forwarding remain unchanged. The result-time close is scoped to
the handler's current session; original-launch binding remains CS-02b1/b2.

## Independent review repair — 2026-10-14

The review verified two defects in the implementation commit. First, a
replacement connection could take over after transport send but before TX
registration; the scoped sender skipped registration and still returned
`Sent`, leaving an unusable SmartFox ticket. The registration result now
becomes a non-`Sent` outcome in single and fragmented sends, and a fragmented
send stops after refusal. Generic reliable callers retain their prior
behavior. Second, an address-map change returned `AddrUnresolved` and canceled
the ticket silently. Every non-`Sent` URL outcome now logs the outcome and
whether exact-ticket cleanup succeeded, with no ticket value in that event.

The existing inline world-entry tests were moved without changing their
assertions to `minigame_tests.rs` to keep the handler below 700 lines.
`minigame_takeover_tests.rs` covers post-send takeover, cleanup of the
failed launch's own ticket, and preservation of a replacement board. The
session-bound tests cover refusal after the first and second fragment.
