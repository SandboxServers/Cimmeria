## Did `handle_gate_travel` need modification? Yes — three changes

The packet brief's assumption (thin reuse, `None` ring id) was half right.
`handle_gate_travel` is reusable, but it is the **back half** of the flow and
could not satisfy two of the three acceptance criteria unmodified. Full trace
in the worknote; the short version:

1. **New parameter `destination_space_id: Option<u32>`.** The only
   destination input was a world name, which the cell resolves via
   `find_or_create_space` — a function that *always allocates a brand new
   space* for an instanced world. `.goto <player>` could never have joined
   the target's instance. Plumbed `CellToBaseMsg::GateTravel` →
   `handle_gate_travel` → `BaseToCellMsg::CreateEntity` →
   `SpaceManager::create_entity_in_space`.
2. **Hoisted the fail-closed `active_player_id` guard above the
   `CreateEntity` round-trip.** There were two copies of it, both *after*
   the create. Hitting either left the cell entity moved into the destination
   world while the client never got `RESET_ENTITIES` and never got a
   `pending_world_entry`. Now one check, before the point of no return.
3. **Added a post-create disconnect reap.** `destroy_client_entities` clears
   `entity_to_addr` before queuing its own `DisconnectEntity`, so that
   teardown can reach the cell *before* our `CreateEntity` and leave a
   clientless ghost entity parked in the destination space forever. The
   handler now re-checks the session after the round-trip and sends
   `DestroyEntity` if it is gone.

No parallel teardown/re-entry path was built. The packet's exclusion
("don't duplicate disconnect-recovery state") holds: the reap reuses the
existing `DestroyEntity` message.

**Why the primitive itself is cell-side, not a base-side wrapper:** the
destructive step (`space_mgr.destroy_entity`) lives in the *cell*, in each
caller, before `GateTravel` is even sent — `handle_gate_travel`'s own doc
comment says "The CellService has already removed the entity from its old
space." "Validate before teardown" is therefore structurally impossible to
implement base-side.

## Correction to decision D15 the coordinator should record

D15 says `.gotolocation`'s instance selection reuses
`resolve_space_id_fallback` as "the existing first/default loaded instance
mechanism". **It is not one.** Read
`crates/services/src/base/world_entry/space_registry.rs`: it is a hardcoded
three-entry match (`Castle_CellBlock`/`SGC_W1`/`CombatSim`) whose catch-all
arm warns and returns `DEFAULT_SPACE_ID` (Castle_CellBlock). Using it as the
selector would send a GM to Castle_CellBlock for every world outside those
three while telling the client a space id nothing is in.

Its sibling `register_space` writes a `world_name → space_id` map that
**nothing reads** (one writer in `cell_dispatch/aoi_dispatch.rs`; grep finds
no readers outside its own test), so the base has no live world→space index
at all.

D15's *intent* is implemented, in the place that actually knows:
`SpaceManager::default_space_for_world` — the non-instanced world's startup
space, else the lowest-numbered loaded instance of that world (deterministic,
because space ids are allocated monotonically). `resolve_space_id_fallback`
is left untouched as the degraded last-resort path it already was. **No
behavior contract changed — only the mechanism named in D15.**

## Behavior implemented

### `cell::space_transfer::transfer_player_to_space` — the P46 entry point

```rust
pub async fn transfer_player_to_space(
    entity_id: u32,
    dest: &TransferDestination,
    tx: &mpsc::Sender<CellToBaseMsg>,
    space_mgr: &mut SpaceManager,
) -> Result<TransferOutcome, TransferRejected>
```

Ordering contract:

1. **Validate** — finite position *and* rotation; subject entity exists;
   subject `is_player` (D15); destination world is in `spaces.xml`;
   destination instance resolves.
2. **Flush** bandolier ammo (the only per-entity state teardown would drop;
   a persistence write, not a state change).
3. **Enqueue** `GateTravel` and confirm the send.
4. **Teardown** `destroy_entity` — only now.

A rejection at 1, or a closed channel at 3, leaves the subject in its origin
space at its origin position with its AoI intact.

### Types P46 will use

```rust
pub struct TransferDestination {
    pub world_name: String,
    pub space_id: Option<u32>,   // None = D15 default instance
    pub position: [f32; 3],
    pub rotation: [f32; 3],
}
impl TransferDestination {
    pub fn in_world(world_name: impl Into<String>, position: [f32; 3]) -> Self;
    pub fn in_instance(world_name: impl Into<String>, space_id: u32, position: [f32; 3]) -> Self;
}

pub enum TransferOutcome {
    /// Destination == subject's current space. NOTHING torn down.
    /// Finish with the P26 same-space snap instead.
    SameSpace { space_id: u32 },
    /// GateTravel enqueued, subject removed from its origin space.
    Transferred { space_id: Option<u32> },
}

pub enum TransferRejected {
    EntityNotFound,
    NotAPlayer,                  // D15
    NonFinitePosition,
    UnknownWorld(String),        // describe() == "Unable to find world: {w}"
    WorldNotLoadable(String),
    InstanceNotLoaded(u32),
    InstanceWorldMismatch { space_id: u32, requested_world: String, actual_world: String },
    EnqueueFailed,
}
impl TransferRejected { pub fn describe(&self) -> String; }
```

### How P46 should call it

- **`.gotolocation <worldName> <x> <y> <z>`** —
  `TransferDestination::in_world(world, [x, y, z])`. D15's first/default
  instance rule is already inside. Map `UnknownWorld` to legacy's exact
  `"Unable to find world: %s"` — that is already `describe()`'s text.
- **`.goto <name>`** — P44 resolves the named player's `entity_id`; read
  their space and position via `space_mgr.get_entity_space_id(target)` and
  `get_entity(target).position`, then
  `TransferDestination::in_instance(world, their_space, their_pos)` for the
  *caller-or-selected* entity.
- **`.summon <name>`** — same call, subject = the named player, destination =
  the caller's space/position.
- **Match the result exhaustively — never `if result.is_ok()`.** `SameSpace`
  performs no position move at all, so treating `Ok(_)` as "teleported" would
  silently do nothing and report success.
- **When the destination world equals the subject's current world, pass
  `space_id: Some(current_space)`.** `in_world` resolves to the *oldest* loaded
  instance, so a GM already inside instance C running `.gotolocation` into
  their own world would otherwise be yanked to instance A with a full loading
  screen. Naming their current space turns it into the cheap `SameSpace` snap.
- **Remove the `#[allow(dead_code)]`** on `pub(crate) mod space_transfer` in
  `cell/mod.rs` — it exists only because the primitive has no production
  caller until P46.
- **Both must handle `Ok(SameSpace { .. })`** by falling through to the P26
  `.gotoxyz` mechanism: `update_entity_position`, then
  `note_authorized_teleport`, then `CellToBaseMsg::TeleportPlayer`. A
  same-instance `.goto` is a snap, not a loading screen.
- **Feedback is P46's job.** The primitive has no feedback channel by design
  (D03: caller identity is carried by the command layer, not the shared
  operation), matching P26's precedent where `TeleportPlayer` carries no
  GM-feedback field.
- **Legacy's `entity = target or player` precedence** is P46's to apply; the
  primitive takes whichever `entity_id` it is handed.

## Known gaps / deliberate non-fixes

1. **`BaseToCellMsg::CreateEntity.reply_tx` has no failure channel.** It is
   `oneshot::Sender<u32>`; a cell-side create failure drops it and the base
   falls back to `resolve_space_id_fallback`, building a world-entry packet
   for a space the entity is not in. The GM transfer path validates the world
   and the instance before teardown specifically so that arm is unreachable,
   and the error log now says what happens. Widening to
   `Result<u32, String>` (4 call sites) is the correct fix and belongs to the
   gate-travel owner — out of P45's blast radius. The `create_startup_spaces`
   guard added in this packet closes the one route that could otherwise have
   reached this arm for GM transfer, so the "unreachable" claim is now
   enforced by code rather than by the shipped XML happening to be disjoint.
2. **`space_registry::register_space` writes a map nothing reads.** Dead
   code, not touched. Worth a cleanup packet.
3. **`RESET_ENTITIES` send failure** (`transport.send_to(...).await?`) still
   returns `Err` with the entity already in the destination space and no
   `pending_world_entry`. Pre-existing; a socket-level send failure on the
   local UDP socket is a different class of problem and was left alone.
4. **No wire-format test.** P45 adds no bytes — `destination_space_id` is an
   internal cell↔base routing field that never reaches the client. The
   client-visible artefact is `pending_world_entry.space_id`, which is
   asserted in `destination_space_id_reaches_create_entity_and_pending_world_entry`.

### Must-fix — security review

**S1. The disconnect reap could destroy a live player's entity.**
`EntityManager::allocate_id` recycles ids from a free list and
`destroy_client_entities` frees ours on the way out, so while we are blocked
on the create oneshot a *second* client can be handed this exact id and
register it against their own address. The reap treated "mapped to a
different addr" identically to "unmapped" and would have sent `DestroyEntity`
for the new owner's live entity — leaving them connected, in no space,
invisible. Precisely the false positive the reap is supposed to be safer
than. **Fixed:** only genuine unmapped / closed-session reaps; a remap to
another address logs at `error` and bails. Guarded by
`recycled_entity_id_is_never_reaped_out_from_under_its_new_owner`.

**S2. A forced transfer stranded the subject's trade partner.**
`destroy_entity` does not clean trade state — that is why both lifecycle arms
call `cancel_trade_on_disconnect` — and the helper early-returns once
`get_entity` misses, so it cannot be called after teardown. `.summon`-ing a
player mid-trade would leave the partner with a `trade_partner_entity_id`
pointing at a freed id and no `onTradeResults(Cancelled)`. **Fixed** in the
primitive (between the confirmed enqueue and the teardown, so the
"a rejection changes nothing" contract holds) and in `handle_dial_gate`,
which had the same omission. Guarded by
`accepted_transfer_cancels_an_open_trade_before_teardown` and its rejection
mirror.

### Must-fix — test review

**T1. The primitive's only pre-teardown mutation was unreachable from every
test.** `spawn_player` never set `player_id`, so the bandolier flush was dead
code in all 16 cell-side tests — the "origin state completely unchanged"
claim was vacuous for the one statement that can actually mutate anything.
**Fixed:** the fixture now sets `player_id` and seeds a dirty bandolier slot,
`OriginState` snapshots the dirty marker (and the trade partner), and the new
`departure_cleanup` module asserts both that an accepted transfer flushes
*before* the `GateTravel` and that a rejected one does not flush at all.

**T2. The stale-instance degrade test only proved the entity landed
somewhere.** The degraded path allocates a genuinely new instanced space, so
it must also emit `SpaceData` and spawn instance NPCs — which hinges on
`is_instanced` deriving from `joined_instance.is_none()` rather than
`destination_space_id.is_none()`, a one-token regression whose symptom is a
live instance the BaseApp never registers. **Fixed:** the test now asserts
`SpaceData == vec![joined]` and that the new space belongs to the named
world. Revert-verified.

**T3. The ordering test pinned the un-spaced abort as acceptable.** Correct
about ordering, wrong about the outcome: the abort returned `Ok` with the
session still live and the entity in no space — a client whose position
updates are all dropped as `EntityMissing`, which is what criterion 3
forbids. **Fixed in the code, not the test:** the abort now ends the session
(`abandon_unspaced_session`) so a reconnect recovers, and the worknote's
"strictly safer" claim about the hoist is corrected to "lateral on failure
shape". New guard:
`aborted_transfer_ends_the_session_rather_than_stranding_an_unspaced_client`.
The pre-existing `gate_travel_without_active_player_id_aborts_before_persist`
was updated to the new contract.

### Should-fix — all taken

- **Determinism test was theatre.** Re-running a static lookup 32 times
  cannot catch an arbitrary-`HashMap`-entry bug (iteration order is stable
  within a process). Replaced with A<B<C, empty A, assert the default moves
  to B — which separates `.min()` from "first created" from "any entry".
- **The reap test could not tell `||` from `&&`.** It removed both
  `entity_to_addr` and `connected`. Now one helper, four interleavings: both
  dropped, mapping only, session only, and recycled-to-another-session.
- **`make_socket` discarded the typed handle**, so "no RESET_ENTITIES" was
  only inferred. The fixture now keeps an `Arc<TestTransport>` and asserts
  `send_count_to(addr) == 1` on the committed path and `is_empty()` on the
  abort.

### Nice-to-have — taken

- `create_startup_spaces` now skips (with a warn) an instanced world listed
  as a startup space. `world_spaces` entries are never invalidated by
  `destroy_space`, so a cached instanced world would hand out a dangling
  space id forever after its first emptying. This is the one input that makes
  the `handle_create_entity` `Err` arm reachable for GM transfer, so it turns
  the "unreachable" argument under *Known gaps* from data-dependent into
  code-enforced.
- `space_transfer` is now `pub(crate)` (it was crate-external `pub` with no
  external consumer — an ungated destructive entry point). It carries
  `#[allow(dead_code)]` until P46 wires it up; **P46 should remove that
  attribute.**
- The `&mut SpaceManager` borrow held across both `.await` points is now
  documented as the load-bearing invariant that closes the
  validate→enqueue→destroy window — a refactor to `&SpaceManager` +
  re-acquire would silently reopen it with no test failing.
- `origin_space_id` now comes from the authoritative `entity_space` index;
  both reviewers then flagged the extra rejection arm as unreachable, so the
  two lookups were collapsed into one `zip` with a single arm.
- Worknote §5's "strictly safer" wording corrected.

### Tracked follow-up — NOT fixed here (reviewer agreed it is out of scope)

- **The same recycled-id hazard exists on the `DisconnectEntity` queued by
  `destroy_client_entities`**: it names an entity id that may already have
  been reissued by the time the cell processes it. Same shape as S1, but on a
  path this packet does not own.
- `BaseToCellMsg::CreateEntity.reply_tx` still has no failure channel (see
  *Known gaps*).
- `world_spaces` is still never invalidated by `destroy_space`; the
  `create_startup_spaces` guard above closes the only route that reached it,
  but the underlying asymmetry remains.
