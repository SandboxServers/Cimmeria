## The API — what P45/P46 depend on

```rust
// crates/services/src/cell/space_manager/queries.rs
// re-exported as crate::cell::space_manager::PlayerNameLookup

#[derive(Debug, Clone, PartialEq, Eq)]
pub enum PlayerNameLookup {
    Found { entity_id: u32, space_id: u32 },
    InTransition { entity_id: u32 },
    NotFound,
    Ambiguous { entity_ids: Vec<u32> },
}

impl SpaceManager {
    pub fn find_online_player_by_name(&self, name: &str) -> PlayerNameLookup;
}
```

Takes `&self` — safe to call from a read borrow before any mutation, which
is what P45's "validate the destination before tearing down origin state"
ordering needs.

### Mapping to legacy's GM strings (P46's job, stated here so the contract is unambiguous)

| Variant | Legacy source | Suggested `.goto` / `.summon` feedback |
|---|---|---|
| `Found { entity_id, space_id }` | `PlayersByName[name]()` with a live space | proceed; then `"Teleporting to player <%s>"` / `"Summoning player <%s>"` |
| `NotFound` | `name not in PlayersByName` (`Player.py:307`, `:330`) | `"Player is not available on this CellApp"` |
| `InTransition { entity_id }` | `destination is None or destination.space is None` (`Player.py:312`, `:335`) | `"Player is not on any reachable space"` |
| `Ambiguous { entity_ids }` | *no legacy equivalent* — legacy's dict cannot hold duplicates | new wording needed; suggest `"Multiple players named <%s> -- refusing to guess"`. Deviation from legacy is unavoidable here and should be recorded in P46's notes rather than silently mapped onto one of the two legacy strings. |

### Three things P45/P46 must not get wrong

1. **Use the returned `space_id`, don't re-derive it.** `Found` carries the
   destination player's *actual* instance. Re-resolving from the world name
   goes through the first/default-loaded-instance rule (D15's
   `.gotolocation` behavior) and will drop the GM into the wrong copy of an
   instanced world. This is exactly P45's "destination instance ID is exact"
   acceptance criterion; the lookup hands it to you for free.
2. **`Ambiguous` is a fourth arm, not an `_ =>` catch-all with the
   not-found message.** Collapsing it reintroduces the silent-pick failure
   the guard exists to prevent, just one layer up.
3. **The lookup says nothing about NPC-vs-player rejection (D15).** It only
   ever resolves player entities, so it cannot *return* an NPC — but the
   *moved* entity in `.goto`/`.gotolocation` is the caller-or-selected
   target, which P26's precedent allows to be an NPC. D15's players-only
   restriction for cross-world legs is P46's check on that entity, not
   something P44 enforces.

## Behavior implemented

- **Scope: service-wide.** The scan walks `self.spaces.values()` — every
  space loaded on this CellApp, including on-demand instanced spaces the
  caller never named — matching P04's `.players` CellApp-wide scope and D05
  ("online players across loaded spaces on this service"). Not restricted to
  the caller's own space.
- **Exact, case-sensitive matching**, ported from legacy's raw
  `name in PlayersByName` dict-key test. Confirmed by direct read rather
  than assumed: `Global.py:5` (`PlayersByName = {}`), `SGWPlayer.py:264`
  (`PlayersByName[self.playerName] = weakref.ref(self)`), `SGWPlayer.py:268`
  (`del PlayersByName[self.playerName]`), `Player.py:307`/`:330` (the
  membership tests). Nothing in the legacy cell tree lowercases, strips or
  otherwise normalizes either the registered key or the probe, so
  case-sensitivity is ported behavior, not an omission. No case-insensitive
  fallback was added.
- **Keyed on `CellEntity::character_name`**, which is player-exclusive (NPC
  display names use the separate `npc_name` field) and is written only by
  the `BaseToCellMsg::InitPlayerState` arm. The lookup deliberately does not
  *also* require `is_player`; `space.players` membership is the authoritative
  reachability signal and is what separates `Found` from `InTransition`.
- **Deterministic under a uniqueness violation.** All matches are collected
  before deciding. Two-plus matches → `Ambiguous` with ascending-sorted ids
  plus a `tracing::error!` on target `player.name_lookup` (negative-logging
  convention: `player_name`, `entity_ids`, `match_count` fields). The scan
  walks `HashMap`s, so "first match wins" would have been genuinely
  nondeterministic per process, not merely ugly.

## Known gaps / divergences

### 1. `InTransition` is correct but not production-reachable today

Same class of finding as P04's `.players` "In transition" gap, restated
precisely so P46 isn't written on a false assumption:

- The **data model** produces the state — `disconnect_entity` removes the id
  from `space.players` before `destroy_entity` drops the named entity — and
  the variant is decided by that real predicate, not a synthetic flag. The
  test builds the state exactly the way `disconnect_entity` does.
- But the cell service is a single task holding `&mut SpaceManager` across
  that teardown, so no other handler currently observes the window.
- **The case a GM would actually hit does not land here.** `.goto Bob`
  while Bob is mid-gate-travel returns `NotFound`, because the cell destroys
  Bob's old entity and `create_entity` builds a fresh one with
  `character_name: None` until `InitPlayerState` re-caches it. Legacy, whose
  dict key survives until `disconnected()`, would have said "not on any
  reachable space". So P46 will emit legacy's *first* error string in a
  situation where legacy emitted the second.

Closing it requires a name roster that outlives the entity — new cell-side
state, out of scope here and the same kind of invented tracking P04 was
explicitly told not to build. Recommend the coordinator record it as a
tracked follow-up rather than expanding P44 or P46. The `InTransition`
variant is the splice point: whichever packet adds the roster changes only
the lookup body, and P46's error mapping is already correct for both.

### 2. `Ambiguous` has no legacy wording

Legacy's dict structurally cannot hold duplicates, so it never had a
message for this. P46 needs to author one. Flagged rather than pre-decided,
since command wording is the coordinator's/P46's call.

### 3. Exclusions honoured as specified

No offline or DB-backed lookup, no cluster-wide routing (D05 defers both),
no fuzzy/partial/prefix matching, no case-insensitive fallback.
