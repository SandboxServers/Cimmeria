## Hypothesis / evidence (from the audit + a fresh read of current source)

1. **All six pre-existing groups' field lists already match legacy exactly.** Compared
   `stat_set()`'s six arms field-by-field and in-order against
   `entityPrimaryStats`/`entitySpeedStats`/`entityArmorStats`/`entityQRStats`/
   `entityAbsorbStats`/`entityStealthStats` (`Entity.py:309-431`) — every name and order matches.
   No fields needed correction. This packet's job was verification (regression tests), not a
   rewrite, per the ledger's own framing.
2. **`.stats` is genuinely new**, confirmed absent from `registry.rs`/`dispatch.rs`/`stats.rs`
   before this packet. `entityStats` (`Entity.py:294-306`) is a 4-field wrapper around the same
   `entityShowStats` helper the other six use: `health`, `focus`, `healthRegen`, `focusRegen`, in
   that order. Cross-checked the exact label strings against `deprecated/python/Atrea/enums.py:
   302-305` (`health = 7`, `focus = 8`, `healthRegen = 9`, `focusRegen = 10`) — the lowercase-
   camelCase labels match the `HEALTH`/`FOCUS`/`HEALTH_REGEN`/`FOCUS_REGEN` constants already
   defined in `crates/entity/src/stats/stat_ids.rs:18-21`, no new stat-id constants needed.
3. **Dead-code pattern identical to the one P02 fixed in `query.rs`.** `stats.rs`'s pre-existing
   `show()` took `target_id: Option<u32>` with a `.unwrap_or(caller_id)` "use caller" fallback, but
   every command routed to it (`primarystats` … `stealthstats`, now `stats`) is registered
   `Target::Being` — a typed, non-`None` target kind. `dispatch::resolve_target` (`dispatch.rs:
   125-158`) returns `Err` before `exec` is ever reached when a typed command has no current
   selection; it never returns `Ok(None)` for a typed spec. So `target_id` is unconditionally
   `Some` by the time it reaches `stats::show`, making the `unwrap_or` branch dead — same shape as
   P02's `query::facing`/`query::combat_info` fix-up. Applied the identical fix: `show` now takes
   `target: u32` directly; `dispatch.rs`'s call site `.expect("Target::Being guarantees a resolved
   target")`-unwraps at the one place that legitimately knows the invariant holds.
4. **The "missing-stat" acceptance criterion cannot be reached through a real `CellEntity`
   fixture under the current data model — confirmed, not assumed.** Read `CellEntity::new`
   (`construction.rs:20-34`): the single constructor unconditionally sets
   `stats: StatList::new()`. Read `StatList::new()` (`stat_list.rs:23-151`): it inserts every
   stat id used by all seven groups (`.stats` through `.stealthstats`) unconditionally — cross-
   checked every constant against the template block, all present. Read the rest of `stat_list.rs`
   for a removal API: none exists (`get`/`get_mut` only; no `remove`). `CellEntity.stats` is a
   `pub` field but `StatList`'s internal `HashMap` is private with no partial constructor exposed.
   So from `crates/services` (this packet's entire owned-path scope), there is no way to build an
   entity whose stat block is genuinely missing an entry any of these seven commands would look up
   — every relevant `entity.stats.get(id)` call is unconditionally `Some` today.

## Design decisions

- **`.stats` registered identically to the other six**: `Target::Being`, arity `0`/`0`, placed
  immediately before `.primarystats` in `registry.rs`'s "F. granular stat readouts" section (the
  audit's own ordering: `.stats` listed first, ahead of `.primarystats`). Dispatch routes it
  through the same `stats::show` handler via one extended match-arm pattern in `dispatch.rs`.
- **`show()` signature fix (`Option<u32>` → `u32`)** — see hypothesis point 3. This is a behavior-
  preserving refactor (the fallback branch was unreachable in production either way; the fix only
  removes dead code and makes the invariant explicit at the type level), not a functional change,
  so it doesn't touch any of the six groups' already-correct field lists.
- **Missing-stat coverage split into two layers, not one end-to-end fixture** (see hypothesis
  point 4):
  - Extracted the per-line formatting logic (`Some(s) => "label: cur/max"`, `None => "label: n/a"`)
    out of `show()`'s loop body into a small private `format_stat_line(label, Option<&Stat>) ->
    String` function, and added `#[cfg(test)]` unit tests directly in `stats.rs` (co-located with
    the private fn, standard Rust convention — `console::tests::p03` can't reach a `stats`-private
    item since it's a sibling, not a descendant, module of `stats`) pinning both branches,
    including `legacy_p03_format_stat_line_reports_na_when_absent`. This is real production code
    under test, not a mock — it's the exact branch that would execute if a stat were ever absent.
  - Did **not** invent a `StatList::remove` (or similar) API in `crates/entity` to force an
    end-to-end fixture — that crate is outside this packet's owned paths, and adding new public
    surface to a shared crate other packets/workers depend on needs coordinator sign-off, not a
    unilateral addition under a "verification packet" mandate. Flagged in the Handoff as a
    proposal, not implemented.
- **`.stats`'s command-not-found path** (`stats::show`'s `"{cmd}: no entity."` branch, when the
  resolved target id no longer exists in the space) reuses the exact same defensive check the six
  pre-existing groups already had — not new logic, just confirmed still correct after the
  signature change and covered by a dedicated regression test since it wasn't covered before.

## Planned tests (see Handoff for actual results)

Filter prefix `legacy_p03_`. Planned before writing:

- One data-driven test asserting the exact ordered feedback-line list for all 7 groups
  (`.stats` + the six pre-existing) against a freshly spawned target's default `StatList::new()`
  values — catches any drop/add/reorder/mis-value in `stat_set()`.
- Selected-target-vs-caller isolation: mutate the NPC target's `HEALTH` to a value distinct from
  the GM's own untouched default, confirm `.stats` reports the target's value and never the
  caller's.
- Caller-only recipient: every `EntityMethodCall` from a stat-dump command routes to the GM's
  entity id, never the target's.
- Vanished-target defensive path: `stats::show` called with a target id no longer present in the
  space reports `"<cmd>: no entity."` rather than panicking.
- Two co-located unit tests in `stats.rs` for `format_stat_line`'s `Some`/`None` branches (the
  "missing-stat" acceptance criterion, see Design decisions above for why this is unit-level, not
  fixture-level).

Did not add a redundant "typed command requires target" test — `cell::console::tests::mod::
typed_command_requires_target` already exercises exactly this rejection path using `.primarystats`
as its example command (pre-existing, unmodified), matching P02's precedent of not duplicating
existing framework coverage.

Test lane: `cargo check -p cimmeria-services`, `cargo test -p cimmeria-services --lib legacy_p03_
-- --test-threads=1`. No live-DB tests — entirely in-memory stat readout, no persistence path.
