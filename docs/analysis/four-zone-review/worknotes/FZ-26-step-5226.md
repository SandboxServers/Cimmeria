## 3. Credit: complete_objective, not advance_step

- `advance_step` is wrong here: 5226 is the terminal step, and advance_step force-completes open objectives without running the auto-complete (CONFIRMED engine note), so it would leave 1664 open.
- `complete_objective` flips one objective, then (`progression.rs:463-505`, CONFIRMED) computes `all_required_complete` over `active_objectives` filtered to non-optional and calls `mission.complete()` when true. With 6061 + 6062 both required and nothing else on 5226:
  - first report: 6062 still active -> mission stays open;
  - second report: all required complete -> 1664 completes, step-5226 completed frame is sent.
- So one `complete_objective` per NPC is enough. Do NOT use `complete_mission` on the first report (it force-completes the other objective and skips its report). `complete_mission` on the second would also work, but adds a second chain per NPC and gains nothing.
- Guard the vacuous-truth branch (`required_count == 0`): not reachable here, both objectives are required.
- Auto-complete runs `mission.complete()`; the mission-completed event path (`fire_mission_completed`) is not re-verified here. RISK: build packet must assert in a replay test that 1664 reaches `completed` and persists `current_step_id` NULL.
