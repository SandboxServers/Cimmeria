# UE3 backport notes, checked against our client

Source: game-archaeology-specialist, 2026-10-31. Read-only: repo docs, agent memory and lab/DLL source. No Ghidra session and no lab run happened for this pass, so nothing here is newly confirmed in the binary; every "VERIFIED" row cites an earlier static or live finding. A second pass the same day read the binary with headless Ghidra (static only, no client run); its results are in [Static pass 2](#static-pass-2-headless-ghidra-2026-10-31) and the rows below point to it. A third pass the same day ran live probes L1-L8 on the lab client; its raw results are in [Live pass](#live-pass-lab-client-2026-10-31) and override the static rows where they differ.

The autopilot research notes (deep-unreal.md, deep-bridge.md, deep-control.md) named UE3 APIs from general knowledge. This page replaces those guesses with what we actually know about SGW.exe (UE3 build about 3004, i686, no ASLR, image base `0x00400000`).

Labels:

- **VERIFIED**: an address or behaviour confirmed in our binary or on the live client, with a citation.
- **PARTLY**: part of the need is confirmed; the rest is static-only, inferred or missing.
- **UNKNOWN**: nothing in our docs or code. The research notes' guess is not evidence.

## Corrections to the research notes

1. **The UI is CEGUI driven by Lua (`lua51.dll`), not Scaleform/GFx.** deep-unreal §2 names GFx; no GFx exists in this client. Evidence: CEGUI `DefaultLogger::logEvent` `0x012129E0` and the Lua IAT entries (`lua_pcall` `0x017F0228`) in `docs/reverse-engineering/findings/client-instrumentation-entry-points.md`; every lab UI tool reads windows through Lua (`crates/lab/src/supervisor/flows/ui_state.rs:146`).
2. **UE3 reflection is present.** deep-bridge.md:228 says build 3004 has "no reflection API". Wrong: `UObject::ProcessEvent` is `0x004e06a0` (vtable slot 58, UObject vtable `0x0180fe54`), and `GObjObjects` `0x01edc69c` and `GNames` `0x01ecade0` are both mapped (`client-instrumentation-entry-points.md`, `docs/reverse-engineering/address-map.md`). Trap: `0x004513d6` is a wxWidgets thunk, not ProcessEvent.
3. **Game entities are BigWorld entities bridged to UE3 actors.** Iterate `g_EntityManager` (`0x01ef244c`), not `FActorIterator`, for anything gameplay-facing. `Entity+0x08` is the actor. `ABigWorldEntity` (vtable `0x01895e3c`) turns UE3 collision off (`address-map.md`), so a UE3 trace may not hit NPCs at all. Static pass 2, S1.6: it sets one component's `CollisionResponseFlags` (`+0x250`) to `0xFFFFC004`; whether traces then miss the entity is untested live.
4. **`0x01EE2684` is `GWorld` (a `UWorld*`), not a `WorldInfo*`.** Settled statically in S2.5: the `!GWorld->NetDriver` assert reads `[0x01EE2684]+0xD0`, and every trace passes it as the `UWorld` `this`. The address map's "WorldInfo*" label is wrong; the lab's `GLEVEL_PTR_VA` reading is right. WorldInfo is `Actors[0]` of the persistent level at `+0x50`.
5. **The camera actor pose can read all zeros on the live client** (`docs/guides/live-research-lab.md` 889, 925). `GetPlayerViewPoint`-style reads through that actor are unreliable. The working readout is the controller's camera object (below).
6. **The game clock most likely to work is BigWorld's, not `WorldInfo.TimeSeconds`.** The `tickSync` handler `0x00dd6d00` writes `gameTime` at `+0x32c` (`docs/analysis/crafting/worknotes/cr-02.md:34`). The `WorldInfo.TimeSeconds` offset is not known.

## Static pass 2: headless Ghidra, 2026-10-31

Source: game-archaeology-specialist, headless Ghidra on the QA `SGW.exe` (`analyzeHeadless -readOnly -noanalysis` with `tools/re/ghidra-headless/Probe.java`). Static only: no client, no x64dbg, no lab. ### S1. Traces (rows 5, 6)

1. **Script natives.** `AActor_execTrace` `0x006e7be0`, `AActor_execFastTrace` `0x006e1490`, `AActor_execTraceActors` `0x006e7280`, `AActor_execTraceComponent` `0x006e6eb0`, `UPrimitiveComponent_execSetTraceBlocking` `0x0061d830`. Registration string `intAActorexecTrace` at `0x0181d718`.
2. **`AActor::Trace` helper `0x006e6d20`** (`__thiscall`; args `out HitLocation, out HitNormal, End*, Start*, bTraceActors, Extent*, TraceHitInfo*, options`). Flags: `bTraceActors == 0` → `0x2086`; else `0x20be`, `| 0x20` if `options & 8`. Always `| 0x4000`; `| 0x800` when hit info is wanted; `options & 2` → `| 0x8000`; `options & 1` → `| 0x20000`; `options & 4` → clear `0x2`. Corrected design facts:

1. **Pawn traces need `TRACE` bit `0x1`.** `0x20be` ("actors") misses BigWorld pawns; `0x20bf` hits them. Pass the own pawn as Source to exclude it.
2. **A BSP hit reports WorldInfo as `Actor`** and the BSP node in `Item`; test `Item >= 0` rather than `Actor == 0` for "hit the level".
3. **Loading: do not poll `0x01EE2B6C` from the tick bridge.** Use a `GWorld` pointer change (and then `Event_World_Loaded` or the existing Lua checks).
4. **Mouse-look scale is 521.5 counts per radian** at gain 20; the window registry holds about 21k windows, so a native walk must page or filter.
