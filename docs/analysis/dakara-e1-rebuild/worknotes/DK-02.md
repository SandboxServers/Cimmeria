### Mesh and prefab names (the landmark census)

`extract_actors` cannot name a mesh. Two throwaway scripts (not committed) read the names with the Python parser. Set up once: `python3 -m venv $S/venv && $S/venv/bin/pip install lzallright` (the parser needs it for LZO-compressed tiles). Both run as `$S/venv/bin/python -I script.py <repo>/tools <map dir> <out.tsv>`, with `sys.path.insert(0, <repo>/tools)` and `from upk_parser import PackageReader`:

```python
# prefabs: every PrefabInstance and the import its TemplatePrefab points at
for f in sorted(glob(mapdir + "/*.umap")):
    p = PackageReader(f); p.parse()
    for a in p.extract_actors({'PrefabInstance'}):
        t = a['properties'].get('TemplatePrefab', 0)               # negative = import index
        name = p.get_export_full_path(p.imports[-t - 1])            # e.g. GLB-Global.GLB-RingTransporter00_Pf0
        ue = a['location']; yaw = a['properties'].get('Rotation', (0, 0, 0))[1] * 360 / 65536
        bw = (ue[1] / 100, ue[2] / 100, ue[0] / 100)                # (ue.y, ue.z, ue.x) / 100
```


### Floor and navmesh checks for a candidate point

For each candidate `(x, z)`: `obj_slab <obj dir> --at p=X,Yhint,Z,5,40 --column X,Z` lists every surface at that column; each upward-facing surface height is probed with `nav_inspect <nav> --probes <file> --h-tol 1.2 --v-tol 1.0 --quiet`, and the surface that returns `ok` is the floor and gives the component. The final rows were re-run with the real seed tolerances (`--h-tol 1.2 --v-tol 4.0`, the `is_point_valid` window) over the committed probe files:

```bash
$BIN/nav_inspect data/spaces/dakara_e1.nav --probes docs/analysis/dakara-e1-rebuild/placements/data/Dakara_E1_probes.txt --h-tol 1.2 --v-tol 4.0 --quiet
$BIN/nav_inspect data/spaces/dakara_e1_storyrm.nav --probes docs/analysis/dakara-e1-rebuild/placements/data/Dakara_E1_StoryRm_probes.txt --h-tol 1.2 --v-tol 4.0 --quiet
$BIN/nav_inspect data/spaces/dakara_e1.nav --max-components 800            # the component table
$BIN/nav_inspect data/spaces/dakara_e1.nav --quiet --gap-pair 279,324 --gap-h 6 --gap-v 3 --gap-count 6
$BIN/obj_slab $S/out/StoryRm --at room=70.6,0,30.2,16,3 --levels 0.5       # the room's floor levels
```

`nav_inspect`'s `dy` is the probe's height minus the polygon's: negative means the polygon is **above** the probe, positive means below. Expected result: every row `ok` except PL-DK-A-05 (a prop inside a tent, the polygon 5.5 m above), with the components in the ledger.

### The cover packs

`covernodes_nikols.pak` and `covernodes_sdeiter.pak` are ZIP files whose entries are named `_<Name>-<w>-<h>`; `covernodes_pault.pak` is a 22-byte empty ZIP. Listing them with `zipfile.ZipFile(path).namelist()`, stripping the leading `_` and trailing `-<w>-<h>`, gives 1,337 distinct template names. Joining those names against the mesh census gives 58 matches covering 3,130 of the 22,505 direct meshes. No entry name carries a map, world or Dakara token.

The [world-map art note](../../../../.claude/agent-memory/game-archaeology-specialist/world-map-art-layout.md) says tiles live in `MapData.upk`; reading them for Dakara_E1 was outside this packet's tool set. 2. **Door sides of the camp tents.** The prefab tents (`JF-MilitaryTent00_Pf0..2`) carry three `DoorwayPrecipitationPlanes` stubs each (collision-off, so `extract_map` and `archetype_census` skip them). Their local offsets, composed with the same `JF-MilitaryTent00` mesh, would give door sides for the direct tents in camp A. Needs a small reader; not in the standard tools.

Is the gap the arch pillars (agent radius 0.6) or a missing off-mesh connection? `nav_inspect --gaps` names the places; `obj_slab --at` on (-214.2, -13.4, 132.0) would say whether the opening is wide enough for a player. This decides how DK-20 spawns hostiles for mission 1647.
4. **SG-18 area.** Is `HB-` Tau'ri? The prefix is the only evidence. A glance at the in-client art of `HB-Humvee_02` and the containers would settle it in a minute.
5. **Is the camp-A tent assignment what the original had?** Only the owner's playtest can say.
