# Startup launcher update requirement

2026-10-23 owner request: check for launcher updates on launch; offer one main-page Update and restart action; require it before Play. Bundle with Windows path display fix in one PR.

Use the existing signed updater and revision-bound inspect/check/prepare/apply commands. The application starts with Play gated, inspects durable updater state and automatically checks the feed once when safe. A staged verified package resumes at ready; active/reconciliation states are inspected, never replayed. The main-page action runs prepare then apply sequentially, stopping on any uncertain/error reply. It provides immediate feedback and ignores duplicate clicks. A button labelled Check for updates after a failure performs inspection/check only; discovering an offer requires a subsequent Update and restart press. Keep Settings recovery controls; they are useful after failures.

Native Play admission and its snapshot must also refuse known available/ready offers, active updater phases and failed attempts retaining an offer. Retain a known offer during a new check and on network failure, so a failed refresh cannot bypass a mandatory update. A successful no-newer check or startup acknowledgment of the new version clears the requirement. No new persistence/IPC fields are needed.

A check failure with no previously known update allows Play after the bounded request finishes, with visible failure/recheck feedback; offline startup alone does not invent an update. Development builds with no configured updater remain playable even after reopening an inactive persisted offer; active/reconciliation work still blocks them. The native host supplies configuration to inspection/admission, never through IPC. No downloads, replacement or restart occur automatically: these require the owner's requested button press. Existing cryptographic verification and replacement rollback remain unchanged.

Tests: frontend startup sequencing, duplicate clicks, prepare-before-apply, failure/lost replies, retained-offer gating, no-offer/offline/development states and refresh resistance; native admission tests for known offers, readiness and failed rechecks; mutation proofs plus frontend build and JS logic UAT. Docs map: desktop updater contract, README, launcher guide/self-update, UAT checklist and project memory. No real release or production replacement will be performed.
