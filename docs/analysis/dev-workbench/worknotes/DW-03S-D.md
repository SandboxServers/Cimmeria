# DW-03S-D: Direct world-entry and Base send origins

> Status: implemented locally, pending review and integration. No live lab action.

Direct encrypted sends in the owned character, world-entry and Base handlers copy origin at build time. The packet-local world-entry reliable registration compares the original sequence Arc plus boot, generation, peer and admission time under the connected lock before inserting ciphertext after send. The private Base-session `shadow_register_reliable_send_for_session` cannot be called across the crate boundary; the packet-local helper uses the public Channel API. This preserves the window and ciphertext behavior but does not emit that helper's detailed `mercury.reliable_send` event fields.

The two pre-Phase-3 login sends remain `send_to_pre_phase3`. Missing Phase 3 seed or stale caller key leaves a direct send untagged. If eviction finds its original state replaced before packet construction, its teardown send is untagged. Full encrypted-send coverage remains DW-03S-F's task. In `crates/base-world-entry/src/base/world_entry/enable_entities.rs`, the create-player branch peeks pending content before calling the already origin-aware `send_reliable_to_addr` helper. A same-peer replacement between that peek and the helper's session lock can pair A's content with B's helper-captured ticket. This helper route is not a direct `send_to` family and needs an expected-content-owner fence in DW-03S-F before any `coverage_complete=true` claim. The D tests and current proof wrapper do not by themselves close that gap.

Regression: paused A world-entry send across same-peer B replacement preserves A and cannot put A ciphertext in B's window; fragmented world-entry packets share A but have distinct wire fingerprints; failed send adds no successful row/window entry. Base eviction paused/failure fixture covers teardown, and a source census checks each direct-send family. No live client, native receive hook or visual UI was used.

Checks (PowerShell build lane, packet order): `cargo fmt -p cimmeria-base-world-entry -p cimmeria-base`: status=ok exit=0; `cargo clippy -p cimmeria-base-world-entry -p cimmeria-base --all-targets -- -D warnings`: status=ok exit=0; `cargo test -p cimmeria-base-world-entry direct_send_origin`: status=ok exit=0, 4 passed; `cargo test -p cimmeria-base direct_send_origin`: status=ok exit=0, 2 passed. Compatibility: `cargo test -p cimmeria-base log_off`: status=ok exit=0, 2 passed; `cargo test -p cimmeria-base-world-entry gate_travel`: status=ok exit=0, 38 passed.

The existing Base login module had 699 lines before the ticket change and exceeded the hard 700-line cap after capture. The account `handle_log_off` teardown was moved to the packet-owned `login/eviction.rs` with the old `login::handle_log_off` entry point re-exported; behavior and call signature remain the same.
