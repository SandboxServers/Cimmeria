# DW-03S-D: Direct world-entry and Base send origins

> Status: implemented locally, pending review and integration. No live lab action.

Direct encrypted sends in the owned character, world-entry and Base handlers copy origin at build time where their content owner can be established. The packet-local world-entry reliable registration compares the original sequence Arc plus boot, generation, peer and admission time under the connected lock before inserting ciphertext after send. The private Base-session `shadow_register_reliable_send_for_session` cannot be called across the crate boundary; the packet-local helper uses the public Channel API and preserves its `send_site`, send kind and `mercury.reliable_send` context.

The two pre-Phase-3 login sends remain `send_to_pre_phase3`. Missing Phase 3 seed or stale caller key leaves a direct send untagged. If eviction finds its original state replaced before packet construction, its teardown send is untagged. The `world_entry/reanchor_player.rs::handle_reanchor_player` Cell event supplies an entity ID but no immutable event-generation ticket; its direct send stays untagged even when a session seed exists. Full encrypted-send coverage remains DW-03S-F's task; this known gap blocks `coverage_complete=true`.

Content captured before awaits now carries its original sequence Arc and origin. `map_loaded` and both character-list reply paths check that owner again before building a packet from the later connected state. The `enable_entities` create-player branch and character-visuals branch pass an owner-fencing transport to the origin-aware reliable helper. If that helper builds using replacement B after content came from A, the fence refuses the send before proof or ciphertext registration. The exact create-player helper path remains a content-ownership coverage boundary for DW-03S-F to audit; the local test proves its B-ticket refusal, not complete outbound census.

Separate gameplay-state races predate this packet: `map_loaded` can update the current `entity_to_addr`/pending-ready state after a send await; `enable_entities` can flip replacement B's `char_list_sent` after its await; reanchor can resolve a reused entity/address to B because the Cell message lacks a generation; and Base login/dispatch teardown can act on a replacement after awaits. These must be owned by later behavior fixes. This packet makes their wire proof fail closed where possible and does not claim those gameplay transitions are fixed.

Regression: paused A world-entry send across same-peer B replacement preserves A and cannot put A ciphertext in B's window; fragmented world-entry packets share A but have distinct wire fingerprints; failed send adds no successful row/window entry. An A-content/B-helper-ticket fixture refuses the send, and a reanchor fixture records an untagged gap. Reliable-window context retains send site and kind. Base eviction paused/failure fixture covers teardown, and a source census checks both conversion and owner-guard choices by family. No live client, native receive hook or visual UI was used.
