# DW-06 mission X-ray handoff

The local `/workbench/api/v1/missions` API now reads `resources.missions`, ordered `resources.mission_steps`, mission-scoped `resources.content_chains`, and the visible tracker for one selected positive mission ID. The five evidence layers remain independent. The tracker title matches `mission_defn` (mission 622 is `Arm Yourself!` with `mission_label=General`); a failed `missions:` UI section invalidates even partial tracker rows. A pure read model shows a persisted active step and tracker text disagreeing and treats missing definition data as unknown. No seed rows or mission mechanics changed.

The live route has no trusted client-to-server session binding producer yet, so it does not query a player's `sgw_mission` row or report a live step disagreement. DW-06A is the separately gated 40k follow-on after DW-03S-B; it must use the exact generation and stable Cell travel epoch before and after the DB read. The model accepts a bound context for that later integration and requires unique agreement of session and player entity in `server_sessions` before a player-ID query. Wire mission packets and client mission-ID state remain unknown until DW-08 and a supported client reader respectively. The route does not drain the shared packet tap. Mission-scoped chain references are only the links directly resolved by `resources.content_chains`; this does not claim to enumerate every cross-scope chain with a mission condition.
