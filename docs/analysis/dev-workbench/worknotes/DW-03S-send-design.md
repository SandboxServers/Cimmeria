# DW-03S send-origin and travel-epoch redesign

> Type: design handoff. Date: 2026-10-16. Scope: packet contracts and ledger only. Static source review, no build or live client run.

## Evidence and decision

`evidence/DW-03S-E.md` (merged PR #1750) traced `crates/mercury/src/transport.rs::Transport::send_to`: only encrypted bytes and peer cross the awaited transport. `crates/base-session/src/base/helpers/mod.rs::collect_pending_retransmits` returns `Vec<Bytes>` without a channel origin. `BaseService::start` projects the same bidirectional transport into the receive loop, Cell fan-out and sweepers. A BaseService-only wrapper that looks up the peer after await can therefore misattribute a paused A send to same-peer B. The sampled `mercury.packet` event and reliable-window registration do not constitute a complete post-send ring.

The replacement contract adds `Transport::send_to_with_origin` as an opt-in, object-safe method with an immutable `SendOrigin`. Phase 3 stores only the fixed generation seed in `ConnectedClientState::extensions`; each sender combines it with the current player entity while the originating session supplies key/sequence/ACK or cached retransmit ciphertext. The Base proof wrapper records only full successful sends whose actual destination equals the immutable origin peer; swapped recipient tickets create `origin_peer_mismatch` coverage gaps, never relabelled proof rows. It also counts untagged/failed/partial/dropped paths as coverage gaps. P builds the seam, G builds boot/generation and observer, H preserves origins through session helpers and retransmit, D covers direct world-entry/Base sends, F audits Cell fan-out and all remaining production send sites, and S publishes only a fail-closed snapshot. Historical A proof is filtered from current B roster; no post-await address lookup is allowed.

GateTravel's Cell producer may enqueue a transition and tear down the origin before Base consumes the message. `ConnectedClientState.world_name`, `world_entry_sent` and displayed roster status can remain unchanged in that interval. The common authoritative source is `SpaceManager::destroy_entity`; its player identity is read before removal. T-C initializes the first-player baseline **after** the Cell lifecycle stamps `player_id`, then maintains a bounded per-player epoch and `InProgress` state through origin teardown. T-O-M/C/S0/S1/I/V/F/Q carry an opaque per-create incarnation, stamp the Cell source before teardown, validate it before Base reservation, and require Cell high-water owner fence, accepted ack and current-occupant query. T-K makes a rejected or missing Cell create reply terminal before O-F activates real Cell rejection. T-DB0 records the selected player/claim before the first await while `active_player_id` may still be None; T-DB2 invalidates both active and in-flight claims at takeover, and T-DB1 claims the trip before destination create and conditions its awaited arrival UPDATE on that exact owner; any missing DB fence blocks proof. T-P1 returns the epoch and incarnation atomically with destination creation, T-P2 captures the originating generation before Cell await and rejects an old receipt after relog, even when peer/player/entity numbers match. `onClientReady` is argument-free: a token read from B's pending slot cannot prove a delayed ready came from B. T-A records ingress without inventing trip identity and latches every later same-generation trip as `ready_ambiguous`; T-R never settles or acknowledges an ambiguous trip. The queued-A-at-ingress, staged-B, dispatch-A regression keeps B `InProgress`/unknown. Without a proven trip-specific signal, that generation does not regain travel proof until reconnect. X requires a matching stable Cell/Base epoch, and B compares it before/after every joined read. A same-world round trip increments the epoch. Missing/evicted state fails closed.

## Verification and unresolved implementation facts

- Source files/functions in the evidence table were inspected. The `SessionExtensions` slot exists and avoids editing roughly 29 `ConnectedClientState` fixture literals. `LabState::lab_query` already forwards a typed read to Cell. This revision changes no runtime code and runs no cargo or lab tool.
- P/G's wrapper must preserve chaos/lossy transport semantics and firehose sampling. `ChaosTransport::send_to` can return `Ok(len)` for a deliberate drop, and its `SendShaper` can queue/delay delivery with only bytes/peer. P/G therefore mark any active lab-chaos shim or chaos-testing override as incomplete and suppress eligible proof until a separately reviewed origin-aware actual-socket seam exists. An `Ok` from that shaper and a default trait implementation never count as observed wire proof.
- The reviewer identified four design gaps, now assigned to packets: T-C owns `cell/service/base_messages/lifecycle.rs` because `player_id` is stamped after `SpaceManager::create_entity`; G uses exactly two auditable `send_to_pre_phase3` sites so concurrent unrelated handshakes do not poison A; T-P1/P2 carry an exact creation token into the ready operation so paused A cannot settle B; T-O-M extracts `base_messages/create_entity.rs` and T-A extracts `client_ready/synth_map_loaded.rs` to bring both preexisting >700-line hosts below the cap.
- Further movement review found the stale internal `CreateEntity` race: Cell's current insertion replaces a reused entity ID without an owner incarnation, and Base's post-await guard runs too late to protect Cell. `crates/services/src/orchestrator.rs::new` creates Base, Cell and one in-process channel, while `crates/cell/src/cell/service/message_loop.rs::run_cell_loop` consumes messages serially; neither fact proves cloned-sender enqueue order or retained-Cell Base restart order. `crates/cell-world/src/cell/space_manager/entities.rs::insert_entity_into_space` replaces the entity map slot without an owner check. O-I must establish a shared process-lifetime issuer; O-F must reject A after an accepted B ack before insertion; O-Q must report the current occupant. Until all pass, P1/P2/S/X/B remain blocked/unknown. Any unsupported process epoch, missing B ack or missing incarnation is `owner_order_unknown`, never a completed binding.
- Final owner-fence review found three more runtime hazards in static source. `CellToBaseMsg::GateTravel` has no source owner and Base resolves current `entity_to_addr` before minting; six Cell producer files must stamp the pre-teardown occupant and O-V must reject stale A **before** reservation. `gate_travel/mod.rs` currently treats a dropped Cell oneshot as a space fallback, so T-K must merge first using O-M typed rejection fixtures; O-F may then emit real Cell rejection without opening an unsafe fallback window. After a successful create, GateTravel awaits `query_world_stargates` and calls `persist_arrival`, whose current UPDATE matches only account/player; the later entity-only owner check is too late. T-DB0/DB2/DB1 add a monotonic DB row claim, pre-await selected-player census and phase-3 takeover invalidation (mark A revoked before reserving B's invalidation order) and exact-trip conditional UPDATE with a live-DB takeover race, including B taking over before playCharacter. A missing owner source, unsupported process epoch, absent DB claim or zero-row arrival is unknown and blocks P1/P2/S/X/B. No source proves cross-process rollover/exclusive DB owner yet; that path stays `BlockedDependency` until the prerequisite test establishes it.
- Final packet-order review closes two staged-rollout holes: T-K must merge against O-M typed rejection fixtures before O-F can emit a live Cell `Rejected`, and DB0 must record a selected player/claim under the connected lock before `handle_play_character` reaches its first await. DB2 enumerates that claim even when `active_player_id=None`, invalidates it before B phase-3 replacement, and a paused-first-entry live-DB fixture proves A cannot reclaim after B. A missing selected claim or terminal Base rejection keeps O-F/DB1/P1/P2/S/X/B blocked.
- DB writer census found a remaining hard blocker beyond these 28 packets: `crates/cell/src/cell/service/base_messages/lifecycle.rs::persist_last_position` queues `CellToBaseMsg::PersistPosition` without an owner ticket, and `crates/base-world-entry/src/base/world_entry/cell_dispatch/position.rs::persist_position` writes `world_location/pos_*` by `player_id` alone. Queue old A, finish B phase-3 takeover/DB invalidation, then deliver A: B's row must survive; current code cannot prove it. A separately scoped exact-owner guard and negative live-DB fixture must merge before S/X/B can publish complete joined fields. This review freezes packet scope at 28; other tracks proceed with joined fields unknown.
- Movement review found the argument-free ready ambiguity and same-peer old-receipt generation race. T-O-V owns the named `gate_travel/trip_receipt.rs` extraction so its 681-line host stays below 700; T-P2 owns the pre-await generation guard in that extracted path. T-A owns the sticky same-generation ambiguity gate at real ready ingress plus the named `client_ready/synth_map_loaded.rs` extraction of the 738-line host; T-R/S/X/B must refuse a stable join while ambiguous. The conservative limit is intentional: a same-generation later trip cannot rebind until a trip-specific client signal is proved or the connection generation changes.
- T-C must verify every GateTravel producer reaches central `destroy_entity`; if any bypasses it, the packet stops with that exact path and X stays blocked. T-R must recheck the current session/trip after Cell's settle reply; a stale A reply cannot acknowledge B.
- F must produce an exhaustive production send-site census, including sweeper and Cell fan-out clones. Any unowned or untagged path keeps `coverage_complete=false`; downstream packets do not call the binding complete.
- Acceptance deliberately expects joined server fields to become unknown after the first same-generation gate travel, even after visible destination readiness, until relog/new generation or a separately evidenced trip-specific signal; DW-35 may verify this only with fresh user approval.
- The real DLL hook hit and client/server fingerprint pair are unproven until the separately approved DW-35 live lab step. D-DW9 and D-DW12 remain `BlockedDecision`; no lab lease, client start/restart or server switch is authorized by these docs.
