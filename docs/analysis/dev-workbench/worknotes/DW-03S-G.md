# DW-03S-G: Base boot, generation and proof observer

> Status: implemented locally, awaiting adversarial review and integration. No live client or lab action.

The Base service now mints a fresh 128-bit boot ID from the OS CSPRNG on each start. Its Phase 3 issuer increments a counter for each inserted session. The origin seed is inserted with the channel under the connected-map lock after the two reviewed handshake datagrams. `ConnectedClientState::wire_send_origin()` copies the immutable boot, generation, peer and connection instant while sampling the current player entity. The existing direct handshake fixtures keep their old function signatures via test-only adapters; production carries the service issuer through the receive loop.

The send proof wrapper encloses the selected receive transport before any projected send clone is made. It compares the literal send address to the ticket peer before awaiting I/O, retains the ticket and verdict, and records only a full successful send with equal peers. The record keeps the Mercury FNV-1a fingerprint, byte length, server send time, sequence, boot, generation, peer and optional player entity. No raw bytes or keys are stored. Legacy sends, pending/cancelled sends, failed/partial sends, peer mismatch, a chaos override or an active lab-chaos shim leave coverage incomplete; simulated chaos success cannot create a row. The two handshake sends are counted as named exemptions. Current snapshots omit disconnected generations; the 256-row/30-second ring counts drops and overflow. Lifetime gap totals remain diagnostic; eligibility uses the latest gap in the current 30-second window and the live tagged and untagged pending counts. Untagged and peer-mismatched sends refresh their gap at completion, so a send awaiting I/O longer than 30 seconds cannot create an eligible capture when it finally sends. Normal expiry cannot poison a later clean window. Snapshots hold the connected lock through ring filtering in connected-to-ring order so a relog cannot replace A with B before an A snapshot returns.

Test coverage: actual BaseService start/restart boot uniqueness and overlapping real UDP Phase 3 logins, before/after player selection, exact peer and post-success guards, swapped recipients, paused same-peer relog send, chaos simulated success, exact overflow sequence/drops, and the actual Phase 3 call site's two exemptions for each of two clients, expiry followed by fresh eligible capture, a paused snapshot versus same-peer relog, and two controlled-age paused sends that verify untagged and mismatched completion gaps. The packet has no live lab or public read endpoint. Later DW-03S-H/D/F/S must close remaining untagged send paths and expose the read-only snapshot.
