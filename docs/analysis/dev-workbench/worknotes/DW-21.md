# DW-21 — dot progression, ability, stat, ammo and pet descriptors

The merged [DW-21-E evidence](../evidence/DW-21-E.md) is the contract for
27 dot-console commands in five registry families. The existing
`command_catalog()` now projects typed arguments, conditional forms,
preconditions, impact, readback, comparison fields, compensation and
availability for every name. Tests compare the descriptor names to the five
production `SPECS` slices and check the projected catalog, bounds and
disabled dispositions. No handler, DB query or client wire behavior changed.

Eight read commands (`.effects` and seven stat reports) are runnable.
`.cooldowns` and `.cleareffects` remain visible but disabled: command-wide
availability cannot enforce per-form cooldown reset confirmation or selected-
subject confirmation and a before-effect snapshot. Their forms and readback
recipes are retained for a future palette with these gates.
`.missionrewards` remains disabled because it can mistake an unloaded tracker
for no mission and does not show a reward set. `.speed` remains disabled until
live two-stat bounds and restoration of distinct prior values can be handled.

Persistent grants stay disabled. `.givexp` can credit a new holder of a reused
entity ID and can also change Applied Science Points. `.giveability`,
`.learnblueprint`, `.craftkit`, `.givecash`, `.allcraft` and discipline grants
need immutable GM/subject owner fences around queued Base work and post-await
client sends. `.giveammo` and its dot alias additionally need confirmation
that the committed reserve item type matches the Cell-captured type; carried
bag readback must be complete (`container_id IN (1,15)`, `truncated=false`).
Feedback alone is never a proof of original-session delivery. The mixed
commands `.dummy`, `.infiniteammo` and `.pet` have safe forms, but remain
disabled at command level until per-form availability can exclude the
unsafe forms. The native slash commands with similar names are separate.
The `.dummy` typed mode already includes `caster` and remains disabled.
The shared typed-action validator now refuses a `.cooldowns` ability ID
without `action=reset`, matching the Cell handler. The two `gm*` ammo
dot names remain in the raw 129-row registry but appear as searchable aliases
on one canonical palette action each.

The packet's listed `workbench_progression.rs` could not compile or appear in
the catalog without narrow registration in `registry/{mod,workbench}.rs`.
`registry/commands/mod.rs` exposes only the five existing family modules to
the sibling metadata test, so set equality uses production `SPECS` rather
than a copied name list. These three registration changes are the sole
deviation from the packet's narrow file list. No live lab was used. No new DB
query was added, so no live-DB test applies.

The new tests pin catalog coverage, fail-closed mixed/grant forms, selected
argument bounds and before/after/readback language. Handler tests still
cover authority and refusal; this packet does not change dispatch.
