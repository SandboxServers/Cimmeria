# DW-03S-C — bounded client Mercury receive proof

The lab bridge mints a fresh 128-bit OS-random epoch when it starts. It is independent of the telemetry session ID and is returned by `events_read`. The existing Winsock `recvfrom` IAT detour remains the sole receive hook: it calls the original first, reads a successful bounded datagram, preserves its error code, and sends at most one lab `mercury.wire_proof` row per qualifying read. The row has the bridge epoch, diagnostic socket and parsed IPv4 peer when available, encrypted byte length and 16-digit FNV-1a fingerprint. It contains no payload bytes or process identity.

The `events_read.mercury_wire_proof` snapshot has `hook_installed`, `received`, `rejected`, `dropped` and `gap`. Before any qualifying read its gap is `hook_unobserved`; a successful read without a parseable peer retains `peer: null` and `gap: peer_unavailable` while incrementing rejected. Non-Mercury request shapes are rejected. The bridge event ring is bounded; a proof row lost to capacity increments the dedicated dropped counter. The supervisor must stamp its own PID and process creation ticks at ingestion in DW-03S-I. Neither the socket nor peer is a game-session identity.

Offline tests cover exact encrypted-byte fingerprint and serialization, no raw byte field, unknown peer, non-Mercury reads, counters, capacity plus one, bridge epoch rotation under the same telemetry session ID, and the `events_read` fixture. The 32-bit lab DLL built and linked. Static RE evidence identifies the 1472-byte Mercury receive request, but the hook and proof row have not been observed in a live client. No lab lease or client action was taken.

The required default fmt, clippy and filtered Mercury tests passed. Lab-bridge filtered tests and 32-bit check/build/clippy passed. An additional x86_64-host lab-bridge clippy run failed on existing warnings in `bridge/crash.rs`, `bridge/native_call.rs`, `bridge/lua_eval.rs` and two pre-existing patterns in `bridge/mod.rs`; the packet does not own the first three files. This remains a build-quality limitation, not a proof failure.
