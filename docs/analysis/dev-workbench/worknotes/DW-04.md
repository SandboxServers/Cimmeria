# DW-04 Lua probe and object browser handoff

The per-user daemon catalog stores versioned, hashed named snippets, favorites
and bounded metadata-only history. The browser API requires a current instance
session, CSRF on POST, a current lab lease for every Lua or CEGUI read and a
matching saved SHA-256 before running. Parameters are Lua literals generated
from bounded JSON data. A read-mode label is operator intent, not a static
proof that arbitrary Lua source has no side effect.

Probe returns and global browsing use raw table traversal and keep userdata
opaque. The Lua wrapper has an instruction hook budget, depth/node/string
limits and a host timeout. Live hook availability is unverified; Lua source
can disable its own hook, so it is an operator aid rather than a security
boundary. A blocking C binding can outlive the host timeout,
so a timeout result explicitly says execution remains unknown. Missing bridge
return capture, Lua errors and partial trees remain distinct. The CEGUI branch
uses the existing bounded `client_window_read` walk. No Lua namespace is
persisted through relog. No live lab lease or client was used for this packet.
