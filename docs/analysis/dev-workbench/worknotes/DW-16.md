# DW-16 — Lab overlay render/device seam

The existing `Direct3DCreate9` IAT detour and `CreateDevice`, `Reset`, and `TestCooperativeLevel` COM hooks provide the device pointer. The bootstrap installs these only after the global SGW.exe code and slot fingerprint report is usable; per-IAT import checking still applies. An EndScene slot is patched only in `lab-bridge` after `bridge_epoch()` exists. The render callback reads only atomic coarse status bits, draws three bounded opaque rectangles with `Clear`, and wraps them in `D3DSBT_ALL` capture/apply/release. The original EndScene runs after the panel path regardless of panel errors. A second device becomes active only when its vtable matches the one patched vtable; a different vtable clears the active device. The real install decision gates the patch callback on the fingerprinted Create9 detour and active bridge, and the unsupported-fingerprint test asserts that callback is never invoked.

The device state disables rendering while lost or after a failed Reset, permits it after successful Reset, rejects recursive EndScene, and permanently disables it after three faults. The software budget is checked between driver calls; it cannot interrupt an individual slow D3D call. Failure reasons and counts are recorded atomically by EndScene and drained every 200 ms by one lab-only non-render worker into a bounded one-shot diagnostic event. Patch failures also record a reason and stop retries after three failures. The panel has no text or target identity yet; DW-18 will publish trace/record/gap bits and controls. The no-client host tests use fake device operations and lifecycle state. Global fingerprint mismatch refusal is covered by the existing fingerprint test suite; no original executable or live lab client was used.
