# Developer workbench work packets

> Type: implementation plan. Audience: packet coders, domain advisors and reviewers. Last updated: 2026-10-16. Companions: [campaign ledger](README.md), [resume note](RESUME.md). Implement only the named packet in a dedicated worktree. Packet numbers are PR units, not permission to run the live lab. Never infer client facts from the Rasa archive.

## Dispatch and review

Create one worktree per packet from the current `main`: resolve `$Main` to that checkout's **absolute path**, then run `pwsh -NoProfile -File (Join-Path $Main 'tools/build-lane/mk-worktree.ps1') dev-workbench/<id>-<slug> <worktree-name>`. One worktree and one `sgw_<worktree>` test DB per worker. A `packet-coder` takes one packet, edits only its listed files, runs its checks and commits locally. Send judgment-heavy RE in DW-17 or DW-24B to `game-archaeology-specialist`; use `rust-gameserver-dev` for a handler requiring design judgment. Run `packet-reviewer` on each diff, and domain/security advisors on DLL, GM and auth packets. One `packet-review-fixer` takes **one packet/worktree** at a time and reruns its gates; integrate reviewed packets in batches of about six within each dependency wave in the ledger. Ship with the `ship-pr` PowerShell workflow after review, and update the ledger/worknote. Do not dispatch overlapping ownership concurrently; dependencies merge first. Stop if a referenced API has changed on `main`, reconcile this contract in the ledger, then resume.

## Shared contract (freeze in DW-01/DW-19)

The new Rust model lives under `crates/lab/src/workbench/`. `CaptureContext { schema_version: 1, instance: String, client_pid: u32, client_fingerprint: String, player_entity_id: Option<u32>, selected_entity_id: Option<u32>, server_session_id: Option<String>, host_ms: i64, monotonic_ms: u64, server_offset_ms: Option<i64>, source: Vec<String>, gaps: Vec<Gap> }`. `Gap { layer: String, code: String, detail: String }`. `Observation<T> { source: String, at_ms: i64, value: Option<T>, gap: Option<Gap> }`. Never turn `None` into an empty successful value. The supervisor owns `CaptureBroker` with one server packet-tap drainer per session and named, bounded client/server cursors; consumers get cloned rows and explicit `{first_seq,last_seq,dropped}`. Reuse the existing event-store cursor machinery if it already meets this contract. A UAT or human recorder that owns a tap retains ownership; broker requests fail with `capture_busy` if safe fan-out is unavailable. All endpoints take an explicit `instance` and a valid lease for writes, and check that PID, session and selected entity still match at execution time.

Workbench JSON uses `{schema_version:1, context, data, gaps}`. Saved evidence includes source timestamps, client/server build fingerprints, command metadata version and redacted fields. `unknown`, `unverified`, `verified` are distinct states. Client instrumentation is compile-time `lab-bridge` plus session activation; no new wire opcode, no server-to-client relay. GUI API is `/workbench/api/v1/*` on the local daemon, separate from MCP; its cookie cannot authenticate `/mcp` or `/status`. A one-use opener nonce lasts 60 seconds, is consumed before redirect and never enters page JS; cookie is HttpOnly/SameSite=Strict; mutations need exact same Origin and CSRF token. `/mcp` continues to refuse browser Origins. The shell remains PowerShell. Compiling Rust goes only through `pwsh -NoProfile -File <absolute-worktree>\tools\build-lane\lane.ps1 cargo ...`; noncompiling `cargo fmt` may run outside the lane per the lane-build skill. Tests are chosen from `TESTING.md`; checks are fmt, clippy, then the named crate test, with `-p`. New JS modules use `node --test` and a JS REPL-style state/persistence exercise. Docs under `docs/` keep CRLF.

GM schema in DW-19: `CommandDescriptor { id: String, channel: Dot|Slash, category: String, aliases: Vec<String>, summary: String, example: Option<String>, availability: Runnable|Unsupported|Hidden, disposition_reason: Option<String>, args: Vec<ArgDescriptor>, target: TargetPolicy, impact: Impact, verify: VerifyRecipe, compensation: Compensation, metadata_version: u32 }`. `ArgDescriptor` has `name`, `kind` (`Text|Integer|Float|Boolean|Enum|Entity|Template|Mission|Item|World|Position`), `required`, `default`, `range`, `choices`, `help`, and `sensitive`. `TargetPolicy` is stable `None|Player|Mob|MobOrId|Being|Spawnable` plus a selection rule. `Impact` states `ReadOnly|Transient|Persistent|Authoring|Irreversible`, a human summary and preconditions. `VerifyRecipe` names explicit read tools and comparison fields; `Compensation` is `None|Inverse(descriptor_id)|Manual(text)`, never a fabricated undo. A command action is `{descriptor_id, instance, actor_entity_id, selected_entity_id, typed_args, idempotency_key}`. The server or lab dispatcher rechecks authorization, target and typed args; no UI trust. Dot executes by `server_console_exec`; slash goes through the stock client path and requires evidence of a GM method, not just text submission. Both return an `ExecutionReceipt` with `submitted`, `server_accepted`, `verified` independently, plus feedback, before/after reads, audit id and evidence paths.

### Rules every packet carries

R1. PowerShell only; absolute worktree paths; no direct compiling `cargo`, bash, WSL, `git stash`, or `git worktree prune`.
R2. Choose a real regression test from `TESTING.md`; a runtime PR changes a test that fails when its fix is reverted.
R3. Keep source files under the 500-line cap; split by responsibility before a touched file crosses it.
R4. Consult `tools/README.md`, `crates/README.md` and existing `src/bin` before adding any script, parser, decoder or CLI.
R5. Protocol facts come from `docs/protocol/` or client evidence, not issue text or the Rasa archive.
R6. Seeds are source of truth; never present a live DB or in-memory edit as a durable seed change.
R7. Update docs from `docs/agents/doc-update-map.md` in the same behavior PR; CRLF for docs, no generated-block edits; status docs only in DW-34.
R8. Do not take the lab lease, start/restart client, or change lab server without an explicit fresh yes; offline fixtures are the packet gates.

Each packet below repeats the operative subset so its section can be sent alone. `fmt` means `cargo fmt --all -- --check` from PowerShell in `<W>`; `clippy/test` run through `<W>\tools\build-lane\lane.ps1` and `-p` the named crate. `<W>` is the packet's absolute worktree path, never the shared root. ## Wave 1B: trusted client-to-server session binding

The static DW-03S-E trace found that `Transport::send_to` receives only bytes and peer, and `collect_pending_retransmits` drops the session identity when it returns `Vec<Bytes>`. A BaseService peer lookup after an awaited send can label A's delayed packet as replacement B. The later DW-03S-C review found that a process-wide `recvfrom` IAT hook supplies only candidate shape and that Phase-3's reply precedes AES. Implement the producer in review batches of about six: 1B-a (E, C, P, G, H, D), 1B-a-receive (R-E, R-P, R-C; sequential after C and original-binary availability), 1B-b (F, T-C, T-O-M, T-O-C, T-O-S0, T-O-I), 1B-c (T-O-S1, T-O-V, T-K, T-O-F, T-O-Q, T-DB0), 1B-d (T-DB2, T-DB1, T-P1, T-P2, T-A, T-R), and 1B-e (S, X, I, B). Each packet is at most 45k working tokens including tests, docs and review overhead; one adversarial review per packet, with one review fixer covering a wave only if its combined diff fits context. The DW-03 dossier remains fail-closed until B. Cookie, telemetry session ID, account/name/entity equality, PID alone and UDP endpoint equality are not binding evidence; NAT may rewrite the peer. A fingerprint is an observation key, never authentication or GM authority. No implementation packet takes a live lab lease or runs the client; DW-35 still requires owner approval.

**Frozen binding contract:** `ServerWireProof { schema_version: 1, server_boot_id: String, session_generation: String, player_entity_id: Option<u32>, peer: String, sent_at_ms: i64, wire_len: usize, wire_fingerprint: String }` describes one successfully sent encrypted datagram and carries no bytes, account name, token or key. The boot ID is minted with a CSPRNG at each BaseService start; generation combines that ID with a connection counter. Its generation is an immutable send-origin ticket captured from the originating `ConnectedClientState.connected_at` while that session creates or queues the datagram, carried through the awaited transport send and used only after success; a lookup by peer after `send_to.await` cannot establish origin. `ClientWireProof { instance: String, pid: u32, process_created_ticks: u64, bridge_epoch: String, observed_at_ms: i64, peer: Option<String>, socket: u64, wire_len: usize, wire_fingerprint: String, eligible: bool, source_kind: String, encryption_state: String, gap: Option<String> }` is accepted only from the active bridge and verified process identity, and only if `eligible=true`, `gap=None`, the Mercury socket/caller is independently proven and the observed datagram is classified post-handshake encrypted. The current IAT shape-only rows are always ineligible. R-E must verify exact original-client x86 hook bytes/ABI; R-P may establish Mercury socket/packet provenance but remains ineligible; only R-C may emit a separate eligible row after successful same-datagram post-handshake cipher and filter proof. Missing evidence keeps D-DW19 blocked. `StoredEvent` additionally carries ingestion-time supervisor-observed `(instance,pid,process_created_ticks,bridge_epoch,captured_at_ms)`; absent identity makes the row ineligible for binding, and read-time PID labelling is forbidden. `BoundSession { instance, pid, process_created_ticks, bridge_epoch, server_boot_id, session_generation, player_entity_id, server_peer, matched_fingerprints, bound_at_ms, expires_at_ms }` is an in-memory observation, not a persistent credential. Require two **different** encrypted fingerprints, each a unique client/server match in a bounded capture window, both server rows from the same generation and server boot; confirm exactly one fresh DW-03S-X authoritative roster row couples that boot/generation to the player entity and active world/shard, and an independent `Unit.Player` slot observation before and after the joined read has the same entity. `server_sessions` and `dossier.rs`'s peer predicate are not binding sources. Server and client wall timestamps are different clock domains: never directly compare `sent_at_ms` with `observed_at_ms` as if synchronized. Bound row age against a capture timestamp from its own clock, and require the two fingerprint pairs to admit one offset whose pair-to-pair variation is within the documented tolerance; an unknown constant offset is allowed. Inconsistent offset, clock jump, stale capture and missing source-local freshness are gaps. A duplicate fingerprint, ambiguous peer or roster, expired row, dropped client/server capture, unmatched process identity or changed player/world invalidates the candidate. Endpoint strings remain diagnostic only. Revalidate the unique generation-bearing roster before and after each joined server read, along with player, world, PID/creation ticks and bridge epoch; relog, process restart, server restart and gate travel clear the cached binding. Keep the existing `CaptureContext` JSON compatible: `server_session_id` becomes the opaque generation only after proof, while source/gaps record the proof state. GM actor authority still comes from server-side session checks, never from this correlation token.

**Frozen producer API (P → G → callers → S):** `cimmeria_mercury::transport::SendOrigin { server_boot_id: Arc<str>, session_generation: Arc<str>, peer: SocketAddr, connected_at: Instant, player_entity_id: Option<u32> }` is an owned, immutable snapshot; `Transport::send_to_with_origin(&self, bytes: &[u8], addr: SocketAddr, origin: &SendOrigin) -> io::Result<usize>` has a default implementation that delegates to `send_to` for existing test transports. `Transport::send_to_pre_phase3(&self, bytes: &[u8], addr: SocketAddr) -> io::Result<usize>` also defaults to `send_to`; only `handle_login`'s two pre-insertion connect-reply/time-sync call sites may use it. The BaseService proof wrapper overrides all three methods. The override forwards bytes unchanged through the real/chaos transport and records a proof row only for `Ok(n)` where `n == bytes.len()` **and** the actual send argument `addr == origin.peer`; compare before the await and retain the result with the immutable ticket. A mismatched destination is a named ineligible coverage gap, even if the send returns full `Ok(len)`; never relabel the ticket to `addr` or another recipient. Untagged, failed, partial or missing-origin sends are also gaps; `send_to_pre_phase3` increments a separate audited exemption counter and never creates a proof row or poisons current generations. An untagged send can never be upgraded by a later peer lookup. `SessionOriginSeed { server_boot_id: Arc<str>, session_generation: Arc<str>, peer: SocketAddr, connected_at: Instant }` is stored in the existing per-session `SessionExtensions` slot at Phase 3, not added as a field to all `ConnectedClientState` fixture literals. `ConnectedClientState::wire_send_origin()` returns `Option<SendOrigin>` by combining that fixed seed with the **current** `player_entity_id` while the helper holds the same lock as key/seq/ACK or retransmit collection; a Phase 3 `None` must not remain frozen after character selection. `PendingRetransmit { bytes: Bytes, origin: SendOrigin }` replaces the identity-losing `Vec<Bytes>` return. If no origin is available, the caller uses the legacy send path and the proof coverage becomes incomplete. No packet may declare binding complete while a relevant coverage gap, dropped proof row, or unknown travel transition is in the capture window.

**Frozen travel contract (T-C → T-R → X/B):** Cell's `SpaceManager::destroy_entity` is the central authoritative source for the origin-space teardown across GateTravel producers in `cell-interactions`, `cell-content`, `cell-console` and respawn. A lab-only per-player `TravelEpoch { player_id: i32, entity_id: u32, epoch: u64, state: InProgress|Stable }` changes no later than that teardown, survives the temporary absence of the cell entity and can become `Stable` only after guarded destination readiness acknowledges that same epoch; ambiguous readiness leaves it `InProgress`. It increments at origin teardown even for same-world travel. A `LabQuery::TravelEpoch { entity_id, player_id }` returns this copied state (or unknown), including during the empty-cell window; it must not derive stability from unchanged Base `world_name`/displayed status. `CreateEntityReceipt { space_id: u32, entity_id: u32, player_id: Option<i32>, incarnation: Option<CreateIncarnation>, travel_epoch: Option<u64> }` is emitted atomically after Cell identity stamping; Base captures `OriginSessionGuard { connected_at, session_generation, account_id, player_id, expected_entity_id }` before its Cell await, rejects a receipt if that exact originating generation no longer owns the connection, and then combines an accepted receipt with the fixed generation into `TravelTripToken { entity_id, player_id, incarnation, travel_epoch, session_generation }` and carries it through per-session `PendingTripSlots { world_entry, map_loaded, client_ready, current }` in `SessionExtensions`. These slots move atomically under the same connected lock as the corresponding `pending_world_entry`, `pending_map_loaded` and `pending_client_ready` state. `onClientReady` has no trip argument (protocol index 24/0xD8), so neither an ingress timestamp nor a pending-slot token proves which trip emitted it. An ingress observation carries only connection generation and a sequence, never inferred trip identity. T-A latches `ready_ambiguous` for the generation before a second trip begins or any pending/in-flight ready is overwritten; absent a protocol-verified trip-specific client signal, every later trip in that generation stays ineligible for Cell proof settlement even if the earlier ready completed. The latch clears only with a new connection generation. Gameplay world entry may continue, but Base publishes no stable travel acknowledgement and X/B return unknown. A ready handler still takes pending and token atomically to prevent cross-operation swaps; that token alone is insufficient when the latch is set. Base snapshot exposes pending world-entry/readiness plus an acknowledged token/epoch; X returns only a stable, matching Cell/Base epoch and unique generation. B compares that epoch/state before and after every joined read. Missing query, incarnation/owner-fence mismatch, disconnect, entity reuse or in-progress transition is `roster_changed`/`transition_unknown`, not success. T-C, T-O-M/C/S0/S1/I/V/F/Q, T-DB0/DB2/K/DB1, T-P1, T-P2, T-A and T-R tests must cover a queued GateTravel, origin teardown before Base consumes it, same-world completion and replaced session. This is in-process diagnostic state, not a client wire change.

**Frozen Cell create-owner contract (T-O-M/C/S0/S1/I/V/F/Q, T-DB0/DB2/K/DB1 → T-P1/P2/T-R/X/B):** Every player `BaseToCellMsg::CreateEntity` carries `CreateOwnerTicket { process_epoch: Arc<str>, issue_order: u64, incarnation: CreateIncarnation, server_boot_id: Arc<str>, session_generation: Arc<str>, entity_id: u32, player_id: i32 }`. `CreateIncarnation` is a fresh opaque CSPRNG value for one create attempt; it is never derived from peer, player or reusable entity ID. The issue order and incarnation are reserved together from one process-lifetime monotonic issuer under the originating session lock **before the first await** of play-character/gate-travel, including the lab-fixture await; DB0 also records the selected account/player/reservation in a bounded `SelectedPlayerClaims` type-keyed entry in `SessionExtensions` under that lock before awaiting; after the entity ID is known, the reservation is finalized into a ticket for exactly that create. A later same-process Base start must use the same issuer. Cell's `OwnerFenceBook` retains the highest accepted order/tombstone per entity ID and an occupant incarnation sidecar. For one process epoch, only a strictly newer ticket may claim a reused entity slot; an older A delivered after accepted B is rejected **before** `SpaceManager::create_entity` mutates it.
