## Decision and evidence

O14-17 requires Marsh to refuse completion without the owned Frost's Letter (item 3730); O14-19 makes mission 1360 one-shot. Castle CS-08a1 `583a85f` advances 4037 to 4038 on the Castle-to-Harset gate crossing while retaining the letter. Existing chain 6501 shows success dialog 4576, sends an unchecked asynchronous removal, clears dialog binding 5356 and completes mission 1360 independently. The base remover can refuse a missing item and the mission writer can later overwrite a completion. Current outbox delivery is keyed by entity ID and marks a channel send, not cell application. This is a `CIMMERIA_RECONSTRUCTION`, not a recovered 2009 mission script.

Database, mission, authority and testing advisers reviewed the source on 2026-10-14. Their common requirement is a mission-specific atomic consume/completion with a persisted one-shot receipt, plus a correlated, session-fenced result before any success side effect. Testing review found the proposed a2 child too broad: internal transport and session fencing become a2; the strict action and cell continuation become a3. Exact manifests and measured budgets still need signoff. No `db/scripts/` migration is authorized; canonical schema and seed reload are the database path.

## Shared a1/a2/a3 interface

- Fixed business tuple: mission 1360, active step 4038, owned accessible item type 3730, exact quantity 1, world 68, Marsh target `CmdCenter_Marsh`/template 10 and chain 6501. A request cannot substitute client counts, item instance, mission, recipient or quantity.
- The cell obtains player identity from the live entity and refuses unknown/zero or mismatched identity. It validates the server-resolved Marsh interaction, world, range, hydrated mission state and active 1360/4038 with 1361/4694 not active. The base dispatch rebinds entity, player and current session before calling a1. A stale request after logout or entity-ID reuse is refused.
- A request carries an opaque attempt token plus a base-minted session token. The token survives same-session retry and changes on relog. A2 derives 16 bytes from `SHA-256("cimmeria:letter-turn-in:v1" || ConnectedClientState.key)`, using a direct `sha2` dependency in the base routing crate. It sends only that digest prefix to the cell on each world entry before interaction can run; the base recomputes it from the current connected session on request. Never log or expose either the raw key or token. The result carries attempt/session tokens, player ID, transaction outcome, consumed instance/before/after and persisted mission postimage. Both base and cell reject a mismatch. World transfer retains the same key, so a3 separately checks current world and Marsh target before any success effect. No client protocol or item propID changes are part of this packet.
- A1 owns the database transaction and durable receipt lookup. A2 owns internal messages, base routing and session fencing. A3 owns the strict content action, cell pending/retry, result application and feedback. A1–A3 do not deploy while old 6501 remains live; HA-1360b replaces the seed in the same campaign PR before any server uses the new handler.

## HA-1360a1 — transaction and stale-writer fence

**Scope:** `db/sgw/Missions/Tables/sgw_mission_1360_receipt.sql`, its `db/database.sql` inclusion, and matching keys in `db/sgw/{_primary_keys.sql,_foreign_keys.sql}`; `crates/base-methods/src/base/world_entry/methods/missions/{mod.rs,letter_turn_in.rs,letter_turn_in_tests.rs}` and focused concurrency tests. Register the test module without expanding unrelated mission writers. The receipt is unique for `(player_id, mission_id=1360)` and stores validated text attempt/session correlation, consumed `item_id`, source container and exact stack before/after. Use canonical DDL, not a one-off migration.

**Interface and DDL to freeze:** a public `commit_letter_turn_in(pool: &PgPool, player_id: i32, attempt_key: &str, session_token: &str) -> Result<LetterTurnInVerdict, sqlx::Error>` in `letter_turn_in.rs`; the request cannot supply mission, step, item type or quantity. `LetterTurnInVerdict` distinguishes `Committed`, idempotent `AlreadyCommitted` for the same attempt/session, and named `Refused` reasons. Both committed forms include the exact `SavedMission` postimage and consumed item/stack fields, so a2 never synthesizes success from cell state. A SQL/commit/transport error maps to `UnknownRetryable` at a2/a3, never a permanent refusal; retry the same attempt and query the receipt because the commit may have succeeded before the error was observed. A receipt row stores `(player_id, mission_id=1360, attempt_key, session_token, item_id, container_id, stack_before, stack_after, created_at)` with `CHECK (mission_id=1360)`, `CHECK (stack_before >= 1 AND stack_after >= 0 AND stack_after = stack_before - 1)`, primary key `(player_id, mission_id)` and FK to `sgw_player` with cascade delete. Do not add a UUID dependency or client field. Use the repo's separate `_primary_keys.sql` and `_foreign_keys.sql` conventions. The a1 test failpoint helper is private/test-only; production callers cannot request a failure stage.

**Transaction:** begin; take shared inventory advisory locks (player-wide key 0, then reachable bag keys in ascending order); acquire a `sgw_player` `FOR KEY SHARE` lock before any item row so the receipt's FK cannot deadlock with concurrent character delete; then inspect prior receipt. Lock an owned accessible 3730 row by unique `item_id`, ordered by container/slot, then lock `(player_id,1360)` mission `FOR UPDATE`. Require the entire canonical B preimage exactly: status 1, step 4038, repeats 0, completed steps `[4037]`, completed objectives `[4650]`, active objectives `[4651]` and failed objectives `[]`. Do not synthesize missing prior progress or accept extra entries. Select no bank, buyback, organization vault or escrow item. Consume exactly one by the selected unique `item_id` with owner/type/container/positive-count predicates and `rows_affected()==1`; never use a type-only mutation, reject zero/missing/foreign/locked rows and never clamp. Update the mission by a full preimage predicate and `rows_affected()==1`: status 2, current step NULL, repeats 1, append 4038 and 4651 once to their captured arrays, and retain active objective IDs `[4651]` to match `mission_update_msg`/hydration semantics. Insert the unique receipt in that transaction and commit. Every error before commit rolls both inventory and mission back; an error returned by commit has unknown outcome and requires same-attempt receipt reconciliation. A retry of the same committed attempt reads the receipt *after* the player-wide lock, checks the terminal mission postimage and returns it without a second consume; a different attempt refuses. Two same-attempt requests serialize on the advisory lock, so the second reads the first receipt rather than reporting a spurious missing letter.

**Writers:** the 1360 branch of `handle_mission_update` must refuse independent status-2 completion, backward 4038-to-4037 progress, and any active/abandon/failed write after a persisted completed row. Its current unconditional UPSERT and abandon delete cannot survive. Ordinary missions keep their existing semantics. Preserve the Cellblock acceptance and Castle 4037-to-4038 writes before the receipt. A queued pre-commit snapshot must not overwrite the terminal row after commit. Document and test the effective lock order with the generic writer.

For this one-shot mission, the generic writer accepts only two exact active snapshots from `mission_update_msg`: A, status 1/step 4037/repeats 0/completed steps and objectives empty/active objectives `[4650]`/failed empty; B, status 1/step 4038/repeats 0/completed steps `[4037]`/completed objectives `[4650]`/active objectives `[4651]`/failed empty. Its legal transitions are absent→A, A→A, A→B and B→B. Reject all generic status 2, 0 or 3 writes, B→A regression and same-step 4038 snapshots with older/different arrays. An atomic conditional `ON CONFLICT ... DO UPDATE ... WHERE` can enforce these transitions under the row lock; a generic abandon delete for 1360 must refuse, including after completion. A1's transaction still checks the full captured B preimage when changing to terminal. The generic writer never holds an inventory row while waiting on the mission row; this preserves inventory-advisory → player KEY SHARE → item-row → mission-row order without a cycle. If source inspection finds a legitimate 1360 writer with another snapshot, amend this contract and test it before code.

Revert proof targets selecting owner/type/access and exact-count eligibility checks, transaction rollback boundary, and generic-writer state fence; redundant final SQL predicates need not each fail in isolation when the row lock and earlier selection still guard them. ## HA-1360a2 — internal transport and session fence

**Scope:** request/result payloads in `crates/wire/src/cell/messages/` and their stable kind names; base routing in `crates/base-world-entry/src/base/world_entry/cell_dispatch/`; SHA-256 session token derivation from the current `ConnectedClientState.key` and internal delivery before `InitPlayerState` on every world entry; token storage and cleanup in the cell entity/space manager; a minimal result handoff for a3. A2 calls a1 after re-binding the connected entity to the requested player and comparing the token. No request received after logout, character change or entity teardown may start a1. A live request accepted before teardown may commit during an in-flight transaction; a3 drops its old-session effects and the next world entry reconciles persisted state. A late result still carries player/session/attempt for a3 to drop. World transfer retains the key: cell result application must recheck world 68 and the saved Marsh target. Name the exact world-entry send and teardown functions before dispatch; never log the raw key or token.

**Tests:** a routed valid request reaches the a1 verdict; wrong player, stale token, disconnected/reused entity and world-transfer teardown refuse before DB mutation. Internal payload and `kind()` tests pin the request/result contract. An old result delivered after a new session is later dropped by a3.

## HA-1360a3 — strict action, pending state and continuation

**Scope:** a focused action/strict loader in `crates/content-engine/src/{actions.rs,loader/action.rs,loader/mod.rs,chain/step_anchors.rs}`; `crates/cell-content/src/cell/content/executor/letter_turn_in.rs` and dispatch/pending guards in `cell/missions/`; cell result route in `crates/cell/src/cell/service/base_messages/`; pending storage and cleanup in `SpaceManager`. Consume a2's internal message/session contract. Name any additional exhaustive-match or teardown files before dispatch; split this child again if the manifest exceeds the packet budget.

**Action:** `complete_mission_with_item` is valid only for the fixed 1360/4038/3730/quantity-1 tuple, zero delay and the approved continuation IDs. The loader fails the entire chain when a mandatory action is malformed; silently skipping it while retaining success actions is forbidden. A3 never calls generic `complete_mission_direct` or sends an independent 1360 `MissionUpdate` for the receipt.

**Pending and result:** first click sends one nonblocking request and immediate processing feedback via the proven Feedback channel. The binding and active mission remain while pending. A repeated click uses the same attempt and says it is processing. Timeout or `UnknownRetryable` retries the same attempt and reconciles from the receipt; neither becomes a permanent refusal or creates a fresh attempt. A definitive refusal clears pending, gives a reason on the first click and emits no success frames/event. On a matching committed result, install the persisted mission postimage, show 4576 only to the still-current Marsh interaction, remove DSM 5356/slot 10, then emit mission/objective/step frames and `mission_completed` once so chain 6511 opens 1361. A duplicate result does not repeat any of these. After a disconnect or world transfer, drop old-session result effects and reconcile the persisted state on world entry; chain 6511's `player_loaded` leg restores the offer. Exactly-once visual display across a crash is not claimed because the client has no acknowledgement of that dialog.

**Tests:** strict loader rejects malformed action with the whole chain; executor first/double click produces one request and processing feedback with no precommit success; wrong entity/world/tag/step/overlap rejects; missing item refusal has no success dialog, DSM removal, mission frames or completion event; duplicate click/retry keeps one attempt; an injected ambiguous commit response keeps the same attempt and recovers by receipt; old-session, wrong-character and reused-entity result is dropped; committed result orders postimage and success effects once; world-transfer/relog loads terminal DB state and opens 1361 without replaying old effects. A receiver-level test inspects emitted success/refusal frames where this path changes delivery, without retesting unchanged serializers. Revert mutations of loader strictness, pending key and postcommit gate must fail their focused tests.
