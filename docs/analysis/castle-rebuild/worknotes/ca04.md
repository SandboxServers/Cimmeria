## Evidence

The advisor pass settled four questions the packet left open. All citations are the
advisor's, verified against the paths named.

1. **The original had no session timeout at all.**
   `MinigameRequestManager::QueueEntry` (`deprecated/cpp/src/baseapp/minigame.hpp`)
   carries no timestamp; entries leave the queue only via an explicit `remove()` or
   `cancel()`. `BaseService.config` has no timeout knob. The WARN at
   `minigame_connection.cpp:386` ("maybe it timed out?") is the original author
   speculating about a client condition, not evidence of a server timer. Recovery in
   the original was two client-driven RPCs instead: `endMinigameForPlayer`
   (`deprecated/python/base/SGWPlayer.py:99`) and `minigameStartCancel`
   (`deprecated/python/cell/SGWPlayer.py:2010`, cell method 30, reporting
   `MINIGAME_RESULT_NotStarted`). **Cimmeria implements neither** — cell method 30
   logs `UNIMPLEMENTED` (`crates/services/src/cell/cell_methods/minigame.rs:131`).
   That is the root cause of B4, and the TTL is a backstop, not a port.
2. **`aborted()` is a client-facing hook, but the C++ wrapper did report upstream.**
   `Placeholder.py:60-63` only sends the `failure` extension message. But
   `Minigame::abort` (`minigame.cpp:154-181`) runs the instance's `aborted()`, then
   `closeMinigame()`, then `handler_(this, MinigameCanceled)` — result code **0**, a
   distinct code from `MinigameDefeat` (2) (`minigame.hpp:8-18`,
   `deprecated/python/common/Constants.py:12-15`). The original needed the report:
   `handleMinigameResults` (`deprecated/python/cell/SGWPlayer.py:1927-1936`) is what
   cleared `BSF_PlayingMinigame` and released the movement lock.
3. **1-5 is the right content-layer range for `difficulty`**, asserted in three
   places: `deprecated/python/cell/Minigame.py:16` (`assert(1 <= difficulty <= 5)`),
   `deprecated/python/Atrea/__init__.py:305`, `deprecated/python/base/SGWPlayer.py:80`.
   Every per-game difficulty table is 1-4 (`Livewire.py:52`, `Alignment.py:14`,
   `GoauldCrystals.py:52`), so difficulty 5 passed the original's assert and then
   raised `KeyError` inside the game. The 1-5 / 1-4 mismatch is original.
4. **No play-time cap in the original either.** Session lifetime was bounded only by
   the socket or an explicit result. Livewire's `paramTimer` countdown
   (`Livewire.py:179`) produces a normal Defeat through the regular result path,
   never a server-side session kill.

## Design decisions

1. **Expiry is two mechanisms, not one.** `spawn_sweep` runs every 60 s and drops
   unconnected sessions older than 180 s; `register` also sweeps inside its own lock
   before the duplicate check. The sweep bounds memory for a player who never comes
   back; the on-register sweep is what makes the *next* interaction recover without
   waiting for a tick. The B4 regression guard exercises the second.
2. **`connected: bool`, set by `mark_connected`, not by `authenticate`.**
   `authenticate` stays read-only so a login that authenticates and then fails to
   build a game instance cannot mark a session immortal. `handle_connection` calls
   `mark_connected` at the same point the C++ sets `entry->session = this`
   (`minigame_connection.cpp:409`), after login succeeds and before the room sends.
3. **TTL = 180 s, sweep interval = 60 s.** Not ported — there is nothing to port.
   Sized to outlast the `onStartMinigame(URL)` to Flash-surface to SWF-load to
   TCP-connect handshake, which is seconds on a healthy client, while staying far
   below any plausible play session. Documented as a backstop in the constant's doc
   comment, with the cell-method-30 fidelity fix named.
4. **`created_at` is a `tokio::time::Instant`.** A `std::time::Instant` is immune to
   `tokio::time::advance`, so every expiry test would have to sleep for real. This is
   the whole reason `crates/services` gains a `tokio` dev-dependency with
   `test-util`; the feature reaches test targets only, not the server binary.
5. **The abort reports result code 0 (Canceled), not nothing and not Defeat.** My
   first cut dispatched nothing, reasoning that a defeat result is noise. The advisor
   showed the original *did* report, with a distinct code. Reporting 0 is faithful,
   is inert on the cell today (`base_messages/minigame.rs:23` acts only on
   `result_code == 1`), and becomes load-bearing the moment `BSF_PlayingMinigame` or
   a movement lock lands — at which point dropping it would strand the player. The
   Discord emit is gated on `result_code != 0` so a closed window does not post a
   "lost" line.
6. **`difficulty` out of range is rejected, not clamped.** A row outside 1-5 is
   dropped at load with a `warn!` naming the chain id, matching `set_npc_poi`'s
   existing style. Clamping would hide the authoring mistake until someone played the
   minigame. Livewire's own `clamp(1, 4)` is the one remaining silent downgrade, so
   it gained a `warn!` for when the clamp actually bites.
7. **`server.rs` became `server/`.** The new tests plus the `run_session` split took
   it to 810 lines, over CLAUDE.md's 700 hard cap. Split along the seams already
   implicit in its section comments: `framing.rs` (null-terminated I/O),
   `handshake.rs` (version check + login), `result_dispatch.rs` (result codes and the
   single outcome seam), `tests.rs`, and `mod.rs` (lifecycle). `pub async fn run`
   keeps its path, so `orchestrator.rs` is untouched. Largest resulting file is 417
   lines.
8. **`run_session` exists so exactly one place unregisters the session.** The four
   handshake sends each returned straight out of `handle_connection`, leaking the
   registry entry on a mid-handshake socket error — the same "entity stuck until
   relog" shape as B4, reachable without any SWF misbehaviour. The caller now always
   runs `registry.remove`.

## Recorded, not implemented

Per the packet's item 4, plus two the advisor surfaced.

- **`on_defeat_chains`.** The victory list has no counterpart, so no chain can react
  to a loss. Would slot beside `on_victory_chains` on `Action::StartMinigame`,
  `CellToBaseMsg::StartMinigame` and `MinigameSession`, and be dispatched from
  `handle_minigame_result`'s `result_code == 2` branch — which does not exist yet,
  since the handler only acts on victory. Decide first whether an *abandon* (code 0)
  should fire them; the original distinguished Canceled from Defeat precisely so it
  could treat them differently.
- **Seed clamping to `0..0x7fffffff`.** `on_victory_chains` is `Vec<i64>` all the way
  down but `content_chains.chain_id` is `i32`. A seed row with a chain id outside
  `i32` loads fine and then silently matches nothing. The loader is the place to
  reject it, next to the new `difficulty` check.
- **The original's other two abort triggers.** `minigame.hpp:64-78` has
  `AbortConnectionClosed` (0), `AbortPlayerCanceled` (1) and `AbortIllegalAction`
  (2). CA04 wires the first. The second needs cell method 30. The third needs a
  failure channel on `MinigameInstance::message`, which returns `Vec<GameOutput>`
  with no way to say "kill this session" — so where the original killed a session on
  a malformed or unknown command (`minigame_connection.cpp:557-563`), Cimmeria logs a
  WARN and keeps going. That is a server-authority gap: a client can spam unknown
  commands indefinitely.
- **Tickets are not single-use** in either implementation — `authenticate` does not
  invalidate, and neither did C++ `find()`. Two connections bearing the same ticket
  can both log in. Pre-existing, unchanged by this packet, and it belongs with the
  SFS DoS hardening in #532 along with the half-open-TCP case: a socket that never
  EOFs pins a connected session forever, and the original had the same hole
  (`minigame_connection.cpp:534-541` is a bare `async_receive` with no read timeout).

## Review round (PR #652, testing-validation-engineer)

The code was approved; the finding was that the suite did not pin its own
claims. Five items, all applied. Each fix carries its own revert proof, run in
one lane hold.

| # | Gap | Fix | Revert proof |
|---|---|---|---|
| 1 | `mark_connected` had one production call site and nothing pinned it | e2e test polls the registry after login and asserts `connected`; teardown switched to `remove_if_ticket` so a stale task cannot delete a newer session | delete `mark_connected` → `a_closed_connection_leaves_the_entity_free_to_relaunch` FAILED |
| 2 | `difficulty` range only exercised behind `require_db_or_skip!` | seven no-DB unit tests in `loader/tests/action_conversion.rs`: 0, 1, 5, 6, absent, string, float, null | widen to `(0..=6)` → `start_minigame_difficulty_rejects_just_outside_the_range` FAILED |
| 3 | `aborted()` called but never observed | abort test half-closes the client write side and asserts the `failure` frame arrives exactly once | delete the `for output in game.aborted()` loop → `closing_the_swf_reports_canceled_and_runs_aborted` FAILED |
| 4 | `spawn_sweep` untested; swapping `ttl`/`interval` invisible | two `start_paused` tests, one evicting and one sparing a connected session | delete `registry.expire_pending(ttl).await` → `spawn_sweep_evicts_a_stale_session_on_its_own` FAILED |
| 5 | seven sends `return`ed past the teardown | labelled `'session` block; every send `break`s into the shared teardown | change the first send's `break 'session` to `return` → `a_send_failure_during_handshake_still_reports_canceled` FAILED |

Two traps worth recording, both of which produced a *passing* test that
asserted nothing:

- **A task spawned under `start_paused` must be polled before you advance the
  clock.** `spawn_sweep` builds its `Interval` inside the task, so the
  interval's epoch is set at first poll. Advancing first moves the epoch along
  with it and the sweep never fires. Both sweep tests now yield before
  advancing (`let_spawned_task_start`).
- **A captured wire stream in an assertion message makes the whole message
  binary.** The minigame frames are NUL-terminated; a failing assertion that
  embedded them printed as `Binary file (standard input) matches` under grep,
  hiding the failure in the first proof run. `half_close_and_read_to_eof` now
  swaps NUL for newline.

`socket2` was added to `crates/services` dev-dependencies. The handshake guard
needs `SO_LINGER=0` so the client's close is a reset: a FIN (what `shutdown`
or a plain drop produces) leaves the server's writes succeeding, and the test
stops reproducing the bug. tokio's own `TcpStream::set_linger` is deprecated,
so the option is set through `socket2::SockRef`, which borrows the same socket.

`Cargo.lock` gains the `socket2` entry plus two `thiserror 2.0.19` to `2.0.20`
lines. The latter are **pre-existing drift**, not from this change: they appear
from `cargo metadata` alone on a pristine checkout of this branch with no
working-tree edits. Verified before committing.
