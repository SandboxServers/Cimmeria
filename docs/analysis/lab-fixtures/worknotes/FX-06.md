## Differences from the packet text

- `applies_fixture` lives in `runner/fixture.rs`, not `runner/mod.rs`
  (`mod.rs` was already near 600 lines).
- In `chain` mode, `fixture_character` is set **after** `ensure_state`, not
  before. The value is the same under `auto`. Under `never`, the run's first
  row now gets the character it really plays, where the packet's order left
  the var unset.
- `ensure_state` now records `in_world_as` when it finds the client already
  in world as the wanted character. Before this change a run that started in
  world never set it, so `auto` could not continue a chain from the first
  row. Caveat: with no record of who is in world, `ensure_state` assumes the
  lab character. A client left in world as another character on the same
  account passes as the lab character, and `auto` may chain from it. The
  code says so at the fallback; the behaviour is unchanged.
- `end_session` drains a name even before the runner has entered the world
  itself. It uses `in_world_as`, or the lab character when the client was
  found in world. F24 says the next login must wait for the server to drop
  the account, and a run usually starts in world as the lab character.
- `establish_fixture` removes any caller-supplied `player_entity_id` before
  resolving the entity, because that id names a different session.
- The first-login hold record keeps label `first_login_hold` and requested
  text `wait 17000 ms`. Its `kind` is `fixture` like the rest of the
  plumbing, so lab-golden strips it.
- FX-04 refuses a stage with a JSON-RPC `invalid_params` error, which
  `McpHttpSession` surfaces as `lab-mcp error -32602: stage refused: ...`
  (`extract_jsonrpc_result`). The BLOCKED reason keeps the text from
  `stage refused: ` on: `fixture not established: stage: stage refused:
  character X is online`. The test endpoint returns the refusal in that
  same wrapped form.
- The `lab_client_stop` arm added to the fake client in `runner/tests.rs`
  makes the fake report itself stopped. No existing test called it.

## Known limitations

- **Lease revoked mid-row.** `run_row` races `drive_row` against the lease
  in a `tokio::select!`. A takeover drops `drive_row`, so that row's final
  `end_session` does not run and the client is left in its session. The
  next fixture row's `establish_fixture` ends any leftover session first,
  so the next row still starts clean. A non-fixture row after it runs from
  wherever the client is, which matches the behaviour before FX-06.
- **One undrained name is carried.** `Runner::pending_drain` holds a single
  name. When the carried name and the session's own name both fail to
  drain, the older one is kept and the warning names it.
- **Character select is not drained.** A session ended at character select
  (a refused stage, for example) has no name to poll for, so no drain runs.
- **Entity id is read once.** It is resolved with a single
  `server_sessions` read after `lab_play_character`. That relies on the flow
  returning only once the server lists the character in world.

## Review fixes

Applied after the adversarial review, 2026-10-11.

- `in_world_as` is set before each `lab_play_character` (the fixture Play
  and the bootstrap Play). A Play that errors after the client reached the
  world now drains the fixture character, not the lab-character fallback.
- `end_session` takes `in_world_as` before its first call. Any error (a
  failed status call, a drain timeout) logs a `lab.uat` warning
  (`event = session_end_failed`) with the row, the character and the
  reason, and keeps the undrained name in `Runner::pending_drain`. The next
  `end_session` stops the client, drains that name, then its own. Errors
  from ending a row's session become a `session end: <error>` flag on the
  row. Flags never change the result. The packet's
  `let _ = self.end_session(ctx)` is gone from both call sites.
- A fixture row sets `${character}` to the fixture character as well as
  `${fixture_character}`. `ctx.character` takes archetype, level and
  alignment from the last `lab_characters` list, matched on the full name
  or any one word of it (`Runner::listed_character_value`).
- The bootstrap's `lab_ensure_character_slot` protects the lab character
  and the fixture character of every profile in the section for this
  instance.
- `tier::is_read_only` no longer counts `server_stage_fixture` as a read.
- The `ActionRecord::kind` doc lists every value the runner writes.
- Tests: split into `fixture_tests.rs` (the fake endpoint, the helpers and
  fixture mode) and `fixture_session_tests.rs` (sessions). The fake
  endpoint now refuses a stage for a character its session list shows,
  lists a `stuck` name only once that character has had a session, and
  gives the lab character entity 41. The fake client gained `fail_after`
  (the call takes effect, then errors). There are 18 fixture tests, up
  from 9. Revert proofs, 2026-10-11:
  - Setting `in_world_as` after Play again failed
    `a_play_that_errors_in_world_drains_the_fixture_character`.
  - Not keeping `pending_drain` failed
    `a_failed_drain_is_flagged_and_drained_by_the_next_row` (the next row
    met a refused stage instead) and
    `the_session_drain_times_out_with_the_name` (30 polls, not 60).
  - Dropping the drain of a client found in world failed
    `a_fixture_row_runs_in_its_own_session_in_order` (no `server_sessions`
    between the first stop and the start) and
    `the_session_drain_times_out_with_the_name`.
