> Type: worknote. Audience: FX-06, FX-09 and FX-12 implementers and

## What landed

- `crates/lab-mcp/src/tools/fixture.rs`: the argument struct
  (`StageFixtureArgs`, `deny_unknown_fields`, the contract's JSON) and
  `stage_fixture(state, call)`. Order: parse, no database, resolve the
  character, GM gate, online gate, shape checks, seed checks, stage. The
  tool reads only; the one write is the in-memory store.
- `crates/lab-mcp/src/tools/mod.rs`: `server_stage_fixture`, next to
  `server_db_query`, one `audit::emit` per call on both paths. The server
  instructions string names the tool.
- `cimmeria-lab-mcp` gained a `cimmeria-test-support` dev-dependency (the
  live-DB gate), a `#[cfg(test)] mod test_support` shim in `lib.rs`, and a
  line in `tools/test-live-db.{sh,ps1}` (`live_db_wrapper_lists_every_test_support_crate`
  requires it). No runtime dependency was added: the store, `GM_ACCESS_LEVEL`
  and `OnlinePlayer` come through `cimmeria_services::base`.

## Behaviour the runner (FX-06) can rely on

- Success: `{ "staged": true, "player_id", "player_name", "replaced" }`,
  `player_name` the full `sgw_player.player_name`.
- Every refusal is a JSON-RPC `invalid_params` error (code -32602) whose
  message starts `stage refused: `. Through `ServerTools::call` it arrives
  as a failed `ToolOutcome` with `error = "lab-mcp error -32602: stage
  refused: ..."`, not as an `isError` result: the other `server_*` tools
  return `isError` results, this one follows the contract.
- A malformed call (unknown field, bad state string, missing `character`)
  is a `stage refused: arguments: ...` refusal too, and is audited: the
  tool takes the raw JSON (`StageFixtureCall`, whose schema is
  `StageFixtureArgs`'s) and parses it itself, because rmcp would otherwise
  reject it before the tool body with its own message and no audit row.
- Character match: `lower(player_name) = lower($1)` or the last
  space-separated word of `player_name` equal case-insensitively;
  exactly one row, else `matches no character` / `matches N characters`.
- Online: a session whose `player_id` is the character's, or (before
  `playCharacter` set one) whose name equals the character's full name.
  A nameless character-select session of the same account does not block
  staging, so the runner may stage while logged in at character select.

## Deviations from the spec

- **World lookup.** The spec said "the same lookup `.gotolocation`
  uses". `.gotolocation` resolves through the cell's in-memory world
  catalog, which this endpoint can only reach by a cell round trip. The
  tool uses the base precheck's lookup instead (`resources.worlds`, the
  foreign key `sgw_player.world_location` needs), which is what the apply
  would refuse on.
- **Items are accepted although FX-02's apply still refuses every item
  list** (`ITEMS_NOT_YET`). FX-03 removes that refusal; refusing here
  would need a follow-up edit when it lands. Until FX-03 merges, a staged
  item fixture is accepted and then logged "lab fixture not applied"
  (`reason = "precheck_refused"`) at Play.
- **Duplicate item design ids are refused**, a check the spec does not
  list: FX-03 deletes every carried instance of a design and then grants,
  so a second entry for the same design would undo the first.
- **Online refusal wording** uses the name as requested
  (`character Fxpraxisdefa is online`), matching the contract example.

## Tests

(`0x401` an item id never inserted; `0x410..=0x471` accounts and players).

- Unit: `an_online_character_is_refused` (by player id and by name),
  `the_runner_arguments_parse_into_the_staged_shape` (the runner's f64
  position, snake_case states, containers), `a_malformed_call_is_a_refusal`,
  `shape_refusals_name_the_field`.
- Live-DB: `live_db_stage_fixture_refuses_a_player_account`,
  `..._refuses_a_step_from_another_mission`,
  `..._stages_for_an_offline_gm_character` (reply shape, `fixture_pending`,
  `replaced` on a second stage by full name, and the fixture taken with the
  owner's account id), `..._refuses_an_online_character`,
  `..._refuses_what_the_seed_lacks` (world, mission, item design),
  `..._refuses_an_ambiguous_name`.
- Revert proof (one run, four gates removed at once: the GM check, the
  online check, the step-owner arm, and `account_id` set from the player
  id): the player-account, other-mission, online and stages tests failed;
  restored, all six pass.
