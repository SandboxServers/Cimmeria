# Client limits: network

The Mercury bounds between the server and the SGW client: datagram and fragment sizes, the reliable windows, resend timing, what the client sends while idle, and the #1341 next-request residue. Grades, column rules and the summary are in the [limits index](README.md); the evidence for the static rows is [client-mercury-receive-path.md](../../reverse-engineering/findings/client-mercury-receive-path.md).

| Largest message body the bundle loop can copy | no fixed cap: a temporary of exactly the body length (`scalable_malloc`), length from a field of up to 4 bytes | static | `0x01579a50` (`Bundle::iterator::data()`), `0x01579cd0` (frees it), `0x0158b2d0` (`expandLength`) | n/a | n/a | One temporary live at a time. | Client resend retry cap | none; resent every RTO until acked or the channel dies | static | `0x0158c420`, `0x0158be30` (statistic at `+0x7c` only) | n/a | n/a | Only a failed send aborts the scan ("Aborting due to failed resend", `0x01b19dd8`). | Client resends per pass per channel | 6 | static | `0x0158c420`, float `5.0` at `0x01e91e00` (count increments after a successful resend at `0x0158c541`, compared at `0x0158c558`) | n/a | n/a | Throttle, not a lifetime cap. A pass runs about every 10 to 16 ms (idle wait). |
| Client idle keepalive | empty bundle after 1.5 s without a send, checked every 1 s, after logOn only | static | `0x0158c7b0` (`+0x168` = max(sps x 0.05, sps x 1.5), `0x0158c99b` to `0x0158c9b7`), `0x0158bed0`, `0x0158bbc0` | n/a | n/a | Fires 1.5 to 2.5 s after the last send. | Client socket receive and send buffer | not set by the client; the OS default applies (numeric size not measured) | static | `0x01583440` (`addListeningSocket`), `0x01577b80` (bind, `getsockname`, `FIONBIO`, no `setsockopt`); all 19 `setsockopt` thunk call sites (`0x012f3d68`) listed | n/a | n/a | The only Mercury `setsockopt` is `SO_BROADCAST` on the discovery socket (`0x015898c0`). | Datagrams the network thread reads per pass | 64 per socket | static | `0x00de00e0` (constructor passes `0x40`), `0x015841d0` (`Nub+0xe0`), `0x01581ab0` (read loop) | n/a | n/a | Stops early on `WSAEWOULDBLOCK`; a full 64 loops again at once. |
| Network thread idle wait | 10 ms requested; about 10 ms at 1 ms timer resolution, up to about 15.6 ms at the default | static | `0x00de00e0` (argument `10` to `Nub+0xbc`), `0x01583bf0`, `0x00a78b90` (`CreateEventW`), `0x00a78bc0` (`WaitForSingleObject(evt, 10)` on an unsignalled event) | n/a | n/a | The thread waits after any pass that emptied the socket before 64 reads, not only a pass with no work. `timeBeginPeriod` is not checked. |
| Messages the game thread processes per frame | the whole queue as of the start of the drain; no count or time budget | static | `0x00c6edf0` (per-frame update), `0x00dd8780`, `0x0157e850` (`internal_size` snapshot, pops that many) | n/a | n/a | Bundles pushed during the drain wait for the next frame. | Client tolerance of server silence | 15 s | config | `crates/mercury/src/lib.rs` `UE3_INACTIVITY_TIMEOUT_MS`, the client's `NetInactivityTimeout=15` | n/a | n/a | Mechanism (static): logOn reads `ServerConnection+0x318` (`0x00dd9239`), queues a `ClientInactivityDetectMessage` (`0x0158d980`), and `0x0158bc50(period, 1.0f)` sets `Channel+0x160` = sps x period and arms a 1 s timer. `+0x318` defaults to 60.0 (`0x019cebe0`), is overwritten from `[Engine.Engine] NetInactivityTimeout` by `0x00c6f7c2`, and falls back to 30 if the key is absent. The client then disconnects with code -7 (`REASON_INACTIVITY`, table `0x00de15e0`; SGW's -11 is `REASON_DUPLICATED_PACKET`). Starts only at logOn. The client's timer, not the server's: the server reaps a silent client after 60 s (`INACTIVITY_TIMEOUT`, `crates/base-session/src/base/tick_sync.rs`). |
